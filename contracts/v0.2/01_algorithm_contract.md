# Algorithm contract v0.2：四阶段独立评估

状态：保留的 v0.2 资料提取草案及旧输出对照；临床有效性仍需病例审阅。当前时间线优先试验采用 [v0.3](../v0.3/01_algorithm_contract.md)。v0.1 原文保留，不修改其历史规则；四阶段提取不调用 v0.1 序贯控制器。

## 1. 研究对象

研究胰腺根治性切除等不可逆干预前，LLM 根据阶段可见原始资料提出建议的能力。根治切除中止是病例检索和临床痛点的入口，不自动等于不适当或可避免的决策。

对患者 i、阶段 k：

`raw_sources_i -> deterministic_extract + source_review -> context_ik`

`fixed_system_prompt + context_ik + question_k -> response_ik`

每阶段为独立会话，不传递前次回答。没有工具调用、环境模拟、memory、RSI、合成检查或实际患者 API 调用。本次实现到本地资料包和 messages 预览为止。

## 2. 四阶段不是四个必须不同的日期

1. 发现病变：本 episode 的首轮可观察相关腹部影像及当轮已有资料。
2. 诊断/分期：首次相关增强 CT/MR 轮次及累计资料。
3. 可切除性评估：本 episode 最早定位到的具体胰腺切除计划文书完成前的累计资料。
4. 治疗选择：与 3 相同的证据，只更换问题。

首份影像本身已是增强检查时，1/2 可以重叠。3/4 必须共享 context hash。未找到第 2 阶段锚点时保留空槽及原因，不拿术后检查填补。不声称源记录首次出现就是患者一生的首次 visit。

具体术式可能是附条件的计划，不代表已经承诺立即根治切除。锚定的是文书完成前，不声称恢复医生首次形成意向的时间。

## 3. Episode 和时间

- 只从原始文书中的明确胰腺切除/根治计划定位候选 episode，不用最终 M 状态、结局标签或预筛信号选择分块。
- 初版默认选择最早可定位计划所属住院；有多个候选住院、未定位时间的计划或时间异常时明确标记。支持来源固定的计划文书 override。
- 同 episode 文书以住院时间和 visit_id 共同约束。检查无可靠住院关联时仅使用住院前 30 天至计划前的窗口；这是可配置的取样规则，不证明所有记录属于同一次诊疗。记录潜在的前次住院重叠。
- `create_time` 是建档相关字段，绝不作为文书完成时间后备。
- 文书完成时间仅来自正文首行时间或明确的“记录时间”。历史叙述中的日期不是文书完成时间。
- 检验按 `report_time`；不能退回 `sample_time` 开放结果。
- 影像按检查时间的候选代理，以“这一轮报告已返回”作为待审约定；不伪造报告发布时间。
- 前两轮默认同日汇集，边界为次日 00:00，且不得超过计划文书完成时间下界。它是研究轮次边界，不是检查发生当刻。
- 分钟级完成时间表示区间 `[该分钟,下一分钟)`；计划取其下界为排他边界，同分钟不能排序。日期级结果按整天区间处理。

## 4. 输入和隔离

输入仅为完整影像原文、全部符合边界的检验条目、可追溯文书原文片段和已返回的可识别诊断性病理。不给研究者标注的病灶特征、风险分组、决策 gap、最终结局或真实拟术式。

允许的文书模板、截取标记和拒绝条件见提取规范。截取不是摘要；记录 Unicode 起止位置、全文 hash、片段 hash 和剔除原因。术后/出院/手术记录不进入当前术前资料包。混合文书有未来叙述或决策残留时待审，不以替换关键词的方式“洗净”。

后续文书不能自动回填早期病史。程序输出候选病史位置；仅在本地 review 配置明确接受、hash 匹配、解释其历史性质并通过日期检查后加入早期 context。此举仍是回顾性重建，不成为精确 EHR 快照。

未知不等于阴性，疑似不等于确诊。病例中未提供的结果、参考范围或面板号均不得补造。按日期/时刻汇集检验不代表同一医嘱。

## 5. 数据质量和运行约束

- 每病例始终输出四个槽；缺锚点的槽标记 `UNRESOLVED`，不生成可用 messages。
- 正常输出为 `DRAFT_REVIEW_REQUIRED`，绝不将“脚本运行成功”标为临床资料已核准。
- 影像时间代理、截取文书、重建病史、阶段重叠、episode 歧义、缺失结果和正文未来日期均在审阅报告中列出。
- 逐条保存 included/excluded/duplicate/review 的处置及来源。相同源键及载荷合并；影像在检查时间、类型和全文完全一致时可做呈现合并并保留全部源映射，这不证明源系统中是同一临床事件。冲突内容不按“更正常”或“更严重”选择。
- 模块不导入或创建远程模型客户端，不读取 API key。CLI 仅向项目 `private/` 或 `outputs/` 写患者衍生文件，目录 0700、文件 0600。
- 同一输入、规则和 review 配置产生确定的 context / messages hash。保存输入文件、患者 bundle、规则代码和提示词 hash。

## 6. 验证与未来评价

软件验证：来源片段逐字匹配；检验不越过报告边界；未来/未知时间不隐式开放；计划和结局隔离；3/4 证据完全一致；重复和缺失正确记录。

资料质量验证：人工对原始来源检查锚点、资料纳入/遗漏及隔离。批量结构通过率不是临床准确率，也不是时间快照真实性证明。

未来临床评价：结局盲法的下一步策略适当性、缺乏充分依据的根治切除承诺、过度延迟/加检/放弃治疗机会及来源支持情况。揭示终局后的可提前识别性单独评价。多个合理行动均可接受；四问不能按四个独立患者统计。
