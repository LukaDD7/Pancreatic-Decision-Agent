# Algorithm contract v0.3：时间线优先的四阶段独立评估

状态：单病例试验实现、来源审阅草稿。替代 v0.2 的当前资料分包规则；v0.1/v0.2 与既有输出保留，未重跑全队列。实现入口为 `pancreatic_agent.timeline_extract`，不调用模型。

## 1. 研究及执行范围

研究不可逆胰腺切除前，在不同证据条件下的下一步建议。根治切除中止不是自动判定临床决策错误的标签。四问独立调用，同一 system prompt，不传入上一问回答；本次仅生成本地 context/messages，不运行 API、memory、RSI 或自主检查环境。

`原始来源 → 全部来源时间线 → 来源绑定的事件锚点 → 累积可见原文 → 四问输入`

输入只读取 `documents_all/imaging_all/laboratory_all/pathology_all`。结局、预筛临床特征及患者状态标签不选择锚点。文件/来源 hash 用于追溯，不作为患者特征。

## 2. 时间线先于窗口和住院

先建立全部来源时间线，保留正文、来源键与时间精度，再定位目标计划和疾病发现过程。没有 30 天回看截断，也不以相同住院号作为所有资料的纳入条件；此前跨住院的病史、诊断性取材和治疗事实可以构成当前背景。

时间线属于审阅资料：含计划、术后及晚病理，绝不能整体作为模型输入。未知时间条目单列，不用建档时间补位。临床事件时间与资料可见时间分列；检验可以按采样事件排列，但开放结果仍按报告时间。

`create_time` 不参与临床排序、锚点选择、文书完成时间或可见性后备。它可能存在于输入 bundle 的 hash 中，不参与决策规则。

| 来源 | 临床/记录时间 | 模型开放依据 |
|---|---|---|
| 文书 | 正文首时间或明确的记录时间；冲突/缺失待审 | 正文完成时间及可用原文段落；混合版本仍需审阅 |
| 影像 | 检查时间 | 优先显式报告时间；无报告时间时，仅在 review 接受后使用检查时间代理 |
| 检验 | 采样时间，可缺失 | `report_time`，不以采样时间替代 |
| 病理 | 报告字段之外的临床日期须按原字段语义另核对 | 报告时间；午夜占位的报告日期按整天不确定区间处理 |
| 回述既往事件 | 原文中被引用的事件日期 | 来源绑定并接受的回顾性重建约定；不能伪装成当时独立记录 |

影像显式报告时间字段存在但格式无效时，不退回较早检查时间。检查时间代理及“该报告已返回”的假设必须显式留痕。没有实际发布时刻，不声称得到真实 EHR 钟点快照。

## 3. 锚点及不等式

1. **发现病变**：优先使用经来源核对的最早相关报告或明确外院报告引用。没有审阅时，最早可取得相关腹部 CT/MR 仅为候选，不认证为疾病首次发现。已选锚点本身纳入。
2. **诊断/分期**：选择已返回的分期检查报告集，以所选轮次最后报告事件定位输入。可以只有一份增强报告，也可以经说明预先选定一轮 CT/MR。外院做过增强但只有简短引述时，不声称本院增强是患者首次增强检查。
3. **可切除性评估**：目标具体胰腺切除计划文书完成时间下界之前。
4. **治疗选择**：与第三问相同证据、更换问题；两者 context hash 必须相同。

**报告返回后的检查锚点：`available_time <= checkpoint`。具体拟术式形成前：`available_time < plan_boundary`，且目标文书整篇隔离。** 这不是把所有边界统一改为 `<=`。

精度规则：秒级时间可以等于检查 checkpoint；分钟级/日期级来源在不能确定先后时按其可能区间判断。日期级锚点自身可作为已返回事件纳入，但其他同日、顺序不明的资料不自动开放。没有“默认取次日零点汇集当天所有结果”。

第三/四问仍不能加入与目标计划同分钟而顺序未知的结果。四问允许共享证据，不能按四个独立患者计数。

目标计划从正文中明确的胰腺切除/根治拟术式选择。保留附条件计划的属性，不自动解释为立即根治承诺。多次拟手术或治疗后再评估必须确认目标 episode；不按最终结局选择。支持来源绑定的计划 override。

## 4. 原文与回述资料

完整提供现有影像原文、全部符合边界的检验原值、可追溯文书段落及已返回的诊断性病理。不额外抽取病灶大小、血管受侵、转移、风险或决策 gap 注入模型；不补造报告正文、面板号或未知结果。

文书结合标题和正文识别入院记录，空白临床模板不作为事实。按明确的本次计划章节和混排诊断 footer 截取；既往史、现病史和诊断依据中的历史治疗叙述不因“手术指征”等词被整段删除。普通计划句仅在显式历史段落之外触发截断；无结构或有较晚事件的混合文书仍需原文片段审阅。

后来的入院文书不整篇提前。review 接受的既往片段必须绑定 bundle hash、源文书 hash、字符范围、原文事件日期、适用阶段、审阅者与理由。事件日期须出现在原文片段；不能借较早事件日期带入后续检查或现在的查体。原文已经可见且包含同段时不重复回建。

同份文书在现病史和辅助检查中分别引用同一外院检查时，可审阅多个不连续原文片段，并以 `discovery_companion_source_ids` 共同锚定该事件；要求同源文书、相同事件时间与精度、明确说明。日期相同的其他检查不因此开放，不能为拼接片段纳入两者之间的后来查体。

目前对既往手术/术后记录不整篇自动开放；既往取材、治疗和病理事实可由当前已可见原文或专门 review 片段保留。新规则不是“所有名为术后的记录均是未来”，也未实现任意历史手术文书的自动分段。

## 5. 审计和交付

- 全部输出为 `DRAFT_REVIEW_REQUIRED` 或 `UNRESOLVED`；无锚点/锚点证据未开放，不生成有效 messages。
- `timeline.json/.md` 保存完整来源索引、原文、时间依据；未知时间保留。其含后续信息，仅供审阅。
- `packets.json`、四份 context/messages 保存四问临床输入；`after_*_context.md` 提供逐份本院影像返回后的备选输入。
- `audit.json` 保存锚点、纳入/排除理由、原文坐标、重复/冲突来源、时间代理、回建及代码/提示词 hash。
- semantic diff 同时报告规则含义变化和实际病例边界、资料集合、正文载荷变化；纯来源别名/显示变化与真实新增临床信息分开统计。
- 病例、配置、时间线及病例 diff 仅保存本地 `private/` 或 `outputs/`；0700 目录、0600 文件，不纳入 Git。公开 contract/diff 仅写一般规则。

## 6. 验证及限制

验证当前报告纳入、等时刻报告纳入、晚一秒排除、计划边界排他、时间精度、create_time 无效、跨住院/长病程保留、原文片段、历史治疗与当前计划分离、空模板、重复/冲突、3/4 一致以及结局标签不影响输入。

软件通过与逐字来源匹配不证明临床完整性、报告真实可见性或医生首次形成决策的时刻。首次可用影像不一定是首次病变；没有独立外院报告时只能提供回述，不补造完整报告。初步试验可以使用明确的回建/代理约定，但正式效果评估需独立临床审阅并按假设类型分层。
