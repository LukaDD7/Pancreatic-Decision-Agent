# HEWV v0.4：本院诊疗 Episode 与完整记录可见性契约

**英文名：Hospital Episode and Whole-Record Visibility Contract。稳定标识：`hewv-v0.4`。**
HEWV 是本项目定义的研究数据契约名称，不是已有临床指南、行业标准或经验证的临床系统。适用当前四问独立的回顾性初步评估。替代 v0.3 的默认输入组织规则，旧版保留作历史对照。

入口：`python -m pancreatic_agent.episode_extract`。配套：[episode 定义](02_episode_definition.md)、[不变量](03_invariants.md)、[配置与运行](../../docs/hewv-extraction.md)、[v0.3 → v0.4 semantic diff](../../docs/semantic-diff-v0.3-v0.4.md)。

## 1. 研究对象与执行边界

研究本院面对胰腺病变时，在不可逆干预前、不同现有证据条件下的建议。根治切除中止/未实施可用于识别研究痛点和结局分析，不自动等于先前临床决策错误。

`本院 episode → 完整来源记录与时间索引 → 来源绑定的 checkpoint → 累积整份可见记录 → 独立提问`

提取入口仅生成本地资料包、messages 和审计文件，远程调用数为零。不运行自主检查申请、memory、RSI，也不把前一问回答带入下一问。配套[独立决策接口 v0.1](05_decision_interface.md)规定 PAUSE/EXIT/CONTINUE、动作表和JSON输出；可选测试入口是 `python -m pancreatic_agent.evaluation`，与提取入口分开。

## 2. Episode 与四阶段

Episode 是**同一患者、同一本院诊疗范围、同一临床问题/治疗情境下，面向某项明确决策的诊疗过程**。患者可以有多个 episode；首次诊治、治疗后再评估与复发评估需分别确认。住院号是关联信息，不自动等于 episode。

起点优先为本院首次接触并记录本次病变/疑似病变的就诊。若缺完整首诊来源，使用 `FIRST_OBSERVED_HOSPITAL_RECORD`，明确为最早可观测本院记录，不能升级为真正首次 visit。外院检查的既往日期不定义本院 episode 起点。

“发现/疑似病变 → 诊断/分期 → 可切除性评估 → 治疗选择”是**提问与组织框架**，不认定为每位患者必经、互斥、已完成的四个临床状态，也不是契约的不变量。首次本院接触即可已有增强影像甚至病理；肿瘤标志物返回不自动意味着可切除性评估完成。

| 问题 | 可选择的来源绑定节点 | 解释边界 |
|---|---|---|
| 发现/疑似病变 | 本院首诊记录或最早可定位的本院相关观察 | 必须区分真正首诊与数据覆盖起点；本院记录可以引用外院材料 |
| 诊断/分期 | 一份报告或预先指定的一轮报告已返回 | 不预设影像自动完成分期，不按最终结局倒选报告 |
| 可切除性评估 | 对该问题有意义的一次证据更新 | 不要求某种固定检查，不把更新事件转换成研究者给定的可切除性结论 |
| 治疗选择 | 被评价的建议/计划文书之前 | 明确独立决策或既有计划复核；整篇隔离目标文书 |

四问可共享 checkpoint，也可不同。缺少可靠节点则该问 `UNRESOLVED`，不复制另一问边界凑齐、不制造时钟。独立问题不等于独立患者或四条独立轨迹。

## 3. 数据来源与完整记录单位

输入只消费 `documents_all`、`imaging_all`、`laboratory_all`、`pathology_all`。`state_pre_T0`、结局、预筛病种/可切除性、实际手术行为、上游参考答案不进入临床输入或选择锚点。

“完整记录”指**当前来源层提供的一个完整文书版本、一份完整现有报告或一条原生检验结果记录**。这是来源层约束，不声称 JSONL 或名为 raw 的文件等于医院最原始数据库。医院源文件→中间索引的规则、关联与上游截断仍须溯源。

- 文书逐字保留完整正文。禁止前缀截取、摘句、删除计划/诊断 footer，以及把后来文书中的历史片段提前开放。
- 影像保留现有报告全文；如只有描述与诊断字段，完整呈现二者并保留组成字段的来源。禁止抽取大小、血管关系、转移等新状态字段注入。
- 检验保留全部符合时间边界的项目行，展示原值、单位、采样/报告时间与原异常标记。源包另有数值/定性/文本结果时连同原字段名保留，不静默丢失，也不冒充原值。禁止按重要项目筛选、每项仅留最新或总条数上限。规范单位副本与主键等溯源字段留在审计层。
- 病理保留现有标本、临床诊断、病理诊断和镜下所见，不按诊断性/手术标本类别筛掉已可见的既往报告。
- 不因“术前”“术后”、护理或非标准模板标题而自动排除。既往已完成的治疗和计划属于真实背景。
- 每条来源保留。v0.4 不做展示去重；未来若引入去重，须另改规则并保存所有源实例。
- 原字段含义未知时保留原值并记录疑问。影像“阳性/阴性”不解释成正常/异常。字段名称不作为医学含义的证明。

脱敏属于独立的、可追溯的数据治理步骤，应保留本地受限原件与处理版本；不能以防泄漏之名改写医学内容。模型上下文不带业务患者号、源文件路径、行号、分析标签或完整患者整合包。来源编号仅供引用。

## 4. 时间与本院接收

各条记录分别保存事件时间、正文完成/报告时间、可见依据、精度及来源。`create_time` 仅可在本地审计 raw 中保留，不参与排序、锚点或可见性后备。

| 类型 | v0.4 当前开放依据 | 缺失/冲突 |
|---|---|---|
| 本院文书 | 正文开头时间或明确“记录时间”；候选一致 | 缺失或冲突，整篇待审，不取建档/入院时间替代 |
| 影像 | 显式报告/签发时间优先 | 缺失时仅经声明接受检查时间代理；无效报告字段不得退回检查时间 |
| 检验 | `report_time` | 不以采样时间替代；`available_time` 保留作溯源，当前适配器不自动采用尚未核实语义的字段 |
| 病理 | 报告时间/报告日期 | 日期字段的午夜占位降为日级，不认为午夜已见结论 |
| 独立外院报告 | 报告形成及本院接收均已有来源 | 外院检查日期不能代替本院接收时间；当前支持原字段 `hospital_received_time`，不能凭 review 造接收时间 |
| 本院文书引用外院材料 | 本院整篇文书已可见时 | 不把引用的外院日期当该文书的可见日期 |

检查代理表示“该报告在选定节点已返回”的实验约定，不认证实际签发钟点。外院接收与检查代理同时使用时，两种假设均留痕。原生签发/版本日志未来可通过明确的来源适配器扩展，不在本版本中悄悄启用新字段。

报告/记录返回后用 `<= checkpoint`；目标决策文书之前用 `< checkpoint`，目标文书整篇排除。采用时间精度区间：仅日期或仅分钟的其他记录，不能确定先后则不自动开放。被明确指定为已返回的粗精度锚点可纳入，不因此开放同日其他资料。没有“默认日末收齐当天结果”。

## 5. 文书版本问题

正文首时间不证明整篇为同一时刻的版本。正文出现晚于该时间的其他日期/时刻，属于**版本核对候选**，可能是未来计划、笔误、签名或事后补录，不能一概宣称信息泄漏。

处理单位始终是整份记录：

1. 原文完整保留于审阅时间线。
2. 未核清则整篇 `unresolved_whole`，不送入有效输入；不保留“安全前半段”。
3. 如能从独立版本日志取得当时真实全文，作为单独源版本进入适配器，保留来源与完成时间；不由本程序删除后文生成早期版本。
4. 若核对后确认较晚日期仅为当时已有的未来计划/笔误，可通过全文 hash 绑定的 `document_version_reviews` 接受整篇并记录依据。review 不能修复缺失完成时间，也不能把已知未来结果审批成过去事实。

## 6. 独立决策与计划复核

`independent_decision`：测试未见被评价医生建议时的选择。边界为该项决策最早可定位的建议/计划记录之前；“限期手术治疗”等一般建议也需计入，不能只定位后来的具体根治术式。此前已出现建议则需要重新定位边界/目标，不能删除建议句后继续称独立决策。

`plan_review`：允许看到先前已形成的建议，完整保留，评价是否支持、补充条件或改变路径。仍可隔离正在被评价的新文书，但必须明确这是复核任务。

当前正则仅筛查更早的手术建议候选，保护显式历史章节，不认证医生首次产生意图。若独立决策边界之前出现候选，该问标 `UNRESOLVED`；由来源审阅澄清目标或切换任务，不自动删句。未识别隐含计划、未知时间文书及历史章节错误仍可能存在，须独立核查。

## 7. 执行、审计与质量解释

1. 确认患者关联与来源范围，绑定输入 bundle hash 和 reviewer；该模块不重做上游跨表患者关联。
2. 构造所有来源，完整保留原文/原字段及 hash；不去重、不做临床重要性过滤。
3. 明确 episode 起点依据、四个 checkpoint、任务模式及所需时间代理。当前需要显式 review，不自动认证关键词命中为首诊或阶段完成。
4. 逐条判定整份可见性，保存 `included_whole / excluded_whole / unresolved_whole` 与理由。已知在截点后和时间/版本不明必须区分。
5. 生成四份累计 context/messages，使用同一版本化 system prompt，不带前问回答。当前采用独立决策接口的三个mode、一项首选动作与JSON格式；复核模式明确调整问题措辞。锚点不可靠时不生成有效 messages。
6. 输出完整来源时间线、审计、review manifest、提示词与问题 hash、代码 hash；可生成病例级 semantic diff。

输出 `DRAFT_REVIEW_REQUIRED` 或 `UNRESOLVED`，没有自动临床认证状态。部分非锚点记录未定时仍可形成有限资料草稿，但必须显示 `SOURCE_VISIBILITY_UNRESOLVED`；不能称完整真实 EHR 快照。

质控至少记录：真正首诊/覆盖起点比例、有效 checkpoint 数、报告代理、未知可见时间、混合版本、完整记录载荷是否逐字一致、不同任务模式，以及上游来源缺口。软件测试通过不证明临床完整性或专家金标准。

## 8. 本地保存与迁移

真实病例、review、时间线、diff、可读表和输出仅保存 `data/`、`private/`、`outputs/` 忽略目录。公开文件只含通用规则与完全虚构示例。无患者 API 调用。

v0.3 的 `evidence_spans`、外院回建锚点和 `plan_source_id` 配置不能直接改版本号复用。必须重新确认本院 entry 与 checkpoint，并从原始来源重新生成；旧原文节选不作为新来源全文。新旧资料变化见 semantic diff，不覆盖旧输出。
