# 排序阶段：定前后、定过程、必要时降级

## 1 这一阶段做什么，不做什么

做：

- 确定每个事件**真正的**时间边界（不是记录时间）
- 确定两个事件之间的先后关系
- 确定哪些事件属于同一个管理过程
- 发现某个候选 checkpoint **不成立**时，把它降级

不做：

- 重新判断"这是不是一个决策"——那是发现阶段的事，已经做完
- 重新分类 `record_function`——除非发现了一个明显的矛盾

如果发现阶段把一个执行痕迹标成了决策，你可以降级它，但要在理由里说清是**哪条原文**推翻了它。

## 2 时间证据怎么用

发现阶段提交的是原文候选 span，不提交 `choice_time`、`time_basis` 或检查证据引文。
候选的 `clock` 来自实际来源资料，只用于检索与程序时钟比较；`clock_basis` 说明它的来源。
它们不自动等于临床团队作出管理判断的时刻，也不能把记录时间改写成选择时间。

- 来源可见时间、文书形成时间、检查执行时间须按各自 `clock_basis` 解释，不互相替换。
- 原文若明确记载某个既往判断发生的时间，可在关系解释中逐字引用，但不得伪造精确选择时刻。
- 检查执行时间可以支持检查已经发生的时点，不自动证明何时决定安排该检查。
- 资料检索时间未知，就保留未知；不得把缺失推断为更早或更晚。

**关键提醒**：本语料里几乎不存在"决定时间：某日某时"这种写法。不要为了建立关系而
把来源检索时钟称为临床选择时刻。

## 3 先后关系怎么定

两个事件 A、B：

- 双方都有可比的精确时间 → 按时间
- 同一分钟或同一秒 → **不可定序**，标记 `same_time_unresolved`，不要凭 event_id 或文字顺序猜
- 一方时间未知 → 标记 `unknown`，不要因为"记录较晚"就断言它较晚发生
- 判断为之后（AFTER）→ 不能当作前轮使用

## 4 同一管理过程

同一过程 ≠ 同一日期 ≠ 同一标题。

判"是同一过程"要看：**是否服务于同一个患者管理目标**。

例：术前决定手术 → 术中根据探查确定具体术式。这是同一手术管理过程里的两个判断，子问题不同不切断它。

反例：同一份术后记录里的"拔管"和"输血"，都发生在术后，但服务不同目标，不是同一过程。

## 5 什么时候降级

降一个 checkpoint，必须能指出**具体的、可引用的**理由，例如：

- 原文显示这只是回述先前安排，不是新决定
- 该"决定"其实是一般性/模板表述
- 研究范围外（不是 PDAC 可切除性/根治路径相关）
- 时间证据完全不成立

不能因为：置信度低、字段不全、和别的记录看起来不一致——这些是 `uncertain`，不是降级。

**不一致不等于错误**（AGENTS.md §4）：同一对象不同时间的不同测量、不同模态的不同描述，都可能是各自有依据的。记录差异，标待核，不要挑一个当真相。

## 6 输出的样子

对每一对相关事件给出：

- `relation`：`same_management_process` / `evidence_comparison_previous` / `same_event` / `none`
- `basis_quotes`：支持这个关系的**原文**。两个端点各有一条引文**不等于**关系有证据——你还需要能支持"连接"的文字，或者明确说明只有上下文关联
- `confidence`：`supported` / `context_only` / `uncertain` / `no_link`

`context_only` 是合法的输出，不是失败。强行把每个关系都写成 `supported`，比留一个诚实的 `context_only` 更糟。

## 7 常见陷阱

- **"同日出现所以有因果"**：新检查和新评估同日出现，不自动支持"该检查导致该评估"
- **"前轮没写理由所以是新证据"**：如果前轮文书已经引述了同样的测量，那不是新信息
- **"记录时间早所以已知"**：记录时间早只说明记录早，不说明医生读过
- **"标题一样所以同一过程"**：标题是模板残留，不是管理目标
- **"数值一样所以重复"**：不同次检查的相同数值可以是新测量，也可以是真的重复——要看对象和检查日期
