# 病例级组织

## 对象与责任

发现阶段 LLM 已提交带精确原文边界的管理候选；程序已为同次检查候选报告组建立证据索引。
本阶段 LLM 组织这些对象，不代替原文，不把候选称作已确认临床决策或独立 episode。

`source_id` 是原文定位锚点；`event_id` 是程序候选对象ID。管理过程关系、身份关系、组成关系
和证据使用关系必须分开。程序核验端点和引文，不替你证明同一管理目标。

## 证据使用方向

`evidence_used` 的唯一方向：既往 `evidence_artifact` → 后续管理候选。
先读取管理候选实际引用的报告，核对检查对象、报告日期/模态/版本和临床文书中的引用线索。
程序检索时钟可比时，证据晚于判断会被拒绝；同刻或未知可保留，但不伪造临床选择时刻。
证据使用不是同一管理过程，不合并过程容器。未找到交付报告时保留二手表述及来源状态，
不能说患者未做检查。

## 身份、组成和过程

- `same_event`：对象、措施、范围和当时管理含义相同的严格重复身份候选。
- `contains`：组合候选包含一个或多个具体候选；记录组合候选→组成候选，不自动合并过程。
- `overlap`：候选有部分共同内容，但不是严格重复或明确包含；保留边界差异。
- `same_management_process`：原文支持服务同一管理目标的候选过程连接。
- `none + no_link`：只否定指定候选对的直接过程边，不删除其他历史、证据或路径。

只有 `confidence=supported` 的 `same_management_process` 合并容器。`context_only`、
`uncertain` 不合并，前者也必须保留为明确关系记录。不能用同次查房、同日、同次住院、同标题、
仅治疗目标看似相近来替代证据。

## 审阅与修正

先记录可支持的关系，再 `preview_episodes` 检查传递合并的实际容器。
发现直接边错误时添加 `none/no_link`，给两端原文和理由，再次预览；不得删除历史记录。
组合/原子候选不能用 `same_event` 强行压平，也不能借 `contains` 自动把所有相关动作归入一个 episode。
孤立管理候选仍保留：它只表示没有已记录连接，不表示临床无关或不存在。

每个证据对象在 finish 时给 `evidence_checks`：`matched`、 `ambiguous`、
`not_found_in_delivery` 或 `not_applicable`，并写匹配依据。
完成声明覆盖所有 active 对象；覆盖清单不等于临床正确，最终 Checkpoint 的材料组织与遮蔽另属后续。
