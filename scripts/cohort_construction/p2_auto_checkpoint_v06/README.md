# Checkpoint / Episode v0.6

2026-10-28。新版本显式启用同源条件反馈和最终关系审计；不更改P1、不读取专家Reference、不覆盖既有结果。实现与验收记录见 `docs/P2-Checkpoint-v0.6-实施计划与验收-20261028.md`。

## 执行顺序

1. 程序把非空文书（包括旧版只作上下文的支持文书）或同次检查候选报告组组织为完整处理单位，记录每份来源的路由。文书类型仅作提示。
2. 发现阶段LLM输出患者管理记录提案；程序按原文逐字定位引文、核验时间。零发现或动作/临床决策子句引文报错时，最多一次同输入反馈；仍允许零发现。错误修订保留初始结果与报错。
3. 程序以最终采用的发现提案重建事件ID及每事件资料范围。发现阶段LLM改变临床决策子句后，不复用旧复核证据池。
4. 复核阶段LLM在同一处理单位内联合检查事件身份、研究相关性、既往临床管理判断比较对象、信息演化及关系。模型看到的当前单位完整原文仅供重建，不是医生盲评材料。
5. 对明确可修复的证明/引文错误，最多一次复核反馈；保持完整原文、证据池、事件ID和许可历史对象集合不变，重新按同一核验规则处理修订。缺失/重复对象或失败均不产生新阳性。
6. 全部单位完成复核后，程序检查最终分类、历史比较依赖、同事件关系和同管理过程关系。明确无效比较使候选状态转为 `UNCERTAIN_FINAL_GRAPH`；无效关系不参与Episode合并。`repeat`、`execution`、非候选或未定本身只作软信号，不一概排除其携带既往管理判断的可能。
7. 程序重新组装候选Episode，保存模型原提案、每次反馈、最终依赖审计及修订前状态。所有结果仍是研究重建候选。

`discovery_feedback_max_rounds`、`review_feedback_max_rounds`只允许0或1。格式反馈是独立的一次接口恢复策略，与语义修订分开；一次格式反馈内仍沿用原有最多3次相同请求体的传输尝试。并发失败现在绑定本请求回执，不使用共享最后回执。

## 新运行入口

以下命令会请求远程临床模型；本次工程验收没有执行它。必须指定新的output目录。

```bash
python3 -m scripts.cohort_construction.p2_auto_checkpoint_v06.run \
  --sources SOURCE_ROOT --manifest FIXED_COHORT_MANIFEST \
  --output NEW_OUTPUT --cache VERSIONED_CACHE \
  --config config/p2_auto_checkpoint_v06_deepseek.json
```

`config/p2_auto_checkpoint_v06_qwen.json`提供同代码的Qwen配置。旧v0.5配置及旧入口保留；旧配置不自动开启支持文书发现、条件反馈或最终图审计。新入口拒绝已存在输出目录，并记录配置、相关代码及来源hash。每例原始输入的精确字节另存到`exact_source_inputs/`，实际导入也读取该快照，防止临时输入路径删除后只剩文件名和hash。此快照仅供研究者；不能把多个修复与模型变化混为一个性能结论。

## 分割与医生材料

`p2_checkpoint_packet`已提供来源manifest、逐字定位工具、绑定Checkpoint的分割提案、确定性分区、独立语义审计契约和医生许可包投影。它当前是独立离线接口；没有从模型分类自动生成可信KEEP/MASK，没有把生产候选自动标为可盲评。

正式医生包需机械PASS、无REVIEW分区、绑定相同分割hash的独立语义审核PASS及外部冻结Questionnaire。医生包只携带许可正文和中性遮蔽占位符；研究者原文及审计单独保存。当前尚未完成FHIR资源约束/Bundle适配、HTML渲染与实际发放；不能把当前研究者FHIR Bundle直接交给医生。

## 验证界限

虚构反例证明程序能阻断已知工程失败；冻结Qwen输出的离线迁移比较只测确定性后处理影响。没有测量新版LLM的召回率、语义准确性或临床Reference一致性。支持文书增加和零发现复查是召回策略变化，须在固定模型、独立原文审查和预定义指标下另行检验。

历史无效引文曾把脱敏显示文本hash保存在`source_sha256`，有效引文则保存原文hash。新版统一`source_sha256`指原文，另以`lookup_display_source_sha256`记录显示文本查找hash，保留拒绝状态，不把显示文本核验冒充原文引文通过。冻结结果不改写；离线报告逐条解释历史字段归属。
