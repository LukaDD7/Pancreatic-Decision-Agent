# P1 v0.3.1：研究相关性与记录可用性

本版本重新从冻结 P0 全体检查资料。自动纳入条件是：身份索引已核对，且至少有一条可回溯的、具有实质研究相关内容的记录。其余进入待核；程序零命中不自动排除。P1 状态、ABC 覆盖及质量标记不构成 P2 的绝对入口门槛。

## 文件职责

- `rules.json`：机器可读规则、检索词和版本边界。没有必需的 ABC 维度或必需血管列表。
- `labels.py`：逐条保存解剖、测量和转移相关表述；处理否定、对象边界、历史/当前范围。标签是可审阅的检索索引，不是临床 GT。
- `references.py`：区分检查计划与已有引用；按检查号、日期、模态生成引用核对状态，不取最近检查冒充原报告。
- `run.py`：校验全部冻结影像输入及全量临床缓存；逐患者汇总、与 v0.2 比较、输出本地个体台账及公开聚合数。
- `verify.py`：核对证据坐标、冻结源覆盖、运行代码哈希和分流，生成开发样本原文卡及聚合验证回执。
- `tests/test_rules.py`：已知反例和分流、引用行为的合成回归测试。

在独立本地版本库根目录运行：

```bash
/opt/anaconda3/bin/python3.12 -m unittest discover -s scripts/cohort_construction/p1_source_quality/p1_quality_v0_3_1/tests -v
/opt/anaconda3/bin/python3.12 -m scripts.cohort_construction.p1_source_quality.p1_quality_v0_3_1.run --repo "$PWD"
/opt/anaconda3/bin/python3.12 -m scripts.cohort_construction.p1_source_quality.p1_quality_v0_3_1.verify --repo "$PWD"
```

需要本地忽略目录中的 v0.2 冻结输出、临床缓存及原项目影像输入。首次运行将完整影像输入复制到非 iCloud 缓存，逐文件匹配 v0.2 的输入 SHA-256。后续运行使用已核验缓存，不重新触发下载。

## 核验强度与保留限制

影像原始来源核验沿用 v0.2 已保存的逐来源证明，前提是索引输入字节哈希完全一致；本次不声称重新从原始记录簇独立核对。临床记录使用完整 L1 源文件、患者关联、物理行与原文哈希回溯。所有处理视图均与源记录关联，不写回或替换原文。

ABC 按全历史记录中“是否检出”标记，不能解释为同一时点状态或临床明确缺失。临床标题识别、目标语境及 ABC 词表属于本版操作化启发式，尚未经医生独立验证；未知标题/未命中/来源未核实都保留待核机会。正文中仍可能存在复制、家族史或所指对象不明确的内容，不能把检索命中解释为当前决策。

局部阴阳表述差异只标记 `DIFFERING_LOCAL_DESCRIPTIONS_REVIEW`，不确认真实冲突或选择真值。角度与尺寸保留原始逐条表达，不生成整个人的切除性判断。术后为上下文线索，不是 P1 否决条件。

引用的日期/检查号匹配是初筛；只有明确检查号且可核验原报告的唯一检查组才标 `FOUND_EXACT`，仍不证明报告当时可见。仅日期匹配为候选，查不到和未独立核验分开。未来检查计划、线索不足引用均单列。

## 输出与安全范围

患者、影像、临床原文索引、引用台账和开发样本仅写入忽略的 `local_artifacts/p1_quality_v0.3.1/results/`。源数据读取失败或全量覆盖与冻结运行不一致时不得发布完整重跑结论。公开 `docs/` 只保存聚合结果、合成案例和哈希回执。旧实现与旧队列不改写，P2 代码与既有统计不在本版本修改范围内。

本版相对 v0.3 的修复及完整回归索引见 `docs/P1-v0.3.1-变更原因与回归覆盖-20261021.md`。统一保护入口为 `regression_guard/run_checks.py`：54项当前测试与51项历史测试，并核对31个已知问题的必需用例。
