# 单病例 checkpoint 组织草稿

本模块回应“已经找到一条决策记录后，怎样组织它的前状态和后续”。只实现人工核对后的 N01 案例，不是新的全队列检索、P2纳入或episode分割规则。

`snapshot.py`提供精确时间检查、当次动作切分、原始检验时点选择、展示层身份遮蔽和可见时间审计。`build_n01.py`声明本例的来源选择：六份既往临床文书、当前文书中动作之前的原文、两份原始MR/CT、138条时点前报告的检验原始结果。原文按来源分块，不拼成新的临床事实，不使用抽取标签替代事实。

按正文落款假设时点2024-12-10 09:26重建。当前医生选择从“今予PTCD”开始隔离；既往已经发生的操作和已提出的计划保留为历史。当前执行、后续状态/决策、后续病理与全历史分析字段不得进入Agent输入。原始文件不改，只生成展示/重建副本。

这份草稿**尚未认证真实可见性**：部分正文描述较早事件，但系统创建较晚；影像只有检查时间，没有签发或阅片时间；检验使用来源报告时间作代理。不能偷偷用正文排序宣称实现了真实EHR的as-of查询；也不能用创建日期晚便断言医生此前不知道相应事实。正式盲评须单独确定/核验该层规则。

```bash
python -m unittest discover -s scripts/cohort_construction/p2_checkpoint_casebook/tests -v
python -m scripts.cohort_construction.p2_checkpoint_casebook.build_n01 --repo "$PWD"
```

输入为上一轮已保存临床上下文、用户交付的本例患者源资料包及原始影像入口。只读明确列出的字段；完整资料包含结局，因此不能将整个源资料包当作输入。源路径、哈希、坐标及排除记录留在私有审计文件。

输出位于忽略Git追踪的 `local_artifacts/n01_checkpoint_casebook_v0.1_20261022/`：

- `agent_state_reconstruction.json`、`N01-决策前资料草稿.md`：按事件时序重建的研究展示草稿；
- `reviewer_source_audit.json`：隔离的当次动作、来源、两套时钟及检验选择审计；
- `reviewer_only_followup.json`、`N01-当次选择与后续-研究者查看.md`：当次选择与之后执行/反馈/再管理原文，不能进入该时点输入；
- `build_receipt.json`：输入/程序/输出哈希、覆盖及未完成的可见性认证。

合成测试覆盖：CP-001未来/缺失报告时间结果不进入前状态；CP-002日期精度不补午夜；CP-003当前动作隔离；CP-004正文早但创建晚的差异保留；CP-005仅遮蔽展示副本且保留临床事实；CP-006只复制指定状态字段，不整包泄露结局；另有动作锚点多义失败及既往操作原文保留对照。病例构建还核验138条报告均早于假设时点、后续文书键未进入输入，以及当次切分位置。

测试验证资料组织的代码行为，不证明决策临床正确、实际可见性或Reference成立。本轮没有调用任何模型接收患者资料，没有生成专家可接受动作集合。
