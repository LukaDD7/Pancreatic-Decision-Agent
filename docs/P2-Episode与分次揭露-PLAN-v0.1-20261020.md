# P2 Episode、分次信息揭露与 RSI：简明 PLAN

历史讨论稿。2026-10-23起当前流程见 `P2-重建验证与医生盲评衔接流程-v0.3-20261023.md`。下文P1 PASS池、episode操作定义和实施顺序均是当时提案/观察，不能作为新P2的默认纳入门槛或已冻结episode规则；新工作遵循AGENTS.md。

2026-10-20｜讨论稿 v0.1｜P1 v0.2 队列保持不变，尚未正式生成 P2 队列。

**建议采用“自然临床 episode + 可变轮数的信息揭露”。先建立可复现的固定证据回放，再在有真实结果支持的子集上增加主动取证。RSI 可以复用同一环境，但不能改变患者证据、揭露边界或评分标准。**

## 1. 数据探查支持什么

既有全量审计：P1 通过 2,004 人，合格报告内容版本 7,794 个、检查组近似数 4,442；565 人只有一个检查组，不能预设所有人均有三轮。单检查组也可能有检验、病理、会诊等更新，不能据此判为单节点。

今天重新读取的范围有限：265 个临床 Parquet 中 255 个为 iCloud 云端占位；10 个本地可读文件有 10,788 行，涉及 112 名 P1 通过者。从中按单检查组、多检查组、质量/时间边界三层各取 10 人，固定种子 20261020，共读取 878 条胰腺相关非护理等文书、864 个患者内不重复全文，关联冻结的 93 个合格影像内容版本。30 人的影像原始患者文件本次均为云端占位，未重新核实签发时间。

这是**便利性开发抽样**，不代表全队列分布，也不构成 episode 验证。探查发现：

- 30 人均有手术评估/术前讨论候选表述；19 人有追加取证表述，10 人有新辅助治疗表述，8 人有再评估表述。均可能包含历史回述或模板内容。
- 宽泛否定手术规则命中 25 人，包含“无腹部手术瘢痕”“无手术禁忌症”等误触发；限定否定作用范围后为 3 人候选，仍涉及既往判断或术后转移病变，不能直接作为当前原发灶 episode 的结论。
- 全部 30 人在多个文书记录日出现手术相关表述；这不能证明存在多个 episode。原文可在入院、查房、术前小结中反复回述同一历史事件。

**结论：有可提取的决策过程，但必须先区分“当前判断／历史回述／条件性计划”以及“原发灶／术后或复发病变”，再切 episode。** 文书有钟点也不等于已证实当时整篇可见。

## 2. AMIE 是否值得借鉴

| 方法 | 可以借鉴 | 本研究应限制的外推 |
|---|---|---|
| [AMIE 疾病管理，Nature 2026](https://www.nature.com/articles/s41586-026-10764-5) | 三次模拟访视逐次加入新信息、保留前次对话、逐次评价管理调整 | 不能把真实 EHR 强制均分为三段；预设后续信息主要检验更新能力，不能单独证明 Agent 会主动选对检查 |
| [MIRA，Nature 2026](https://www.nature.com/articles/s41586-026-10675-5) | 把证据获取变成可执行、可记录的工具动作 | 沙盒中的动作接口不能自动解决本队列的时点可见性、真实检查覆盖和反事实结果缺失 |
| [Sequential Diagnosis / MAI-DxO，2025 预印本](https://arxiv.org/abs/2506.22405) | 将请求动作、环境响应和取证成本分别记录 | 不照搬可为未观察检查生成结果的模拟方式；真实资料回放不能据此补造分支 |
| [MedRSI，2026 预印本](https://arxiv.org/abs/2609.24838) | 按临床后果组织失败，候选改动与稳定版本分开，跨患者验证后再保留 | 其诊断/影像实验不等于已证明可优化胰腺手术序贯决策 |

因此，方案中“AMIE 的分次揭露不适合 RSI/Memory”宜改为：**固定揭露可以支持记忆和更新策略的优化，但不足以单独评价主动取证能力。** 这是本次方法综合后的建议，而非 AMIE 对本研究的验证结论。

## 3. P2 的操作性定义

**一个 episode 是围绕同一目标病变、同一次当前根治性切除评估任务的连续决策过程；一个 checkpoint 是其中一次实际可观测的证据/判断更新。**

| 环节 | 建议规则 |
|---|---|
| 进入 | 研究期内临床记录对当前目标病变提出根治切除可行性或管理取舍，包括明确“不宜手术”的否定评估；单纯“胰腺外科”、CT 日期或既往“曾建议手术”不足以确认进入 |
| 候选提取 | 手术指征/可切除性、根治意图、MDT/会诊、为手术而进行的分期取证、NAT 后手术再评估等信号宽召回；保留原文、来源键、事件时间、记录时间、目标病变及当前/历史/条件性角色，疑义待核 |
| 持续 | 同一任务未结束，补影像、活检、会诊或处理当前证据冲突，形成可变个数的 checkpoint；同轮报告不按字段拆开，重复文书不制造新节点 |
| 结束 | 实际进入预先定义的不可逆根治手术步骤、明确转向 NAT/其他治疗而离开当前手术路径，或失访/转院/数据截止。CENSOR 单列，不能当 REDIRECT |
| 再进入 | NAT 后重新出现手术评估，创建新 episode，链接前一个 episode；已有历史仅作为当时可见背景，不延长原 episode 为完整 NAT 管理过程 |

当前方案存在一处应先统一的语义：`ADVANCE` 既可表示继续术前准备，又被用于 episode 终点。建议另存 `terminal_event`；**mode=ADVANCE 不自动等于已进入不可逆步骤**。episode 的观察起点也与第一个有效提问 checkpoint 分开。

## 4. 分次揭露怎样兼容 RSI

先使用同一份冻结的证据台账，按两种协议运行，结果分开报告：

1. **固定回放作为主分析。** 按可核验的真实可见先后生成 `D0 → D1 → … → Dk`，轮数由资料决定。每轮呈现截至该点累计的完整可用记录，让模型按现有接口输出 management mode 与首选取证动作；不能通过事后拆删一份完整报告来制造序贯性。已包含被评价医生建议的文书应整篇隔离，或改为方案复核任务，不能只删掉计划句制造独立决策输入。时序不明的同日记录合并或待核；“排序代理”不能冒充真实签发时间。
2. **受限主动取证作为扩展。** 仅在有真实、时间与语义均可支持该请求的结果时响应；明确区分“读取已完成检查”和“请求未来实施检查”。无可验证分支就返回 `UNSUPPORTED_REPLAY` 并终止该分支的效果推断，不能填阴性、虚构结果或自动跳到下一轮。对无支持请求不记医疗错误、不提供下一步提示；单列分支中止率，避免把历史做过哪些检查变成隐藏答案。它是有限历史回放，不是治疗反事实模拟。
3. **RSI 优化 Agent，不优化考题。** 患者级划分开发、验证、锁定测试；同患者的所有 episode 同属一组，本次已探查者标为开发。允许迭代提示词、工具、记忆或规则；每次改动先在独立患者验证，冻结后再测。单病例信息在本例节点间保留，跨患者原始病例状态清空；测试参考答案不进入经验记忆。

环境只固定证据、动作接口、时间边界和评价 contract，不预置必须由 RSI 学得的 patient-state 或临床决策规则。B1 完整当前病史、B2 加指南/工具继续作为基线；比较时记录同一可见证据与计算/调用预算。Q1–Q5、Severity 与专家 Confidence 分别保留；节点 reference 的专家只见当节点证据，不能用后续真实轨迹替代当时可接受的选择。评价同时看错误推进、无必要等待、错误转向、取证价值和更新行为，避免“永远 HOLD”获得虚假优势；仅固定回放获益时不声称主动取证已改善。

## 5. 推荐执行顺序

| 步骤 | 产物 / 进入下一步前要回答的问题 |
|---|---|
| ① 冻结 P2 v0.1 契约 | 确定 entry、terminal_event、NAT 再进入与当前/历史角色；先解决 ADVANCE 语义，不改 P1 成员 |
| ② 核验 30–50 例候选 | 覆盖初始评估、NAT 后评估、明确否定、单节点和冲突例；人工确认边界与来源时间。记录候选漏检/误触发，未确认者不计正式 episode |
| ③ 建立首批回放集 | 先形成约 50–100 个可核验 episode；不足则报告实际数量，不凑三轮、不伪造。单节点可用于 node-level；至少两个有效节点才可能用于序贯更新；主动取证另评覆盖率 |
| ④ 再接 RSI | 固定环境、患者划分和专家参考后，开发失败→候选改动→独立验证→版本冻结；最后一次性评价锁定测试。P3 继续逐 episode/checkpoint 判断正式纳入 |

**下一步优先做 ①②：先证明 episode 边界及信息顺序可重建，再决定多少病例能够提供固定回放和主动取证环境。**
