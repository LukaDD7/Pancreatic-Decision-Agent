## 1. 变更与反例覆盖

### 1.1 CE-REAL-012：正式执行分离两个来源范围

- `input_contract.sources` 保存当前处理单位原文与冻结事件 `event.source_ids ∪ actual_model_evidence[].source_id` 依赖闭包。
- `input_contract.graph_audit_sources` 单独保存当前处理单位完整原文。
- 正式首次执行及成功重建后的新图运行均分别传入这两个集合；普通执行、resume 和无模型 replay 按合同各自重建请求。
- 图审核和独立重建只使用 `graph_audit_sources`，不因材料需要历史来源而扩大声明处理单位。
- 材料装配使用 `sources`，不以删除历史证据或缩小来源集合掩盖缺口。
- 新增完整 `execute_batch` 首次图审核 PASS 反例：current=3、material=4，实际进入两个 Checkpoint 的材料请求并核对 `DOC-BUDGET` 已在请求内，装配失败为空、`MATERIAL_PREPARATION=PASS`。
- 新增成功 generation 批次反例：重建链来自初始 Episode 的 REVISE 父运行；新图重新独立图审核 PASS，冻结合同继续保持 current=3/material=4。

历史单范围合同只在显式历史 replay 下按旧单范围语义解释；严格当前实现 replay 不允许它静默冒充双范围新合同。

### 1.2 CE-GRA-010：真实 Client 的 transport Schema 异常证据

- `ModelRequestFailed.response_evidence` 在正常 return 之前的私有异常通道中保存可解析 JSON object 和 provider envelope。
- 脱敏异常回执保留该次 `invocation_id` 及与成功路径一致的 envelope `response_sha256`。
- 失败链恢复实际解析 response，并保存 invocation、provider response hash 和解析后 response content hash；保留 `transport_response_schema_rejected`。
- HTTP/TLS/JSON 解码失败没有可解析 response，不伪造响应或 provider 回执；Schema 失败仍失败关闭，不能成为候选新图。
- 使用生产 Client、仅 mock HTTP 的反例验证响应和调用身份留存，且异常字符串、脱敏 invocation archive 不含该响应或凭证。

### 1.3 CE-GRA-010：失败链不能凭自 hash 跨父图通过

- provider 无响应及 response 校验失败两条路径均先重建并核验完整请求，不再提前绕过 `_validate_request`。
- 批次 replay 从对应父运行的 `graph_audit_chain.initial_request` 和最后一轮 REVISE response 独立构造预期重建请求。
- 同时核对 case、输入图 hash、台账 task、expected_gain、context、request hash、invocation_id 和可用的 response hash。
- 修复成功 generation 的 gen1 父目录定位：先保存初始 Episode 目录，再将最终 replay 目录指向最后一代。
- generation 序号必须连续；汇总声明某代存在而相应 `reconstruction-*.json` 缺失时，以 `REAL_BATCH_RECONSTRUCTION_REQUIRED_CHAIN_MISSING` 拒绝，不得跳过链 replay。
- 保留合法失败正对照，以及修改请求后重算 hash、跨父图、伪造成功 generation 和缺链负对照。

### 1.4 完整套件下的测试隔离
