基线：`IPMN_研究方案_v1.0_完整版.docx` 与 `private/ipmn_data_readiness_v0/run_v0_20261113_r3/`，均只读保留

## 1. 唯一主研究链

本版只执行一条主线，扩展不再自动进入主流程。

| 项目 | 冻结方向 |
|---|---|
| 来源人群 | 实际监测路径中的 BD-IPMN；规则候选须经临床审定 |
| entry | 首次具备本研究诊断与监测语境的合格检查日，检查日与报告可用日分开 |
| landmark | entry 后 365 日；只使用当时及之前可得资料 |
| 主风险集 | landmark 前存活、未发生目标恶性事件、未确诊 cPDAC且 index 未切除者 |
| 主结局 | landmark 后 1095 日内首次临床确诊 IPMN 相关 HGD/浸润癌，须独立归属审定 |
| 主表型 | 结局盲态下冻结的唯一纵向表型；无合格候选则停止主检验 |
| 强对照 | M1 包含冻结的静态及已知动态信息，包括有符号变化和可支持的胰管、结节、检验变化 |
| 主检验 | 同一确认患者集合、同一风险起点和结局审定下，M2 对 M1 的唯一预定检验 |
| 推断单位 | 患者；所有病灶、检查及时点按患者划分开发与确认 |

开发、测量复核和结局审定可以并行，但通过角色和文件权限隔离信息。任何阶段不得以确认集癌结局选择表型、窗口、切点或模型。

## 3. 分阶段实现与停止规则

| 闸门 | 必需工作 | 承接对象 | 未通过时允许的成果 |
|---|---|---|---|
| G0 来源通道核对 | 对齐原始报告、临床文书、检验、旧研究字段和派生表；标明时间、单位、来源及可采用范围 | 来源通道说明、稳定问题编号、回源证据引用 | 来源与接口修复；不得声称患者层面缺失 |
| G1 人群与测量准备 | 临床审定风险集和患者隔离；闭合 index、协议、复测误差；冻结 M1 组件 | 审定人群索引、测量长表、M1 字典 | 资料质量、测量重复性或可行性成果 |
| G2 盲态候选准备 | 仅用许可开发资料；限制候选与预算；冻结唯一主表型及计算 manifest | 候选清单、失败台账、冻结 manifest | 无合格候选则结案，不进入确认集补选 |
| G3 结局与统计放行 | 独立审定事件、竞争事件和失访；隔离统计确认共同集合、自由度和精度 | 结局审定记录、统计放行记录 | 信息不足则限制成果，不更换主结局或强对照 |
| G4 临床确认 | 六项结构化复核全部有证据通过；应用冻结表型和 M1/M2 | 唯一主检验及预定区间、失败或支持结论 | 不得重复解盲改版后仍称独立确认 |

G1–G3 的具体先后由资料角色安排，但最终放行条件不因并行而减少。审计汇总人数不能替代任何临床、测量或统计复核。

## 4. 最小数据与反馈接口

主执行链只保留五类对象：

1. **人群索引**：患者、entry、landmark、开发/确认分组、临床审定状态和来源引用。
2. **测量长表**：患者、病灶、检查、模态/协议、测量时间、可用时间、数值、单位、测量版本和质量状态。
3. **候选 manifest**：公式、输入窗口、最少观测、缺失规则、代码 hash、父候选、失败原因和冻结状态。
4. **独立结局复核**：事件类型、来源归属、日期依据、竞争事件、失访、复核角色和证据引用。
5. **复核承接单**：把上述放行状态交给临床确认阶段，不携带候选—结局关联结果。

`scripts/ipmn_data_readiness/audit.py` 接受可选 `--review-file`，并输出 `readiness_handoff.json`。来源索引人数从实际 CSV 推导，不再把 r3 的 7,122/9,921 写成接口前提；重复 ID、L1/L2 断链和患者包覆盖不完整均明确失败。

候选冻结后的独立放行使用 `scripts/ipmn_data_readiness/release.py`，直接读取既有 `summary.json`，不为取得承接单而重跑审计。复核项固定为：

- `source_channels`
- `clinical_population`
- `measurement`
- `outcomes`
- `analysis`
- `candidate_freeze`

每项状态为 `pending`、`passed` 或 `failed`；未提供时为 `missing`。`passed` 和 `failed` 必须同时提供 `reviewer_role`、`reviewed_at` 和非空 `evidence_refs`。证据引用指向本地审定记录，不在承接单复制患者原文。未知复核项和未知字段直接报错，避免拼写差异被当成未完成或已通过。

`candidate_freeze=passed` 还必须提供 `artifact_sha256` 和实际候选 manifest。manifest 遵循 `contracts/ipmn/v0.1/candidate_manifest.schema.json`，绑定审计 summary 的规范化 JSON hash、唯一主表型、时间窗、测量与代码 hash、开发/选择患者集 hash、结局未接触声明及 M1/M2 主检验。程序拒绝多个主候选、已知再发现冒充新主表型、非选中候选无失败原因、结局或 landmark 后来源字段，以及复核后 manifest 被替换或篡改。

承接单只有三种决定：

- `READINESS_REVIEW_REQUIRED`：仍有复核缺失或待完成，临床确认不可运行。
- `REPAIR_REQUIRED`：至少一项复核失败，必须先修复相应来源、接口或方案执行。
- `READY_FOR_CLINICAL_CONFIRMATION`：六项均有可追溯通过证据，且候选 manifest 通过语义和 hash 核验，才允许调用冻结分析。

```bash
python -m scripts.ipmn_data_readiness.release \
  --summary <既有审计目录>/summary.json \
  --review-file <独立复核文件>.json \
  --candidate-manifest <冻结候选>.json \
  --output <新承接单>.json
```

`--review-file` 只供独立放行流程使用，不得注入候选发现 Agent 的上下文。程序只校验契约、hash 和证据存在性，不替代临床或统计判断；承接单及其实现 hash 一并保存。

### 4.1 冻结候选的最小实际计算链

`scripts/ipmn_data_readiness/measurement.py` 定义审定测量长表。每行只表示一个患者、一个测量对象、一次检查和一个变量，并携带 entry、检查日、实际可用日、可用性依据、模态、协议、单位、来源引用、测量版本及身份/协议复核。未知字段会被拒绝，避免结局信息混入计算输入。

`compute_candidate_values(manifest, rows, patient_ids)` 当前只执行两种白名单公式：

- `signed_size_change / observation_days`
- `signed_mpd_change / observation_days`

不执行任意表达式。内置公式的 `code_sha256` 是 `candidate.py` 与 `measurement.py` 文件 hash 对象的规范化 JSON hash；release 和计算阶段都核验，避免引擎更新后沿用旧放行。

计算前校验全部输入，并按以下规则失败关闭：

- 检查日和可用日都必须落在 manifest 时间窗内；landmark 后才可用的报告不进入当时序列。
- 同一患者的目标序列只能有一个对象、一种模态、一个协议和一个测量版本；不得自动挑选某个囊肿或拼接 CT/MRI。
- 身份和协议复核均须通过；未复核、复核失败、数值缺失、同日冲突和观察间隔不足分别返回原因。
- 只使用预定首末观测计算有符号变化率，负增长保留；缺失值不补成正常或零变化。
- 可显式传入分析患者集，集外测量行报错；集内无测量者也保留为 `not_computable`，不因缺少值而从覆盖报告消失。

输出包含患者、候选、manifest hash、计算状态、值或不可计算原因，以及首末测量引用，不包含患者原文或结局字段。

## 5. 当前底层探查问题：IPMN-HARNESS-001

**首次异常层：汇总展示。** r3 中 351/926 人有同模态重复 MPD 明确状态，4/926 人仅有一次数值覆盖，0/926 人有重复数值；与此同时，部分 `analysis_only` 旧研究行可见胰管测量字段。

**已知事实：**旧研究字段与报告文本属于不同证据通道；旧字段可能来自手术选择子集、既有影像测量或不同时间口径，不能直接并入纵向主分析。r3 的“0”只描述当前报告解析及同模态汇总链，不证明患者没有测量。

**尚未证实：**原始报告中数值的实际覆盖、字段映射是否遗漏、正则是否丢失真实表达、旧字段的来源与日期。当前 `/Volumes/LQ1000/IPMN` 不可访问，不能完成全量回源，故本轮不登记为已证实解析错误，也不修改 MPD 正则。

**恢复来源后的最小核查：**

1. 对重复状态但无数值者分层抽样，核对相应时点原始报告，而非只看派生 JSON。
2. 沿 `exam_view` → `mpd_measurement` → `mpd_days` → `build_tables` → 报告逐层重放，定位首次信息丢失层。
3. 对 `analysis_only` 字段追查生成来源、测量对象、日期和单位；无合法时间及来源者不补入主轨。
4. 若证实提取错误，登记新的解析问题编号、最小反例和阳性/阴性对照，再修复并用新旧运行 diff 说明迁移。
5. 若原报告确实未提供数值，保留“明确状态可得、数值不可得”，不得把状态正常换算成 0 mm 或其他假定值。

## 6. 本轮移出主执行链的功能

以下项目保留为未来独立方案，不删除历史设计，但当前不自动实现或运行：

- 潜在状态、HMM、状态转移 taxonomy 和连续演化扩展；
- 全胰腺 cPDAC 扩展及其与主结局的复合使用；
- CT/MRI 跨模态合并、原始影像分割和无来源 DICOM 的测量承诺；
- Agent、专家、规则搜索三臂效率试验及单 LLM 消融；
- 重复 landmark、五年主窗口、预测模型外部验证、DCA 和干预策略评价；
- 无下游消费者的知识图谱展示、重复候选台账和绕过承接单的直接建模入口。

需要恢复其中任一项时，必须另写研究用途、输入输出契约、消费者和验收方式，不得借“以后可能有用”重新挤入主流程。

## 7. 不可因瘦身删除的边界

- 原始来源、时间、单位、版本和证据引用；
- 结局盲态、患者级开发/确认隔离和未来信息隔离；
- M1 已知动态强对照和唯一主检验；
- 未提及、明确阴性、无法判断、程序未识别和来源未交付的区分；
- cPDAC 与 IPMN 来源事件审定、竞争事件和失访处理；
- 无合格候选、信息不足、主假设未支持和获得独立支持的分流结案。

所有异常均按项目 `AGENTS.md` 第 11 节执行：先重建 harness 链，再定位根因；最小修复后做端到端回归，同时删除无消费者的接口、上下文和反馈回路。未完成该闭环不得写成“已修复”。
