# P2决策记录定位：规则与程序逻辑

说明修订：2026-10-21，v0.3.2。程序与统计仍为2026-10-20的v0.3.0；本次只调整逻辑表达。

**本轮要找的是：哪份文书承载了“当次是否推进胰腺切除路径”的判断、计划或待评估安排，以及这份记录之前是否已有相同/相反意见。先定位源文书中的语义记录，再确定研究决策单元；不能从标签数量直接得到独立临床决策数。**

这里的“双向”只指两个查看角度：从标签找到上下文，以及从少量已读懂的样本检查标签是否合适。它只用于核对现有规则，不另设方法框架或队列标准。

新版已重跑同一批100/300人，修复已知词形与作用域问题；另复核12名患者的12份目的抽样源文书及邻域，8份支持当次意见/评估安排，4份为待核或错误对照。建议先读[4例私有导读](/Users/lucachangretta/Documents/ChatGPT/不可逆胰腺癌根治术决策智能体/private/p2_localization_v0.3_20261020/双向语义样本-导读-v0.3-20261020.md)。具体原文、来源键、偏移及时间线见[私有双向样本卡](/Users/lucachangretta/Documents/ChatGPT/不可逆胰腺癌根治术决策智能体/private/p2_localization_v0.3_20261020/双向语义决策记录样本-v0.3-20261020.md)。这12份参与规则迭代，不是独立验证集，8/12不是准确率。

## 1. 先说明单位，避免混用

| 名称 | 本文定义 | 不能据此推断什么 |
|---|---|---|
| 患者 | 固定P1名单中的patient_uid | 零标签不等于临床未评估 |
| 文书 | 一条有原文和来源键的病历记录 | 一份文书不一定是一项新决定 |
| visit | 源系统VISIT_ID标识的一次就诊分组 | 不等于研究episode，也不是AMIE式预设的信息揭露轮次 |
| 患者—visit | `(patient_uid, VISIT_ID)`二元组，只用作检索容器 | 同次就诊可能有多次判断；跨就诊也可能仍在同一评估过程 |
| 标签 | 文字满足预定义匹配规则的结果；允许多标签 | 不是已证实的临床判断或专家标签 |
| 锚点 | 用来检索前后文的一条标签文书及其观察时间 | 不默认它是首次或实际决策时点 |
| 语义决策记录 | 结合全文，确实承载当次选择、暂缓或待评估安排的记录 | 不保证意见正确、首次形成，或满足正式P2/P3纳入 |
| 候选链 | 将相近、文字状态相同的候选文书连起来，供复核 | 不是独立决策数，也不是episode数 |

缺失VISIT_ID的文书各自成组，不能把所有未知visit合并。临床“首次作出决定的瞬间”通常不能由记录时间直接证明；本轮先定位可追溯的意见记录及时间不确定性。

旧报告的**“原根治计划”仅是旧字典 `PLAN_CURATIVE_PANCREAS` 的缩写**，指文字满足v0.2的“胰…根治”等表达，并不表示临床已确认可根治。这一缩写未在旧报告开头定义，容易误读；新版不再把它当医学类别，统一改用下表中明确定义的具体切除计划标签。

## 2. 三个operator怎样落地

### 2.1 文字：先匹配，再判断作用域与上下文

| 新标签 | 可执行的召回定义与例子 | 后续怎么用 |
|---|---|---|
| PLAN_RESECTION：具体切除计划 | 明示“拟/计划/建议/考虑行”等意向，或“拟施手术名称和手术方式”字段，连接具体胰腺切除名称 | 首要计划线索；不要求含根治二字，也不自动确认根治意图 |
| INDICATION_YES：肯定线索 | 有〔明确/外科/根治性〕手术指征、手术指征明确、可切除、可手术等 | 必须排除疑问/否定作用域，并确认不是穿刺、疼痛等操作指征 |
| INDICATION_NO：不推进手术线索 | 无手术指征、不宜手术、不可切除、暂缓手术、不建议手术、患者拒绝手术等 | 检索的是“不推进”的表述；疾病、身体状态和意愿原因仍不同，不能统一叫解剖不可切除 |
| ASSESSMENT_PENDING：待评估 | 是否有手术指征、是否可切除、待检查明确手术方案、处理问题后再评估外科手术 | 保留未形成最终结论的当次安排 |
| NAT_PLAN：新辅助/转化意向 | 拟/建议/先行/推荐等连接新辅助或转化治疗；排除病名中的“新辅助治疗后” | 先召回；只有同文书另有明确当次手术判断/重评语句时才进入主候选，单次化疗周期不自动算手术重评 |
| GENERIC_SURGERY_PLAN：泛手术意向 | 拟行手术治疗、择期/限期手术等 | 作为更早意见的辅助线索，操作对象需上下文核查 |
| FITNESS_CONTEXT：禁忌相关上下文 | 无/未见/排除手术禁忌等 | 单独命中不生成主候选，也不证明检查已完成或可切除 |

这是检索字典，不是临床管理模式分类。旧版“当时无手术指征”在新版保留为否定文字加历史角色；不再依赖另一个PAST标签代替上下文判断。完整正则、80字符限制和各组名单在 `configs/rules-v0.3.json`，与实际程序一致。

具体切除名称至少覆盖：胰十二指肠切除、胰体尾/胰尾/胰腺等切除或根治、次全切/大部分切除、全胰切除和Whipple；允许“切除/切除术/切除手术”“根治/根治术”“次全切术”等词形，允许根治性位于胰之前。机器人、腹腔镜等修饰可位于意向与解剖名称之间。字典仍非自然语言的穷举，未命中者保留待核。

### 2.2 文书类型：原始名称与归并组分开存

**“首次上级查房”是代码归并的文书类型组，不是判断标签，也不一定是医院原始名称。**

| 原始文书名称的模式（示意） | 归并组 | 中文称呼 |
|---|---|---|
| 某主治医师首次查房记录、首次主任医师查房记录等 | FIRST_SENIOR_ROUND | 首次上级查房 |
| 首次病程记录 | FIRST_COURSE | 首次病程 |
| 其他…查房记录 | WARD_ROUND | 其他查房 |
| 术前小结 / 术前讨论 | PREOP_BRIEF / PREOP_DISCUSSION | 术前小结 / 讨论 |
| 会诊、MDT/多学科、转入/转出、门诊、入院等名称 | 各自独立组 | 不混为首次查房 |

原始名称完整保留，归并优先级见 `documents.py`。因此，“无手术指征＋首次上级查房”只表示**该句出现在这类文书里**；是否是当次判断，仍要看它位于现病史、诊断依据、医生分析还是治疗计划。

### 2.3 时间：每个字段有不同含义

- 正文头时间：文书开头声明的日期及时分；没有时分则不补午夜。
- 系统记录时间：源create_time；缺失时使用入院时间回退，并标明来源。
- 讨论日期：从“讨论日期”字段另行保存，日期精度不冒充小时精度。
- 计划手术日：只表示计划日期，不是决策时刻，也不证明已执行。

正文与系统时间均暂作观察时钟；另标正文/系统日期不同、讨论日/正文日期不同。不能统一用文书时间减24/48小时推算决策日，也不能用最近影像检查时间取代决策时间。

## 3. 程序首先怎样找候选记录

采用“**判断步骤 → 短注释说明原因 → 具体分支 → 实际代码操作**”的写法。中文伪代码解释逻辑；函数名、局部范围和正则说明实现，二者不混成一段完整程序。

准备时保留每份文书的原文、原始名称、归并类型和各种日期。实际入口为 `documents.py` 的 `load_sources()`、`document_family()`、`header_time()` 和 `explicit_dates()`；命中的文字偏移与来源键始终保留，便于核对。

### 3.1 匹配判断性表述

```text
寻找具体切除计划，以及肯定、否定、待评估等表述。
    # 先广泛找到文字线索；同一文书可以表达多项安排，不能强制只有一个标签。
    若具体胰腺切除名前有明确意向用语或拟施手术字段 → 标记具体切除计划。
    其余表述分别按肯定、否定、待评估、新辅助、泛手术和禁忌词表匹配。
    保存所有命中，随后再检查语境，不在这一步认定临床结论。
```

**代码操作：**`labels.py → Labeler.match()`。`operation_pattern.finditer()`先定位切除名称，再在**同一分句、切除名前最多80字符**内用`intent_pattern`找意向；分句边界包括句号、分号、换行及中英文逗号。其余标签分别使用`yes_pattern`、`no_pattern`、`pending_pattern`等匹配。完整词形见配置，切除、切除术、切除手术、次全切术及根治的不同词序均有覆盖。

### 3.2 检查疑问、否定及明确历史提示

```text
检查肯定命中是否实际处在疑问或否定语境。
    # “是否有手术指征”不能读成“有指征”；“不可切除”也不能只截取“可切除”。
    若肯定命中之前有“是否/有无”等 → 标记疑问，不作为肯定意见。
    若肯定命中前紧接“不/未见/否认”等规则中的否定形式 → 标记否定作用域。

检查明确历史或已执行提示。
    # 过去作过的选择不能因为在今天病历中被再次写出，就自动成为新选择。
    若命中前有“当时/既往/此前/曾经” → 标记明确历史。
    若切除计划命中前有“已行/曾行/完成了”等，或命中后紧接“后/术后” → 标记已执行或历史。
```

**代码操作：**`labels.py → Labeler.role()`先执行这些分支；命中范围用`start/end`定位。前文取**最多35字符，且不越过最近句号、分号或换行**；“紧接”由正则末尾的`$`限定，不是见到任何一个“不”字就排除。

关键实际操作摘录如下；`left`为最近句界之后的位置：

```python
prefix = text[max(left, start - 35):start]
# 疑问检查，仅作用于肯定标签：
re.search(r'是否|有无|评估.*(?:是否|有无)', prefix)
# 否定作用域检查，也仅作用于肯定标签：
re.search(r'不(?:存?在)?$|未见$|否认$', prefix)
# 明确历史提示：
re.search(r'当时|既往|此前|曾经', prefix)
```

切除计划的已执行检查另外读取命中后28字符，检查是否以“后/术后”开始，以及上述前文中的执行提示。**原肯定命中被标为疑问，不等于直接改写成待评估标签**；待评估和否定表述分别由`pending_pattern`、`no_pattern`独立召回。

### 3.3 结合段落与医生指示，判断是否为当次意见线索

```text
对前一步尚未明确判定的命中，查看段落及局部医生指示。
    # 同一句话出现在现病史或治疗计划中，含义可能不同；“目前”二字本身不够。
    若局部有明确医生当次指示，文书类型合适，且不在现病史等历史段 → 当次意见候选。
    否则，若在注意事项等模板段 → 模板上下文。
    否则，若在现病史、诊断依据等叙述段 → 叙述待核，不直接认定为历史。
    否则，若在配置的分析、治疗计划等段 → 当次意见候选。
    否则，若为术前小结/讨论中的具体切除计划 → 当次意见候选。
    其余 → 上下文不明，待核。
```

**代码操作：**仍在`Labeler.role()`内，按上面顺序返回角色。`Labeler.section()`用`section_pattern`找命中位置之前或从命中位置开始的最近标题；再对照`current_sections`、`narrative_sections`、`template_sections`三份名单。

医生指示在**命中前最多160字符、命中后60字符**的局部范围查找，前部不越过最近句界。现行规则包括`查房后…指示/指出`、`查看患者/病人后示`、`外科评估后`等。该局部提示在符合条件时优先于较早的引用影像“其它诊断”标题；但不覆盖`现病史/既往史/病史特点/诊疗经过`四类段落。这里是在说明启发式判定，并未认证真实临床发生时间。

### 3.4 检查所指操作，避免把其他操作指征当成切除指征

```text
分别判断每条命中的操作对象。
    # “有手术指征”可能指穿刺或疼痛操作；但“不宜手术，拟穿刺”仍有需保留的不手术判断。
    若为具体胰腺切除计划标签 → 记录为具名胰腺切除。
    若为肯定或泛手术标签，局部只有穿刺等其他操作、没有胰腺切除名 → 其他操作。
    其余命中，若全文有胰腺相关词 → 保留为胰腺上下文、具体操作未定。
    若连胰腺上下文也无法确认 → 对象不明，待核。
```

**代码操作：**`labels.py → Labeler.target()`。其他操作检查只对`INDICATION_YES`、`GENERIC_SURGERY_PLAN`执行，**不因同句出现EUS/FNA就排除否定判断**。它用`nonresection_procedure_pattern`和`operation_pattern`作局部对照：前部最多80字符且不早于当前段落起点，后部最多220字符并受下一标题限制，另补看命中后160字符。

其余命中用全文的`胰|PDAC|pancrea`检查提供胰腺上下文。这个保留值是`PANCREAS_CONTEXT_UNSPECIFIED`，**不等于已经确认根治切除对象**；完全无法确认时才是`TARGET_UNRESOLVED`。

### 3.5 汇总检查结果，区分主候选与待核

```text
汇总标签、语境、对象和文书类型四项检查。
    # 将“优先查看的候选”和“仍需核对的命中”分开，不能据此直接排除患者。
    只有同时满足以下条件，才列为主候选：
        属于具体计划、肯定、否定、待评估或新辅助等决策类标签；
        被判为当次意见候选；
        对象不是明确其他操作或完全不明；
        文书类型在候选名单中。

    若是新辅助/转化计划，再检查同文书是否还有当次肯定、否定或待评估语句。
        没有 → 保留为新辅助线索待核，不单凭一个化疗周期计划生成主候选。

    泛手术意向或无禁忌单独命中 → 只作上下文。
    不满足主候选条件的决策类命中 → 保留原文、来源和具体待核原因。
```

**代码操作：**`Labeler.match()`对照`candidate_labels`、角色、对象和`candidate_families`，把不满足的条件写入`review_reasons`；`eligible = not reasons`决定主候选标记。新辅助还检查同一文书内是否存在已通过前述条件的肯定、否定或待评估命中。`run.py`把未通过的决策类命中写入`review_queue.json`。

叙述段里也可能承载真实当次意见，因此`NARRATIVE_UNRESOLVED`是待核，不能解释为已证实历史。**正式P2不得只按主候选集合排人**；主候选只是优先复核队列，其余文字及完整邻域仍在。

## 4. 找到候选后，怎样查看时间关系并处理重复

先看标签之前有哪些文书和检查，再整理重复记录；最后用少量原文样本检查这套做法是否合理。下面的时间配对表和候选数量表用途不同，不能互相换算。

### 4.1 从标签往前看：哪些记录可能更接近判断

```text
对每个患者—visit，取首份含具体切除计划的术前小结或讨论：
    # 术前记录可能重复较早计划，因此向前寻找已承载判断的文书，而非直接倒减时间。
    查找它之前最近的首次上级查房，作为文书类型对照。
    查找它之前已写出当次肯定意见或具体切除计划的非术前文书。
    查找同患者更早的腹部CT/MR，作为可能的依据线索。

    分别看这些记录是否落在前24小时、48小时或7天内。
    更远的记录也保留；不能因超过窗口就丢掉。
    分别按正文时间和系统时间比较，保留时间不一致的情况。
```

**代码操作：**`run.py → main()`中的时间配对部分。先用`(patient_uid, visit_key)`分组，取观察时间最早的合格术前计划作为起点；在同组内筛选时间不晚于起点、且不是起点本身的医生文书，取时间最大的一份，即最近的更早记录。影像在同患者范围取不晚于起点的最近检查。计算小时差后分别统计`≤24/≤48/≤168`小时，不先按48小时删去记录；正文优先和系统时钟各算一遍。

这一时间配对先看“有术前计划”的一支；后面的候选数量统计还包括否定、暂缓和待评估记录。两张表的对象不同。

配对允许时间相等，等时记录不证明真实先后。影像按同患者已提供的腹部CT/MR、检查日期及名称关联，可以早于本次就诊；检查时刻不等于报告可见时刻，未证明是哪项触发了判断，也未解决版本冲突或逐项核定增量价值。

本轮术前计划锚点为293个**患者—visit组合**：每组首份符合条件的术前小结/讨论，二者合并取首次；不是293名患者，更不是293次新决定。

| 锚点之前的配对对象 | 找到配对 | ≤24h | ≤48h | ≤7天 | 已配对观察间隔中位数 |
|---|---:|---:|---:|---:|---:|
| 任意首次上级查房 | 292 | 155 | 221 | 286 | 23.05h |
| 非术前文书中的当次肯定/具体切除计划 | 231 | 96 | 145 | 228 | 27.10h |
| 腹部CT/MR检查 | 268 | 83 | 125 | 206 | 56.93h |

表中医生与检查是不同用途：医生意见承载选择，检查用于寻找依据。首次上级查房值得优先查看，但“同类当次意见”覆盖低于“任意首次查房”，二者不能互相替代。**现行程序先取同visit最近的合格记录，再统计24/48小时和7天的距离；不是先截断48小时再自动逐级扩大。** 人工查看时可先看48小时内的记录，再继续查看7天、完整就诊及相关既往记录。医生文书的跨visit追溯目前靠样本复核，不是这一自动配对步骤。这一时间规律不能直接套到历史否定或化疗回述。

**这张表取的是最近一份更早记录，衡量近邻检索，不估计最初决策发生的延迟。** 即便48小时内配对成功，完整时间线中仍可能已有更早同类意见；必须继续查是否属于重复确认。本轮已读的源文书样本中有这种情况。

### 4.2 整理重复：哪些文书暂时放在一起

```text
将同一患者、同次就诊的候选文书按时间排列，依次比较：
    # 同一选择可能在多份文书中重复；相反意见则需要单独保留，不能被时间接近掩盖。
    若文字选择相同，且距本组第一份记录未超过设定窗口：暂时连为一组。
    若文字选择不同，或超过窗口：另列一组供查看。
    若出现相反意见：标记为“冲突或可能更新”，不自动认定真实更新。

跨就诊再检查相同判断句是否重复出现：
    标记重复，保留来源；不直接认定每次都是新决定，也不直接全部合并。

最后统计每人有多少组候选记录，包括零候选患者。
```

**代码操作：**`timeline.py → witness_state()`先把具体切除计划/肯定合为手术路径文字状态，否定、待评估、新辅助各自保留，允许组合；`build_chains()`在同患者—visit内排序，仅在**状态完全相同、距本组首条记录不超过窗口**时追加，状态变化或超窗则另组。相反意见加`OPPOSING_OPINIONS_OR_UPDATE_REVIEW`标记。

跨就诊重复由`cross_visit_repeats()`处理：去掉判断句的空白后，按“患者＋标签＋句子”分组；若出现于多个visit，则标重复。只去空白，不删除数字，也不凭这个标记自动合并临床事件。

这里的一组就是前面定义的“候选链”，只是暂时整理在一起的文书。

窗口分别为24/48小时和7天。不是每visit每标签只留第一次；同一visit相反意见不会因为时间近而被合并，但也不自动认证为两次真实更新。同结论的实际重评仍可能被压缩，相同旧计划跨窗口仍可能被拆开，因此链数只是复核工作量指标。

按正文头优先、48小时压缩：

| 固定样本 | 主候选文书 | 候选链 | 每人链数中位数（Q1–Q3） | 零候选患者 |
|---|---:|---:|---:|---:|
| 100人 | 300 | 153 | 1.5（1–2） | 4 |
| 300人 | 862 | 423 | 1（1–2） | 13 |

300人改用24小时/48小时/7天，候选链分别为504 / 423 / 331，逐人中位数分别为2 / 1 / 1。**这说明候选数量受压缩定义影响，不能把“中位数1个”直接解释成人群真实的决策次数。** v0.2的450个候选点和本版链数也不能直接比较优劣：字典、上下文范围及压缩规则同时变化。

### 4.3 用少量原文检查上述规则是否合适

抽取少量记录读全文，检查两件事：**命中的话是否真的表达当次判断；全文中已有的判断是否被规则漏掉。** 同时看前后文，判断是否只是重复、回述或意见冲突。这就是本轮“双向”的概念含义，不另设一套定位流程。

本轮不是先认定所有命中都对，而是以源文书语义及不按标签筛选的邻域反查：

| 源文书复核结果 | 份数 | 可支持的结论 |
|---|---:|---|
| 当次否定手术、或因身体状态暂不宜手术 | 2 | 有明确不推进/暂缓意见；不等于解剖不可切除 |
| 先处理问题再重评、或待检查明确手术方案 | 2 | 已有当次评估安排；不是重评已完成，也不是最终可切除性结论 |
| 当次肯定转外科、或具体切除计划见证 | 4 | 可追溯到选择/计划记录；仍要找更早意见，不保证是首次 |
| 疑问模板、历史回述、诊断考虑误连、其他操作对照 | 4 | 不可直接认证为当前根治切除决定 |

具体引文均保存在私有样本卡。原文查看已促成以下修正：

- 不按标签检索的邻域发现，更早文书写的是“有外科手术指征”“查看患者后示”。旧句式会漏，现已扩展并加入测试；更晚的“有手术指征”未必是首次。
- 引用影像中的“其它诊断：”还会误导段落解析，遮住其后医生明确作出的意见。现让局部医生指示优先于这一较早标题，同时保留现病史等真正历史段落的待核处理。
- 首次病程可能先有泛手术计划，首次查房才出现具体切除名，术前文书再重复确认。三份文书不自动算三个选择；后两份更明确，不代表决定直到那时才形成。
- 源文书中存在先写拟切除、后写无指征而仍引用相同影像的情况。可能是意见修正，也可能是模板沿用；现按相反意见留待核标记，不自动认定真实更新。
- 跨住院的“目前无手术指征”可位于历史叙述中，后文还继续讲后续治疗。现先分段和角色，保留回溯来源，不将每次化疗住院复制出的句子当新点。
- “次全切术”“根治（不带术字）”“切除手术”“切除”均已覆盖；先前已知4名词形漏检患者已重新检到候选文书。新版仍有零候选，患者集合与旧版不同，不能只对比零患者个数。
- 某源记录按正文时钟距后续术前文书约69小时，但正文还含晚于记录头的检验日期，系统时钟差仅数分钟，讨论日期又不同。故69小时仅是观察时钟差，**不能认证实际决策发生在术前69小时**；已分开存命名日期并标冲突，复杂内部时间矛盾保留人工核对。
