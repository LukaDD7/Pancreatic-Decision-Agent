# P2 候选 Checkpoint 十例 HTML 预览阅读指南

日期：2026-11-19

## 1. 使用性质与版本边界

本指南供医生和研究者在**开发预览、材料审核和试评**中使用。当前 HTML 是私有研究开发预览，**不是正式医生发布包、正式盲评包或临床 Reference**，不能用于真实患者管理。

预览包含候选 CP、后续候选 CP、研究审核原文和 Agent 输出。页签或折叠块只改变显示方式，不构成访问隔离；即使阅读者自觉只打开默认页，也不能据此把该文件称为正式盲评材料。

版本须按病例和材料清单分别辨认：

- **本轮新五例**：在 FHIR `import_sources` 内、返回 sources 之前，也在任何模型请求之前，已对输入执行确定性去标识化。该处理发生在候选发现和后续模型阶段之前，不是生成 HTML 后才补救性脱敏。此结论仅限定于本轮新五例。
- **旧五例**：如合并预览中保留旧版运行或旧版材料，必须保留并查看其旧版标识，例如“r19 原始 FHIR 全量重建结果 · r24 材料重投影”。不能因旧五例与新五例放在同一总目录，就写成“十例均采用新版前置去标识化流程”，也不能把旧版材料计数当作新版十例计数。
- 材料格式、渲染格式、运行轮次和去标识化阶段是不同版本维度。阅读或回收意见时，以当前病例页、`manifest` 和导出文件中的版本及 hash 为准；本指南不替代逐例版本验收。

## 2. 先理解两个核心对象

### 候选 Checkpoint 不等于已确认临床决策

候选 Checkpoint（候选 CP）是程序结合发现阶段 Agent 提案、原文定位、来源时钟、证据演化裁决和材料投影形成的**候选评价状态**。`ACCEPTED`、`RETAIN_CP` 或页面可打开，都不表示专家已经确认它是一个独立临床决策点，也不表示病历中的临床团队当时确实按页面所示方式作过选择。

候选 CP 的管理问题、`phase`、`record_functions`、候选动作、关系和裁决均应连同来源及复核状态阅读。程序核验通过主要说明结构、引文、时间方向或覆盖满足当前规则，不等于临床语义正确。临床 Reference 只能按冻结方案由独立医生评价形成，不能从候选 CP 或 Agent 输出直接取得。

### Episode 是持续管理目标的候选组织

这里的 Episode 是围绕**持续根治性切除管理目标**组织的候选轨迹，不是一次检查、一次住院、一条医嘱或一次手术的同义词。CT、MR、EUS、病理、NAT 和手术评估不因检查或文书类型不同就自动拆成不同 Episode。

同一候选 Episode 可包含多个候选 CP、证据状态和动作循环，用来阅读证据逐渐到达、管理问题变化及阶段转换。其成员和前后关系仍是程序组织或 Agent 记录的候选关系，不是已确认临床 Episode。检查前与报告后两个 CP 可由程序围绕同一检查事件连接；这种连接本身也不证明一个原始临床 Episode 已获确认。“旧 Episode 来源”只表示迁移谱系，不等于当前 Episode 归属。

## 3. 推荐阅读顺序

1. 从总目录进入一位患者，先核对病例标识和版本说明。
2. 在任务头阅读候选 CP ID、任务类型、管理目标、管理问题、评价时点、时间依据、时点角色、主要评价范围和 `scope_reason`。
3. 默认在“当时可见资料”阅读本 CP 截止时点内、已经完成相应遮蔽的来源；不要用后续 CP 的结局反推当前答案。
4. 阅读“本状态相对前一状态的新增内容”和证据演化裁决，区分新增患者证据、同轮支持、重复计划、执行和待核。
5. 需要研究审核时，再看“MASK”“前后关系”和“研究原文”。研究原文可能显示目标管理判断或其他不宜进入当前医生投影的内容。
6. “动作填写”只用于开发草稿。候选动作不是答案，填写结果也不会自动成为临床 Reference。

## 4. 三类任务类型

| 页面任务类型 | 代码 `kind` | 阅读任务与遮蔽重点 |
| --- | --- | --- |
| 检查前，页面称“证据获取前状态” | `BEFORE_ACQUISITION` | 评价即将获取证据之前的管理任务。目标检查组整份遮蔽，可见文书中的目标检查相关回述也按规则遮蔽；只依据检查前可见上下文判断下一步管理。发现阶段候选动作及理由移至“研究原文”，避免在默认任务头泄漏目标检查。 |
| 报告后再评价，页面称“新证据到达后状态” | `AFTER_EVIDENCE_ARRIVAL` | 当前检查报告作为新证据进入可见资料，任务是结合此前上下文重新评价管理路径。晚于报告可见时点的来源不进入本状态，后续管理动作仍需遮蔽；看到报告不等于看到临床团队随后实际采取的计划。 |
| 管理再评价，页面称“管理再评估状态” | `MANAGEMENT_REASSESSMENT` | 围绕管理问题或患者条件的变化再评价。目标管理判断及同一来源、同一事件或同一候选 CP 的跨文书回述按规则联合遮蔽；重复计划、转科、执行或更具体安排可只作支持，不能自动算作新的独立决策。 |

三类标签描述当前开发投影的任务形态，不是经专家确认的治疗阶段分类。旧字段名如 `pre_exam_evaluation`、`evidence_arrival_reassessment`、`management_decision` 只应在核对旧版材料时按旧版含义理解。

## 5. 目标来源、上下文来源与重复内容

### 目标来源与上下文来源

- **目标来源**：当前候选 CP 的 `target.source_ids` 所指向的原文对象。管理再评价中通常是目标管理判断所在文书；报告后再评价中是本次新证据报告；检查前任务中目标检查组仍列为目标来源，但正文和标题被整组遮蔽。
- **上下文来源**：本 CP 的 `included_sources` 中除目标来源外、按当前候选截止规则保留的其他来源。它们用于重建当时可见背景，不代表 Agent 实际使用过，也不代表临床团队实际阅读过。
- “目标”表示评价对象，“上下文”表示本投影中的呈现角色，均不是临床重要性、证据强度或正确性的排名。同一来源可在不同 CP 中承担不同角色，并随时点和 MASK 规则呈现不同内容。

### `included_sources` 与 `excluded_sources`

- `included_sources` 是进入当前候选材料投影的来源卡片，正文已经按任务类型、目标关系、候选截止时点和直接标识符规则处理。纳入不等于临床认可，也不等于来源完整覆盖了当时全部病历。
- `excluded_sources` 是未进入当前可见投影的来源及处置元数据，常见原因包括可见时钟晚于候选截止、缺少可用于当前截止判断的可见时钟，或文书创建时间晚于候选截止。排除的是**该来源在当前 CP 的可见性**，不是患者排除，不是临床上没有做该检查，也不是医院不存在该报告。
- “目标原文截止后创建，未进入当时可见资料”的警示要求阅读者不要把该目标正文回填为当时已知信息。保留的其他上下文仍须按各自时钟阅读，不能用目标文书较后的创建时间伪造当时可见性。

### 为什么会看到重复内容

重复出现有多种正常来源，不应直接当作程序重复计数：

1. “当时可见资料”和“MASK”都展示 `included_sources`，前者便于按时点阅读，后者便于核对遮蔽理由和元数据。
2. “研究原文”再次展示目标来源的研究审核副本，以便对照遮蔽前后；它不是另一份临床文书。
3. 同一来源会进入多个候选 CP，但每个 CP 的截止时点和遮蔽范围可以不同。
4. 病历本身可能保存报告副本、修订候选版本、转诊摘要或后续文书中的旧报告复述。为保留来源身份、时间和审计链，预览不按文字相似度静默去重。

文字重复不自动构成新增患者证据，也不自动产生新的独立临床决策。是否属于同轮支持、重复计划或执行，应结合证据演化裁决和原文来源判断；报告版本关系没有来源证明时，不能仅凭相似文字认定初稿、复核稿或最终稿。

## 6. 评价时点代理与“24小时”折叠

### 评价时点是资料检索代理

“评价时点”及其 `time_basis`、`role` 是当前候选状态用于组织资料和限制可见性的**代理时点**。来源卡片中的检索时钟以及 `exam`、`report`、`verified` 等时钟也各有来源含义。它们不等于医生实际阅读报告的时刻、临床团队作出选择的时刻或措施执行时刻。

时间精度不足、同日粗时间或来源创建时间与正文记录时间不一致时，不应自行补出精确顺序。一个来源在代理时点内可见，只说明当前程序投影将它保留，不证明临床团队当时实际获得或使用该证据。

### “24小时”只是自然日折叠标签

“当时可见资料”把全部 `included_sources` 按来源检索时钟的**自然日**分组成折叠块，界面标作“YYYY-MM-DD（24小时）”。这不是从评价时点向前滚动 24 小时的纳入窗口，也不会新增、删除或截断来源。

当前 CP 评价日默认展开，其他日期按需展开；若评价日没有对应分组，则默认展开最新的已知日期分组，时间未知者单列。折叠状态与证据强弱无关。目标来源缺少可用于分组的时钟时，界面可仅为显示而借用评价日，这不等于补证了来源时间。

## 7. MASK、研究原文与去标识化不是同一件事

### MASK

MASK 是为当前候选任务控制目标信息和时点信息可见范围的程序投影，包括目标管理判断、检查前目标检查组、相关跨文书回述及晚于评价时点的显式日期时间等。局部遮蔽和整份来源遮蔽都可能出现。

“MASK”页显示遮蔽理由、局部区间数量、整份来源数量、元数据和遮蔽后全文。新版材料的 `start/end` 坐标与展示正文都基于 Episode 重建前已去标识化的来源文本；旧版材料的坐标基准须按各自 `span_offset_basis` 阅读，不能跨版本套用。当前“跨文书复核：未确认”等状态必须如实阅读；启发式遮蔽不等于已经证明无泄漏，更不等于正式盲评方案已经冻结或通过验收。

### 研究原文

“研究原文”是**当前 CP 目标来源**供研究者核对的目标/时点遮蔽前副本，仍已做直接标识符去标识化；它不是全患者未遮蔽病历。该页还可展示完整 Agent 裁决理由、完整引文，以及检查前任务被移出默认页的候选动作和理由。

研究原文可能直接暴露目标管理判断、目标检查或其他超出当前医生投影的信息。它用于研究审核，不能作为医生正式盲评材料，也不能用阅读后的信息回填当前 CP 的当时可见状态。

### 直接标识符去标识化

直接标识符去标识化与 MASK 的目的不同：前者处理姓名、联系方式、地址、就诊或证件标识等，后者处理当前任务不应可见的临床内容和时间。保留年龄、性别及序贯评价所需精确日期，90 岁及以上年龄可归并为 `≥90岁`。当前保守规则不声称满足 HIPAA Safe Harbor，也不等于所有间接标识风险均已消除。预览仍须按私有研究材料管理。

## 8. 候选动作与证据演化裁决

### 候选动作不是答案

“Agent候选动作”来自发现或复核阶段的模型提案及其结构化理由，不是推荐答案、专家意见、Acceptable Mode Set 或临床 Reference。`action_space` 中的 `ADVANCE`、`HOLD_FOR_EVIDENCE`、`REDIRECT` 和动作计划 schema 也只是开发表单结构，不表示这些模式在当前患者身上均可接受，更不限制医生正式评价时应接受的集合。

“动作填写”不预填医生答案。开发试评时应以当前 CP 的当时可见资料为依据，可以提出不同于 Agent 候选动作的计划；不能把照抄候选动作当作独立评价。保存或导出的内容仍是 `draft_not_clinical_reference`。

### 证据演化裁决

证据演化裁决是病例级 Agent 对候选管理 CP 与最近保留比较状态之间关系的研究判断，程序再核验比较对象、引文边界、来源、时间方向和覆盖。常见阅读方式如下：

- `RETAIN_CP + FIRST_VISIBLE`：当前候选被作为首见锚点保留，不等于专家确认首次临床决策。
- `RETAIN_CP + NEW_EVIDENCE_ROUND`：Agent 主张存在严格晚于比较状态、且不晚于当前 CP 的新增患者证据，并提交原始来源逐字连续引文。当前或其他 CP 的管理动作句不能冒充新增患者证据。
- `SUPPORT_ONLY + SAME_ROUND_SUPPORT / REPEATED_PLAN / EXECUTION`：当前记录作为同轮支持、重复计划或执行归入承接 CP，原文和遮蔽区间保留，但不作为新的独立证据轮次。
- `REVIEW_REQUIRED + UNCERTAIN`：时间、并列状态或证据关系仍待核，不能猜测成保留或归并。

“本 CP 的证据演化裁决”与“归并到本 CP 的支持记录”不是同一层级。只有确认 `NEW_EVIDENCE_ROUND` 时，页面才把所附引文标作 Agent 指定的新增患者证据；其他裁决所附依据不必然是新证据。默认页只展示裁决结构和在本 CP 遮蔽后仍可见的引文，完整自由文本理由及研究引文见“研究原文”。

程序接受裁决不等于引文在临床上必然是患者证据，也不等于证据关系、Episode 或 CP 已获专家确认。

## 9. 主要评价、非主要评价与导出

### 主评价与非主要评价

- **本版主要评价**：`primary_evaluation_eligible=true`，范围为术前路径推进或 NAT 再评价，即 `PRIMARY_TASK_PREOPERATIVE_OR_NAT_REASSESSMENT`。
- **非本版主要评价**：`primary_evaluation_eligible=false`，保留用于完整 P2 轨迹和手术截止审核，例如 `NON_PRIMARY_P2_POSTOPERATIVE_TRAJECTORY`；不进入术前路径推进／NAT 再评价主评分。

“非主要”不是临床上不重要、资料质量差或候选 CP 无效，也不表示可以删除。应同时阅读 `evaluation_scope` 和 `evaluation_scope_reason`。手术边界未知或被标为待核时，不能仅凭页面落入主要评价一侧就认定边界已获临床确认。

### `non_primary_p2_review_responses` 导出

每个 CP 的开发草稿包含 Mode、一个或多个具体动作、理由及可选待补证据。具体动作中的 `action_type`、`target`、`timing` 和总理由为表单必填项，`conditions`、`evidence_to_obtain` 可选。

1. 在当前 CP 点击“保存本机草稿”。草稿保存在该浏览器的本机存储中，不会自动上传服务器。
2. 完成当前患者需要回收的 CP 后，点击“导出动作计划草稿”，再点击生成的 `candidate-action-drafts.json` 下载链接。当前未保存但已填写的表单也须通过必填校验才能导出。
3. 导出按当前患者汇总本机已保存草稿及当前有效表单，不是一次导出全部十例。逐例导出时应避免同名文件混淆，并保留病例及材料版本对应关系。
4. JSON 中 `responses` 收纳主要评价草稿，`non_primary_p2_review_responses` 单独收纳非主要评价草稿。回收和统计时不得把数组合并后全部计入术前／NAT 主评分。
5. 导出同时携带 `case_id`、`checkpoint_id`、`material_manifest_sha256`、表单及渲染格式等绑定信息。它仍是开发动作计划草稿，不是正式医生响应或临床 Reference。

## 10. 患者内导航与前后关系

- 顶部“按任务类型筛选”和“当前 Checkpoint”用于在当前患者内切换，一次只显示一个候选 CP。
- “本患者上一 CP／下一 CP”按全患者 `display_order` 浏览，只在当前患者内移动，不把不同患者串联。换患者应回到总目录重新进入。
- “前后关系”页按 `episode_navigation` 显示同一候选 Episode 内的相邻状态及已记录关系，其顺序和范围可以不同于全患者导航。
- 两种导航都只是显示顺序，不是已确认的临床决策、治疗或时间关系。未记录直接关系不等于临床上无关系；`same_event`、`same_management_process`、`evidence_used` 等标签也必须结合其来源、方向和引文审核。
- 后续 CP 已嵌入开发 HTML。阅读当前 CP 时不应借“下一 CP”提前获取结局；这种自我限制仍不能把开发预览变成正式盲评包。

## 11. 审核时至少记录的问题

研究审核或开发试评发现问题时，应记录患者、`checkpoint_id`、材料版本和具体来源 ID，并区分：

- 候选 CP 是否被误当作已确认临床决策；
- 任务类型、持续管理目标 Episode 或关系是否需要复核；
- 来源是当前投影纳入／排除问题，还是原始交付中未找到、时间不明或版本关系未证实；
- 评价时点代理是否被误读为实际临床阅读或选择时刻；
- MASK 是否不足或过度，研究原文是否被误用于当前时点作答；
- 重复文字是否被误当成新增证据；
- Agent 候选动作或证据演化裁决是否被误当成专家答案；
- 主评价与 `non_primary_p2_review_responses` 是否被错误合并计分。

局部问题应作用于具体 CP、来源、引文或字段，不自动升级为整例患者排除，也不以较后结局改写较早时点资料。
