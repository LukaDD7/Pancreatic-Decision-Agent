# P2 十例候选 Episode／Checkpoint 重建报告

日期：2026-11-19  
性质：开发集真实运行与材料技术验收，不是临床性能评价或正式医生盲评结果。

## 1. 本轮目标与方案边界

本轮依据《PDAC根治性切除路径的证据感知序贯决策支持研究》v1.0，并参照 v0.3 的 Episode／Checkpoint 和材料治理原则，检查能否把杂乱病历组织为可逐时点审核的管理状态：

> 状态 → 行动 → 新证据 → 状态更新 → 下一次行动。

方案将本版主要任务限定为**术前根治性路径推进与 NAT 后再评估**。术中切除／重建、术后治疗及急性并发症处理不进入本版主要评分，但可保留在完整 P2 轨迹中，供审核手术截止、任务适用性和资料组织。网页中的“非主要评价”不是删除或临床上不重要。

本轮交付回答的是候选重建和材料工程问题，不回答 Agent 的临床策略是否优于基线。没有生成未实施检查的虚构结果，没有把历史回放称为 Agent 曾控制真实治疗，也没有形成专家 Reference。

## 2. 本轮核心改造

### 2.1 检查动作重新进入候选过程

此前把 CT、MR 等检查主要作为 evidence，容易漏掉“当时决定获取该项证据”这一管理动作。本轮围绕同一检查事件组织两个候选状态：

1. **证据获取前状态**：还原决定检查前的可见资料，遮蔽目标检查组及结果；
2. **新证据到达后状态**：报告成为新证据，评价管理路径是否需要维持或调整。

检查前和报告后不是两个无关 Episode。CT、MR、EUS、病理、NAT 和手术评估均围绕同一持续根治性切除管理目标组织。审核时间不可得时使用报告时间作为可见性代理；代理时点不等于医生实际阅读或选择时刻。

### 2.2 管理文书不再凭出现即成为独立 CP

发现阶段从原始文书提议可输出动作的管理记录，程序核验来源、逐字 span、时间和结构。全局裁决再比较候选管理 CP 与程序确定的最近保留状态：

- `FIRST_VISIBLE`：首个可见管理锚点；
- `NEW_EVIDENCE_ROUND`：存在严格晚于比较状态、且不晚于当前状态的新增患者证据；
- `SUPPORT_ONLY`：同轮支持、重复计划或执行，归并到承接 CP；
- `REVIEW_REQUIRED`：同刻顺序、身份或证据时间关系不确定，保留待核。

新文书、新时间戳或更具体的安排不自动构成新证据。比较对象由程序提供，区间原文通过索引供 Agent 按需读取，避免强制阅读全部区间资料。

### 2.3 每个 CP 分别控制资料可见性

材料保留来源 ID、原文、时钟、引文及 hash，按当前任务形成 KEEP／MASK／REVIEW 投影。目标管理安排、目标检查、跨文书回述、决策后执行或结局按规则遮蔽。同一来源可在不同 CP 中有不同可见范围，不能共享一套全程可见原文。

HTML 显示任务类型、当前原始文书类型、评价时点及依据、目标／上下文来源、候选动作、证据演化裁决和前后关系。可见资料按自然日折叠；“24小时”只是显示标签，不是滚动纳入窗口。

## 3. 真实运行范围与版本

SCALE-01～05 均使用独立的新 output/cache，执行完整 Discovery 和全局证据演化裁决，不使用冻结 replay 冒充新结果。早期网络失败轮次不进入交付；只有 `COMPLETE`、`unfinished=[]`、`failure=null` 且全局裁决完成的病例才进入汇总。

## 4. 前置去标识化与运行安全

新五例在 `import_sources()` 解码并核验原始 FHIR 后、返回 sources 前执行确定性去标识化，因此发生在 Discovery 和后续任何模型请求之前，不是生成 HTML 后补救。无损影像 merge 入口显式使用 `deidentify=False`，后续研究重建入口才执行脱敏。

规则处理结构化 Patient 值、明确标签值及跨文书已知同值；保留年龄、性别和序贯评价所需精确日期，90 岁及以上年龄归并。`source_id` 保持稳定；`source_sha256` 对应当前脱敏正文，`original_source_sha256` 保留脱敏前正文 hash。冻结 span 必须匹配当前正文，旧 raw offset 不得直接切到脱敏正文。

这是一套保守的直接标识符处理，**不宣称满足 HIPAA Safe Harbor**，也不能消除全部间接识别风险。对已完成的最终轮请求，以原始 Patient／标签提取的姓名、地址、电话和就诊标识种子扫描，均要求 0 命中；逐例回执不记录或展示真实标识符。

对抗审计另发现旧会话恢复、纯数字 Patient ID 和无标签手机号形状数值的边界问题，已补充防护与反例：缺脱敏来源标记的旧 session 拒绝恢复；纯数字 Patient ID 仅在原文明确作为就诊标识出现时跨文书替换；明确临床数值语境的手机号形状数字不当作电话删除。修复前后五例脱敏正文逐字段比较均为 0 差异。

非本轮路径仍需注意：如果脱敏后的 bundle 再次进入影像 merge 并改变正文，original hash 语义需单独修正；本轮实际输入路径不是“先脱敏、再 merge”。

## 6. 与正式方案的差距

当前 HTML 是研究审核和开发试评材料，包含研究原文、后续 CP 和 Agent 输出，不具备正式盲法隔离。动作表单也不是 v1.0 正式 Q1–Q5 CRF，尚未实现五人独立评价、4/5 共识、关键动作约束、严重度规则、逐时点隔离及分配接触史管理。

因此本轮不能给出：

- Agent 或基线的临床可接受率、错误率或 Major 风险；
- 主复合终点、序贯更新收益或 RSI 改进效果；
- 独立临床决策点的准确数、召回率或专家共识；
- 正式研究样本量、可推广性或临床安全性结论。

候选 CP 中的 `REVIEW_REQUIRED`、时间代理、来源缺口和材料未决项必须保留，不得为了形成评分样本而静默删除。

## 7. 建议下一步

1. **医生先做重建审核**：按快速阅读说明检查候选点是否成立、同源／同轮归并是否合理、检查前后双状态是否准确、手术截止及主／非主要范围是否恰当。
2. **独立核验遗漏和错误新增**：不仅审已保留 CP，也抽查零发现、被排除单位和时间不明来源，分别记录错拆、错并、遗漏和跨时点污染。
3. **形成正式许可包**：移除研究原文、后续 CP、Agent 输出和隐藏数据，完成独立语义审核与盲态线索定位测试。
4. **冻结评价接口**：按 v1.0 实现 Q1–Q5、逐 Mode 和关键动作计划、严重度、5 人／4 票规则及逐时点接触控制，再进入试评。
5. **修复非本轮 merge 路径**：为脱敏后再次 merge 的 original hash 增加专门回归，避免未来复用时误传正文版本。

本轮最值得医生优先反馈的不是候选动作是否“像答案”，而是：**这个状态是否值得独立评价、当时可见资料是否足够且合法、与前一状态相比是否确有新增患者证据。**
