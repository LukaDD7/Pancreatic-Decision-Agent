# P2 候选 CP 与检查双节点重建实施计划

日期：2026-11-15  
状态：已批准实施  
基线：SCALE-01 `relations-r6-resumed-01` 与 `relations-r6-materials-v3`，均只读保留

## 目标与边界

把当前“每个 candidate span 机械生成一个 Checkpoint”的流程改为：原文候选片段先经动作可评价性、主任务范围、同源合并和时点遮蔽检查，再成为候选 CP。检查选择是管理动作，检查结果是新证据；一次检查组织为检查前评价和报告后再评价两个纵向时点，而不是把报告排除在 CP 外。

本轮主要任务仍为术前根治性切除路径推进及 NAT 后再评估。重复、执行、通用模板和入院意图保留为支持记录；术中、术后常规管理及急性并发症不混入主要评分 CP。没有医生 Reference 时不声称临床准确性，不发布医生包。

## 对象与术语

- `candidate_span`：发现阶段 LLM 提议且程序定位的连续原文区间，不是 CP。
- `candidate_checkpoint`：可作答任务的候选对象，包含任务头、评价时点、动作空间、来源成员和遮蔽范围。
- `diagnostic_event`：程序按同次检查候选报告组组织的检查事件，保留 exam/report/verified 三类时钟，不冒充已确认临床决策。
- `pre_exam_evaluation`：检查前回溯性评价时点。没有医嘱原文时不得声称记录了临床团队的选择过程。
- `evidence_arrival_reassessment`：报告可见后的再评价时点，允许维持原策略。
- Episode 只连接合法候选 CP；支持记录和证据对象作为上下文，不因存在原文而独立成 CP。

## 实施规则

### 1. 信息可见性

有有效 `report_time` 时以其作为报告可见性代理；缺失时用 `verified_time` 并记录降级；两者均缺失则为 `visibility_unknown`，不得用 exam_time 冒充报告可见。始终保留三种原始时钟和所选依据，不声称 report_time 等于医生实际阅读时刻。

### 2. 检查双节点

检查前 CP 以 exam_time 为时间引导，任务询问当时下一步管理及检查选择；目标检查组、检查名称、所见、结论、建议及跨文书目标动作回述必须遮蔽。没有精确选择时刻时标为“检查前评价”，不伪造分钟级临床决策时刻。

报告后 CP 以报告可见性代理为信息截止，完整呈现当前报告作为新增证据，遮蔽后续选择、执行、回述和结局。`evidence_arrival` 与 `evidence_used` 分开，后者不得由时间或内容相似自动推断。

同一管理 source 的多个组合／原子／重复 span 合并为一个候选 CP；检查前与报告后是不同任务和不同时点，不属于同刻重复 CP。医生评审仍须按时间顺序、不可回改。

### 3. 动作门槛和范围

候选 CP 必须有唯一管理问题、评价时点、可输出的 Mode（ADVANCE/HOLD_FOR_EVIDENCE/REDIRECT）及具体动作计划。新证据支持维持原策略也是有效结果。

旧 38 个候选逐项迁移为：保留、合并、支持记录、主任务外或待核；不得静默删除。离线重投影先复用冻结 discovery，避免以模型重跑掩盖程序规则问题。

### 4. 演示增量

新版私有 HTML 对每个 CP 展示：任务类型、评价问题、评价时点及依据、当时可见原文、Agent 提议动作／记录分类、联合 MASK 范围与理由、前后 CP 关系、检查 exam/report/verified 时钟及新旧迁移去向。检查前页面不得显示目标检查名称或结果；报告后页面须显示完整当前报告。

## 工程步骤

1. 提交本计划，登记基线与未提交工作区边界。
2. 并行实现检查事件／可见性、候选 CP 重投影／联合遮蔽、新版展示与测试。
3. 运行 Harness 标准测试及 P1 guard；新增反例覆盖 MR/CT 双节点、报告时间优先、同源合并、入院句排除、跨文书泄漏和腹腔镜部署／模板对照。
4. 由独立 subagent 假定实现错误并审计，只报告错误原因和证据；主线程修复后复验。
5. 生成 SCALE-01 离线新版 demo 和 38 项迁移对照，核对无目标泄漏后，再以新 contract、授权、缓存和输出目录执行真实 discovery-only／病例组织小跑。
6. 用真实结果生成新版 demo；不覆盖旧运行。最终只提交本任务代码、测试、方案和非敏感回执，私有病历与模型原始输出继续留在 private。

## 验收

- SCALE-01 出现 MR 检查前、MR 报告后和增强 CT 检查前候选；CT 报告后与手术时间关系不明时明确待核。
- 检查前 CP 有时间和管理问题提示，但看不到目标检查类型、计划或结果。
- 报告后 CP 可见完整报告，看不到后续管理答案。
- 入院意图不独立成 CP；术前讨论多 span 不互相泄漏。
- 每个正式候选 CP 可输出具体动作计划；无动作字段为技术失败。
- 迁移表、关系、时钟、材料 hash 和表单版本可审计；测试通过不等于临床正确性已验证。

## 全病例导航与候选 CP 组织补充

- 全病例“上一节点／下一节点”按 `display_order` 导航，不依赖 Episode；Episode 内顺序另行保留，二者都不自动成为临床时序真值。
- 新增候选 CP 关系记录阶段，端点使用 `checkpoint_id`，不能沿用旧 `event_id + span` 接口。Agent 仅记录有原文依据的关系，程序按 `checkpoint_ids` 组装 Episode，未连接节点保留。
- 检查前→报告后是程序诊断事件边；`evidence_used` 只能由具体原文支持，不能从时间或内容相似推断。
- 使用独立 runner 读取冻结 discovery，运行合同绑定 discovery、来源、配置与代码 hash，并使用新的授权、缓存和输出目录。
- 新版材料直接消费候选 CP 关系和 Episode，不再从旧 EV 关系推测新 CP 归属；新材料包含输入 hash，旧 demo 不覆盖。

## 首轮真实审计后的边界收紧

- CP 关系的两端原文只保留在独立关系运行文件，不复制进各时点材料；页面保留关系方向、类型、说明及引文数量，避免关系审计反过来泄漏当前或未来答案。
- 新 `same_event` 关系与旧 EV 关系都参与跨文书联合遮蔽；报告后节点也遮蔽非目标文书中的同刻管理动作，目标报告本身保持完整。
- 医生投影中的明确未来日期时间及晚于评价时点的来源时钟须遮蔽；研究审核原文独立保留原始值。
- 只有 case、格式、候选投影 hash 和 CP 全覆盖均匹配的组织结果才能进入材料。不同共同管理目标不得经传递闭包合并。
- 非空 CP 运行必须实际列出全部 CP（含分页）后才能判为组织阶段 COMPLETE；合同还需覆盖外部执行模块，summary 绑定输出文件与 session hash。
- `evidence_used` 需有目标管理原文中的实际证据引用或使用连接，不接受“证据到达＋孤立管理动作”；重复引文须用偏移消歧。

## 第二轮批准口径：广泛召回、Discovery 筛选与真实闭环

- 程序继续广泛建立检查证据索引，不用 PICC、CT 等关键词作临床硬过滤。Discovery LLM 必须分别审核检查安排与报告后再评价候选，记录 `yes/no/uncertain`、具体动作和理由；检查候选不得绕过 Discovery 直接成为 CP。
- PICC 等并非“没有临床动作”，而是通常不属于 PDAC 根治路径的独立评分动作，由 Discovery 明确排除并保留理由。
- 检查安排 CP 以具体检查动作为任务中心；目标报告全部临床内容遮蔽，保留评价时点及“此时应采取什么管理动作”的引导。检查时间可靠时用检查时间，明确不可用时以报告可见时间降级锚定并记录 `time_basis`。
- 同一检查来源不得同时形成检查前和报告后两个评分 CP；优先保留可作答的检查安排 CP。报告后确有新管理决策时，由后续真实管理文书承载，避免同源互相泄漏。第 34 行“双时点”及第 44、58 行的旧展示／验收口径以此条为准。
- 所有保留 CP 必须有 Discovery 提出的 `action_type` 与 `target`；它们不是预填医生答案，也不是 Reference。
- 新一轮不复用冻结 Discovery、候选 CP 或 Episode 结果；使用新合同、授权、缓存及输出目录执行真实模型闭环。旧结果只读用于 diff，最多三轮有实际改进的闭环，不用旧快照冒充新模型效果。
- 首屏直接显示评价问题、Agent 候选动作和全部当时可见资料；“全病例”导航改称“本患者”，避免误解为跨开发集患者。

## 第一轮对抗审计后的程序收紧

- `performed_test_report` 缺少任一类 Discovery 审核时，病例运行不得标记 COMPLETE；organization-only 交接必须保留诊断审核与修订记录。
- 同一来源的管理 CP 与诊断 CP 也只能保留一个：检查安排优先；报告后候选与既有管理 CP 同源时并入该管理 CP。不得仅凭相同检查名称合并不同时间的检查。
- 报告后节点的非目标来源同时使用 Discovery span 与动作语句遮蔽；检查前节点对其他检查报告中的目标检查回述也执行遮蔽。
- `run_case` 授权 hash 覆盖实际来源导入、单位构建与模型访问外部模块，避免外部代码变化后合同 hash 不变。
- 上述每一项均有合成反例回归；测试通过仅说明程序边界，不等于临床正确性或医生 Reference 已建立。

## 第一轮全新真实运行后的提示纠正

- SCALE-01 新运行完成 37 个阅读单位、46 个管理候选 span 和 5 个检查单位的双审；未复用旧 Discovery。PICC 由 Agent 明确排除，增强 CT 进入检查安排候选。
- MR 被误置 `uncertain` 的原因是 Agent 把“未记载医嘱、指征或部署句”当成不能审核检查动作，这与动作中心规则不符。检查相关且属于根治路径补证动作即可接受，选择过程不明只作为回溯性评价限制。
- 报告后审核也不要求报告原文已经写出管理决定；Agent 可以提出基于新证据的待评审动作，但不得冒充病历记载的临床团队决策。
- 第二轮使用新合同、新缓存和新输出重跑 Discovery；第一轮目录与 demo 只读保留，用于证明 MR／CT 候选及 CP 数量的真实变化。
