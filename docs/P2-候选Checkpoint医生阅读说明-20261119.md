# 候选 Checkpoint HTML：医生阅读说明

## 这份材料是什么

这是 PDAC 根治性切除路径的 **P2 候选重建开发预览**，供医生和研究者检查：候选时点是否合理、资料是否足以作答、遮蔽是否恰当、相邻时点是否确有新增证据。

它不是正式盲评包，不是专家确认的临床决策点或 Reference，也不能用于患者管理。当前页面含研究原文、后续 CP 和 Agent 输出，页签不能实现正式盲法隔离；请勿公开转发。

- SCALE-01～05：本轮在 Episode 重建前确定性去标识化后，全新真实 Discovery 与全局证据演化裁决。
- SCALE-06～10：保留既有 r19 真实运行、r24 材料重投影版本，用于合并预览；不能称为本轮前置脱敏重跑。

## 建议怎么读

1. 从总目录选择一位患者，先读页面顶部的版本和候选 CP 说明。
2. 看任务头：当前管理问题、任务类型、评价时点、原始文书类型及是否属于本版主要评价。
3. 在“当时可见资料”中，只依据该时点允许出现的信息思考：此时应如何管理？
4. 看“本状态相对前一状态的新增内容”及证据演化裁决，判断本 CP 是否值得单独评价。
5. 需要审核时再打开 MASK、前后关系和研究原文。研究原文可能暴露当前实际安排，不能把它当作当前时点的作答依据。
6. “动作填写”仅用于开发试评和检查任务可理解性；不会自动形成临床 Reference。

## 三类 CP

| 页面名称 | 含义 | 阅读重点 |
| --- | --- | --- |
| 证据获取前状态 | 还原决定实施 CT、MR、EUS、腹腔镜等取证措施之前的状态 | 目标检查及结果应遮蔽；根据此前信息决定下一步管理 |
| 新证据到达后状态 | 检查报告已经到达后的再评价状态 | 本次报告可见，但其后的实际计划、执行与结局仍应遮蔽 |
| 管理再评估状态 | 围绕管理问题或患者条件变化的候选状态 | 核对是否真有新增患者证据，而非重复计划、同轮支持或执行记录 |

CP 是程序与 Agent 提出的**候选评价单位**，不等于已确认临床决策。检查前与报告后可以是同一检查事件引出的两个状态；CT、MR、病理、NAT 和手术评估仍围绕同一持续根治性切除管理目标，不按检查类型拆成不同 Episode。

## 来源和界面术语

- **目标来源**：当前 CP 所评价或遮蔽的对象。检查前任务中，目标检查组整份遮蔽；报告后任务中，新报告是目标来源并可见。
- **上下文来源**：当前评价时点内保留的其他资料。纳入不等于临床团队当时实际读过。
- **评价时点**：用于检索和限制资料可见性的代理时点，不是医生实际阅读报告或作出决定的精确时刻。
- **自然日折叠块**：按来源时钟分组显示，界面所称“24小时”不是滚动纳入窗口，不增加或删除资料。
- **MASK**：针对当前任务遮蔽目标安排、目标检查、相关回述或晚于时点的信息，不表示原始病历有误。
- **研究原文**：当前 CP 目标来源的研究审核副本，可能含目标动作；不是全患者病历，也不是当前时点的许可作答资料。
- **候选动作**：Discovery Agent 提出的可能动作及理由，不是专家答案，也不要求医生照选。
- **主评价**：术前路径推进或 NAT 后再评价。**非主要评价**保留完整 P2 轨迹和手术截止供审核，不进入本版术前／NAT 主评分。
- **本患者上一／下一 CP**：全患者显示顺序。**前后关系**中的相邻状态：同一候选 Episode 的过程关系；两者可能不同，均不是已确认临床因果。

## 如何看证据演化

- `RETAIN_CP + FIRST_VISIBLE`：首个可见管理锚点，不证明此前没有临床决策。
- `RETAIN_CP + NEW_EVIDENCE_ROUND`：Agent 主张比较状态之后、当前状态之前出现了新增患者证据；应核对原始来源和引文。
- `SUPPORT_ONLY`：同轮支持、重复计划或执行记录，归入承接 CP，不另作为独立证据轮次。
- `REVIEW_REQUIRED + UNCERTAIN`：时间、顺序或证据关系仍待核，不能强行保留或归并。

新增一条文书、一个新时间戳或更具体的手术安排，不自动等于新增患者证据。新增证据也不必导致 Mode 改变，它同样可以支持维持原策略。

## 本版评价边界

研究方案的主要任务为术前根治性路径推进与 NAT 后再评估，Mode 为：

- `ADVANCE`：推进当前根治性手术路径，不等于立即开刀；
- `HOLD_FOR_EVIDENCE`：保留路径，但须先补充会改变决策的关键证据；
- `REDIRECT`：当前转入明确替代管理方向，不等于永久失去手术机会。

减黄、营养和体能优化不自动等于 HOLD。当前 HTML 的开发动作表单**不是方案正式 Q1–Q5 CRF**，也没有实现正式五人独立盲评、4/5 共识、逐时点隔离和分配管理。正式评价前仍须冻结任务、动作字典、CRF、盲法和回收规则。

## 去标识化边界

本轮新五例在任何模型请求前处理姓名、明确标识的地址／联系方式／就诊或证件标识，并对跨文书已知同值进行规则替换；保留年龄、性别和序贯评价所需精确日期，90 岁及以上年龄归并。该流程是保守的直接标识符处理，**不宣称满足 HIPAA Safe Harbor**，也不能排除所有间接识别风险。

如需记录问题，请写明患者编号、完整 CP ID、来源 ID和具体页签，并区分：候选点选择、来源纳入／排除、时间可见性、MASK、证据演化及表单理解问题。详细技术术语见同目录《阅读指南.md》。
