## 2. CE-REAL-013：独立病例清单、调用结算及分母

新运行在创建 provider Client 前冻结 `batch-execution-inventory.json`，记录完整 preflight 病例及其状态、授权子集、manifest/授权 hash、继承台账前缀 hash 和数量。有效授权文件标明所需清单版本；缺失清单时不得静默退回历史兼容路径。

replay 先独立核对下列内容，再逐例核验运行链和重建链：

1. 进度行与冻结病例清单逐项一致，无遗漏、重复或额外病例。
2. 台账每个 provider 调用计划均有对应结算；未结算调用不产生“完整 replay 通过”。失败响应仍允许作为已结算失败进入核验。
3. 调用病例与实际产物目录均被进度表覆盖，并属于授权范围；有调用的病例必须有运行身份与 hash，不能标成未尝试。
4. 继承台账前缀保持原样，累计预算不重置。未结算的继承台账须先查明及结算，不能仅启动新请求来抹去未结算状态。
5. 子集外病例也逐项保存进度事件，修复末尾跳过病例未写入最终进度的问题。

汇总增加 `case_inventory` 与 `verified_case_count`。其中分开记录冻结病例数、授权病例数、含调用记录的尝试病例数、进度结果数及子集外数量；保留旧 `fixed_case_count` 字段，但不能单独将其解释为运行成功数。

历史批次没有追补冻结清单。兼容核验仍检查授权、台账结算与产物覆盖，`frozen_case_count=null`，范围明确为 `LEGACY_AUTHORIZATION_LEDGER_AND_ARTIFACTS_ONLY`；不从进度表补造固定总体分母。`replay_batch(..., persist=False)` 支持只读核验；若源码已变化，还须显式说明 `verify_implementation=False` 的历史核验边界。旧不完整批次可能被新完整性检查拒绝，不能为维持旧 PASS 而绕过核验。

正式测试覆盖无旧回执时的空表、丢行、重复病例、已调用病例冒充未尝试、无运行证据、删除清单、未结算调用、合法子集、末尾未尝试项、已结算台账的新目录续跑、授权篡改和既存回执不变保护。
