# P2 自动候选与证据演化：algorithm contract v0.1

日期：2026-10-24。状态：开发原型；不是临床验证、DecisionEvent gold 或 Clinical Reference。

同日修订v0.1.1：事后定位比较发现“限期手术”（无“行”字）及“胰体癌根治术”（无“手术/切除”字样）两类明确计划表达漏过候选词表，补通用表达及正反例回归。两原则、FHIR映射、样本成员和语义输出契约不变。v0.1源码、运行及对照保留；不把旧36点强制加入模型结果，不称独立验证。

## 目标与两条原则

输入按患者组织的原始EHR，自动产生有原文依据的候选管理判断和所在管理过程：

1. 判断是否围绕胰腺肿瘤根治性切除路径管理，包含推进、暂缓、不推进、补证据及服务于路径的支持处理。
2. 判断本轮相对于此前管理状态是否有决策相关证据演化。相同行动也可能是新一轮；新报告本身不自动成为新判断。首见判断作为初始参照单列，不能伪造此前决策。

程序不预设医院、病例、文书编号或已知CP。不得读取既有Decision Graph、relation proposal、A/B/C gold、P1标签、结局分析字段或Clinical Reference作为输入。固定10例清单只提供患者身份和抽样成员，不提供旧候选点。

## FHIR的职责

采用FHIR R4 4.0.1，与既有本地适配保持一致。

|原始内容|FHIR资源|研究含义|
|---|---|---|
|临床文书|DocumentReference，附件保存原文|原始记载，不自动是DecisionEvent|
|独立影像报告所见/结论|DiagnosticReport，effective为检查时间；issued仅有原始发布时间才填|证据事件，不能由检查完成补造医嘱|
|原始检验项目/结果|Observation，原始结果保留限定词和单位|按采样/报告时间分别保存，不把报告时间当采样时间|
|原始病理文字、隔离资料|本版保留为DocumentReference并标注来源类别|隔离资料不升级为干净检验事实|
|研究DecisionEvent和候选episode|Basic + 明确的研究扩展 + Provenance|AI产生的研究注释，不伪装医院医嘱、ClinicalImpression或标准原生DecisionEvent|
|实际订单（若未来交付）|ServiceRequest；实际完成用相应Procedure/DiagnosticReport|只有真实订单来源才能直接生成医嘱，不能从结果反推订单|

DecisionEvent不是FHIR原生资源。研究episode也不自动等于行政含义的EpisodeOfCare。使用Basic不替代已有标准资源；这里只承载与源临床数据不同的研究注释。扩展使用开发域名，尚未发布正式Implementation Guide、术语集、搜索参数或FHIRPath验证。

## 输入与来源分类

输入：患者`patient_source_bundle.json`的原始来源白名单，配置`config/p2_auto_checkpoint_v01.json`。

当前交付影像不是一批标题叫“MRI报告”的文书，而是`imaging_all`中`exam_method=胰腺MR平扫+增强`等记录，加`original_findings`、`original_impression`。来源位置决定报告类型；病程里出现MRI仍是二手引用。文书类型沿用原始`文书名称`，再按显式配置归为病程/入院/术前/术中/支持表单等。未知类型仍执行动作+主题的候选兜底并留审计；护理表单保留作背景，不作为本版主要选择锚点。

每份来源保存患者归属、原文、hash、来源键、类型和原始时间。登记全部来源不等于保证全部来源都已正确分类或完整交付。缺失的栏目、未命中的文字、源解析失败分别留记录。

实际执行先生成来源FHIR Bundle，再从FHIR读回同一份原文/时间表，核对每条source_id和原文hash，候选提取使用读回的来源。也可用`--fhir-bundle`直接输入受支持的单患者R4 Bundle；该入口忽略研究Basic注释，只读源DocumentReference/DiagnosticReport/Observation。更多医院资源类型或机构Profile需要扩展适配器，不能静默略过未知临床资源。当前扩展保留原始表格文字，不要求预先完成LOINC/SNOMED映射。

## 可执行流程

### A. 规则提出候选

检查主题词覆盖MRI/MRCP、CT/CTA、PET、EUS/取材、胆汁引流、系统治疗、手术/取消/暂缓和患者条件支持。词表参考临床路径任务及交付文字表达，用于检索，不作为指南正确性规则。

在临床文书中寻找主题词和行动/判断表达共现，例如“拟完善”“予以/予”“遂行”“继续”“取消”“评估/判断/考虑可切除或不可切除”。不能只找执行动作而漏掉可切除性判断。逐句记录候选和上下文原文坐标。

独立报告登记证据事件；没有医嘱/选择表达时不自动生成一次“选择做该检查”。历史已做检查保留为待核选择线索，不能因为检查已完成而全部归为背景。通用鉴别诊断或风险模板由下一步排除，不能由关键词直接当已实施。

同检查不同原报告版本按检查号/方法/时间分组，版本仍保存，不择最新或最大值当真。病程对同一检查的复述不产生多个报告事件。精确相同历史句+相同日期/主题可以合并重复mention；当前判断不得仅凭同动作或同日合并。

### B. LLM逐项判断是什么

输入：每条规则候选、文书类型、时间含义、该句之前的局部上下文。没有其他患者资料、旧CP或未来文书。

输出固定JSON：candidate_id、角色（当前判断/历史检查/结果复述/通用模板/非判断/不确定）、根治路径关联yes/no/uncertain、管理问题、动作、当前/历史/未来计划、已知选择理由、逐字引用、缺口。

程序验证ID无漏项/新增、引用来自实际提供片段、原文坐标和hash一致。失败单列，不把调用失败当非决策。模型可见文字做长度保持的身份字段遮蔽，引用验证后映回本地原文；不是已认证的匿名数据集。

### C. 构造本轮证据窗口

以当前候选的判断时间/临床阶段为上界，前一轮已保留判断为区间下界。提供：

- 前一轮以前的原始资料作为累计背景；
- 两轮之间新增原始报告、检验、病程作为本轮变化；
- 当前文书在选择之前的原文；
- 当前与前一轮的实际判断，仅供“重建判定模块”识别，不是盲评输入。

为避免每次重发患者全部历史，模型实际收到前轮所引用的原句（前轮状态）以及两轮之间新增全文/当前前段；累计历史完整保留在本地窗口审计中。这一模块只判断证据变化，不承担完整临床状态回放。时间/角色/根治关联尚不明、或历史检查缺少选择前状态时，不额外调用演化模型强求结论，状态明确记为未评估前提不明；这与网络或引用校验失败分开统计。

影像检查时间、报告发布时间、文书正文时间、创建时间、术中阶段、历史提及的事件日期各保留含义。未来资料不得进入。只有同日日期、同一分钟而一端只有分钟精度、同一时刻却无法定序、未知时间、隔离源均进入REVIEW，不补午夜或擅自视作该分钟第0秒。当前同文可凭先后语义提供前段，不能把整份术后手术记录倒放到手术开始前。

选择前边界可以在一句话中间：优先定位“拟/建议/遂决定”等当前行动表达；术中“术中诊断……遂决定”从当前综合诊断前截取，保留此前直接探查所见。原句作为完整重建锚点保留，另存choice_start；不能把整句都当作选择而删掉同句的新发现。标记只是候选边界，当前还没有经过独立语义遮蔽评估。前轮与本轮若来自同一文书、时间相同，可凭不重叠原文顺序比较；其他同刻不能冒充“首见”，保留定序不明。

术后首次病程、转入/出室记录或出院小结中的“术中……遂决定”按二手回述保留，不能因为写作时间更晚就再造一次当前手术选择。同份术后记录中的新营养、症状等当前管理仍逐项判断，不能把整个患者或整份术后资料排掉。术中探查段允许原始缩进空白，不把段首空格当成阶段不匹配。

已知历史检查发生时点若只有日期，不能把后来病程全文作为当时输入。缺选择前资料即保留缺口。影像只有检查时间时属于回顾性代理，不能声称报告当时已发布或被医生阅读。正文标签时间在全文查找，但多表、多时刻不强行选一个。未知时区按既有本地适配声明+08:00，不声称已完成机构时区核验。

窗口超出单次模型预算时，按完整来源块分页，模型逐页选择与本轮问题/前轮变化有关的原句；正常、异常、不利、矛盾和未完成状态均须考虑，不能只选支持实际选择的内容。程序逐字核对选句，再把原句交给演化判断；不生成替代原文的病例摘要。完整原文及未选来源仍保留在本地审计，未选不等于阴性。选句后仍超预算、单份来源超过页上限或页数超上限时显式DEFER，不静默截断。上限均在配置中声明，当前不宣称能无限长度运行。

### D. LLM判断证据演化和管理过程

输出：相对前一轮为首见/同轮/新轮/不同任务/不确定；证据为新增相关/重复/新增但连接不足/不足；是否同一管理任务；连接为明确支持/上下文支持/不确定；新证据引用、连接引用、缺口。

程序只在根治关联yes、当前判断有依据、时间可定位，且首见或有新增相关选择前证据时保留候选CP。结果仍是候选而非gold。当前选择本身不能充当新增证据。明确连接必须有连接原文，只有上下文支持保持context_only。未知保留，不补因果。

前一轮是最近保留的候选判断，本版为线性近似；同时存在多条未解决管理问题时可能不是正确比较对象。episode仅在同一管理任务有支持时连接，未知链接单列，不把日期、住院或同一次手术当episode定义。

## 输出契约

每例输出来源清单、规则候选、模型归类/失败、证据窗口及逐来源理由、DecisionEvent研究注释、候选CP状态、候选episode、FHIR Bundle及验证结果、调用回执。所有有内容的语义字段带原文依据；不能保证的字段显式unknown/uncertain。

候选DecisionEvent与最终用于盲评的CP分别统计：历史相关但输入不足的检查选择仍在DecisionEvent候选账本中；当前没有自动生成正式盲评材料。当前实际选择会提供给重建模块，不能直接把该窗口给医生或待测Agent。

旧36点只在自动运行完成后用于开发diff，不参与生成、筛选或提示。旧清单不是独立gold，不计算有临床含义的准确率/F1。

## 最小验证与后续评估

1. 反例：报告中的MRI不造选择；病程复述不重复造检查；真实“拟MRI”和历史“做过PET-MRI”能进入候选。
2. 时间：晚回报检验、晚MRI不能支持早判断；当前选择之后的术中内容不进入选择前窗口；日期不明保留未知。
3. 来源：独立CTA导入；正文时间在第120字之后也能识别；非CP文书的既往病史仍能进入后续窗口。
4. 模型：无效JSON/quote/ID、缺连接引用、上下文过长不能变成阴性或正式CP。
5. FHIR：官方R4 JSON Schema和所有本地引用通过；不把JSON结构验证称临床语义、术语或完整IG验证。
6. 临床评估尚待：另行冻结规则/提示/配置，在未用于开发的样本独立标注候选召回、角色、重复合并、证据演化、时点输入完整性/泄漏、episode连接。逐类报告真实信息不足与规则/模型错误。

- Wang & Weiss，AMIA Informatics Summit 2025，临床事件与相对时间提取：https://arxiv.org/abs/2504.12350 。病例报告实验不能当本项目EHR性能；事件召回与时间正确性应分别评价。
- CliniCIRCA，2026年9月预印本：https://arxiv.org/abs/2609.19585 。分阶段提取、处理时间不精确性及医生核对时间线可供方法参考；精神健康出院记录的结果不能转用于本项目。
- NCCN 2025患者指南：https://pancreatic.org/wp-content/uploads/2025/07/NCCN-2025-pancreatic-patient.pdf 。用于理解补充分期等候选主题，不按2025指南回写2022年患者选择理由，不生成临床正确性Reference。
- 结构化输出接口：https://developers.openai.com/api/docs/guides/structured-outputs 。当前第三方兼容接口使用JSON mode并本地schema校验，不宣称其支持OpenAI的strict schema能力。
