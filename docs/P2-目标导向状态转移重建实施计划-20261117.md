# P2 目标导向状态转移重建实施计划

日期：2026-11-17  
状态：已批准实施

## 本轮纠正的问题

旧实现以“文书—管理句—CP—关系拼 Episode”为主：10 例产生 118 个 CP，其中 99 个是管理文书 CP、19 个是检查前 CP，报告后状态为 0。CT、MR、EUS、病理、术前讨论和手术安排因此可能被拆成不同管理过程；重复小结、日程、谈话和查房又各自形成 CP。

本轮改为“持续根治切除管理目标—当前证据状态—下一步动作—新证据到达—更新状态”。CP 是 `(截至时点可见状态 St, 下一步管理动作问题)`，不是一份文书或一句话。检查前还原安排检查时可作答的状态，检查后呈现新证据并询问下一步动作；两者是不同 cutoff 的时间投影。

`docs/P2-候选CP与检查双节点重建实施计划-20261115.md` 第 86、94 行“同一检查来源全病例只能保留一个 CP／前后互斥”自本版本起废止。旧文件与输出保留用于版本 diff，不反向改写历史结果。

## 对象和接口

新格式版本为 `management-trajectory-0.1.0`。旧 `candidate_checkpoints` 接口继续可读；新投影同时输出：

- `management_episodes`：`episode_id`、持续 `goal`、`checkpoint_ids`、`phase_transitions`。同一根治切除目标下 CT、MR、EUS、病理、腹腔镜、减黄、NAT、手术评估均留在该轨迹；phase 只描述阶段，不拆 Episode。研究主任务外的常规术后管理另记支持或排除原因，不以 REDIRECT 自动终止全患者研究轨迹。
- `action_cycles`：`action_cycle_id`、`episode_id`、`phase`、`evidence_state_id`、`input_evidence_ids`、`candidate_action_space`、`support_source_ids`、`member_event_ids`、`checkpoint_ids`、来源引文及迁移审计。
- 状态 CP：`checkpoint_id`、`kind`、`clock`、`clock_basis`、`action_cycle_id`、`evidence_state_id`、`support_source_ids`、`member_event_ids`、`masked_spans`、`candidate_actions`、`provenance`。内部 kind 为 `BEFORE_ACQUISITION`、`AFTER_EVIDENCE_ARRIVAL`、`MANAGEMENT_REASSESSMENT`；停用有歧义的 `pre_exam_evaluation` 展示名。
- `evidence_events`：统一 CT、MR、EUS、病理、操作/手术等证据事件，保留原始 source、exam/report/verified 时钟、可见性代理及差异，不把检查时间冒充报告可见或医生阅读时刻。
- `migrations`：每个旧 candidate span 和旧诊断候选均映射为保留、合并、支持记录、主任务外或待核；输入数量必须守恒，禁止静默删除。

phase 候选：`INITIAL_RESECTABILITY_ASSESSMENT`、`PREOPERATIVE_OPTIMIZATION`、`NAT_OR_CONVERSION`、`POST_TREATMENT_REASSESSMENT`、`SURGICAL_EXPLORATION`。NCCN 动作骨架仅用于动作索引和覆盖审计，不按关键词硬纳入，更不预填专家 Reference。Discovery 继续广泛召回，并由 LLM 排除 PICC、纯模板、既往回述等。

## 纳入、合并和时点规则

1. 一个 CP 必须有可输出的 Mode 与具体动作计划问题。入院意图、纯执行、通用模板、重复手术计划/小结/讨论/日程/谈话不各自成 CP，但原文保留为支持、动作定位或遮蔽来源。
2. 同一决策周期内一个 source 只能属于一个目标 CP。不同 cutoff 可以有不同时间投影；检查前完全遮蔽目标检查安排及报告，报告后合法显示当前新证据。不能用“source 出现过”推断信息泄漏。
3. 不机械地每张报告生成两个 CP。联合安排/联合返回且没有状态或动作增量的证据合并；CT 后为解决不确定性再做 MR 等增量必须保留。只有动作或证据状态增量才建 CP。
4. 管理 CP 按同一未解决管理问题及重复动作合并，不能按 source 或相同目标字符串一律合并。新条件、取消/改期、证据到达、治疗改变或再评估可形成新状态。
5. 病理到达后可接受 NAT，不额外套一个内容相同的化疗文书 CP；疗效复评后才形成新状态。术后 ICU/出院中的当前主任务外处置不能因 profile 不是 postoperative 而漏入评分 CP；原文回述另行保留。
6. 有报告时间优先作为可见性代理，缺失时降级 verified time；保留降级和未知。无可见上下文或精确选择时刻时如实标记，不伪造分钟级选择时刻。
7. 原始文字是临床事实来源，LLM 动作和分类均为待审核候选。证据到达不等于证据被使用，后者仍需明确原文依据。

## 工程和验收

- 主线程先固定 schema；并行扩展证据单位、目标轨迹/去重模块及合成反例，再接入材料、私有 HTML 和迁移审计。工作区已有用户改动，不整批暂存、不覆盖旧输出。
- 先用现有真实 Discovery 对 SCALE-02、09、05 离线重投影，单独标明“非新模型运行”。确认报告后状态不再为 0、同一目标轨迹容纳 CT/MR/EUS/手术评估、重复文书归并、主任务外术后管理不入评分 CP。
- 合成反例覆盖双时点、联合证据、重复文书、病理、既往腹腔镜不建当前 CP、模板 EUS 不建 CP、同源不同 cutoff 无泄漏、术后其他 profile 排除。
- HTML 每屏展示管理目标、phase、新增证据、可作答动作空间、支持文书、MASK 理由、前后状态与 action cycle。可见材料继续按自然日折叠；Agent 提议不是预填医生答案。
- 独立对抗审计假定实现错误，只报告证据和原因；主线程修复后运行 Harness 标准测试与 P1 regression guard，并在浏览器实际导航和检查遮蔽。
- 真实闭环优先 SCALE-02，再 SCALE-09、05；新合同、缓存、授权和输出目录。若成本可控再全量。最终报告真实调用数、前后 CP/Episode 变化、测试与 HTML 路径；技术通过不等于临床正确性或专家 Reference 已建立。
