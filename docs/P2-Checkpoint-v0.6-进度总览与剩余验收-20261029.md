## 2. 核心变化及其证据层次

1. **程序在全部LLM复核结束后重新核验依赖。** 程序检查LLM指定的既往临床管理判断比较对象、同事件关系和同管理过程关系；明确无效的关系不再合并候选Episode。程序保留原LLM提案，不把执行、重复或非候选标签一律当作临床错误。
2. **错误反馈有次数上限，也允许维持未定或撤回提案。** 发现和复核各最多一次语义反馈，格式恢复单独记账。发现阶段LLM修改目标临床决策子句后，程序重新生成事件及资料范围；复核阶段反馈则保持当前原文和许可证据池不变。支持文书和零发现补查已有代码，召回改善仍是假设。
3. **来源与原文分区可以追溯。** 新运行归档实际输入的精确字节，区分原文hash与脱敏显示文本hash。分割编译器按Unicode code point区间绑定原文、来源和Checkpoint，显式保留KEEP／MASK／REVIEW。历史已消失的临时输入不能由新归档机制反向认证。
4. **独立材料审核成为可逐项填写的对象。** SemanticAudit 0.2.0逐区间绑定原文、坐标、hash和处置理由，并记录来源覆盖、目标临床决策时间证据、跨文书回述和开放问题。AI研究准备草稿只能保持PENDING，不能代表独立人员已经审核。
5. **医生端有可运行的资料和响应接口。** 医生FHIR包仅含当前Checkpoint的许可正文和冻结问卷；单文件HTML支持多选、条件题和本地下载。结构化响应绑定Checkpoint、资料包版本/hash、表单版本/hash和评审分配。被遮原文、未来Checkpoint及研究者全量对象不进入医生文件。当前实测使用虚构资料与演示选项。
6. **工程测试与临床结论分开。** 程序回归、FHIR结构核验、浏览器往返和固定模型技术完成均有回执；这些回执没有测得临床准确性改善，也没有形成专家Acceptable Mode Set。

## 5. 下一步如何验收

1. **独立研究验证，可与材料审核并行。** 独立从原文核对管理判断定位、事件粒度、LLM指定的历史比较对象、信息演化、当时可见性及遗漏／错误新增候选；另对支持文书、零发现和被排除单位分层抽查。固定来源、模型、温度和指标，区分程序修复、反馈和召回策略的影响。
2. **独立材料审核。** 实际人员审核353段以及纳入／排除来源、必要资料覆盖、跨文书目标临床决策回述和时间证据。需要修订时另存新版、重新编译并重新审核；不能只审核343个REVIEW后忽略其余原有MASK。
3. **临床方案冻结，可与前两项并行。** 冻结任务、术前／术中动作空间、Mode/action、Q1—Q5、Severity／Confidence锚点、指南年代、评审人数、独立性与分歧处理。现有草案未恢复原方案全部Q1—Q5原文字，不能由代码补定为临床标准。
4. **真实医生试评。** 只有真实独立语义PASS、完整审核范围、无REVIEW、无待执行修订和外部冻结问卷同时具备时，才创建并分配真实医生许可包。小规模试评验证任务可理解性、选项覆盖和意见回收后，再按冻结方案开展正式盲评并形成Reference。

FHIR当前提供24个draft StructureDefinition、R4 JSON Schema与本地合同／引用核验，尚未完成profile snapshot、完整FHIRPath及术语验证，不能称为已发布的FHIR研究规范。hash核验保证内容绑定，不能认证人员身份、实际独立性或临床正确性。
