## 1. 两条研究原则不变

先判断管理是否关联 PDAC 可切除性与根治路径，包括证据收集、患者条件优化、暂缓、不推进及直接相关的围手术期管理；再判断与前轮相比，是否出现与当前管理判断相关的证据演化。

新信息可以支持改变方向，也可以在再次评估后确认继续推进。只有“继续治疗”不自动构成新一轮；新报告行也不自动等于新的患者信息。首个可见安排可以作为起始锚点，但不能宣称已验证两轮间演化。

决策存在、是否独立一轮、是否证据驱动 checkpoint、是否同一具体问题、是否同一管理过程，是需要分别保留的判断。未知选择时刻不能抹掉已明确存在的管理安排；存在检查报告也不能虚构当初为什么选择检查。

## 2. LLM 与程序的决定权

| 事项 | 主责 | 边界 |
|---|---|---|
| 根治路径关联、是否存在管理判断 | LLM | 标题和关键词只作检索提示；可以补充规则未命中的决定，也可返回零事件 |
| 事件粒度、合并/拆分、当前或历史功能 | LLM | 提供完整文书及此前上下文，保留理由与来源；不能逐句机械生成事件 |
| 前轮、证据演化与信息-判断连接 | LLM | 可拒绝程序预选前轮、改选多个候选中的适当前轮，或保留未知 |
| checkpoint 与 episode 连接 | LLM | 具体子问题不同不自动切断同一管理过程；相同治疗名不足以合并同一事件 |
| source 身份、hash、原文引用与跨度 | 程序 | 不允许模型编造来源、改写引文或选择一个未经验证的跨度 |
| 已知先后约束与允许引用范围 | 程序 | 已知未来、当前动作、选择后结果不作此前观察；不把代理钟认证为真实选择钟 |
| schema、ID、前轮集合与输出结构一致性 | 程序 | 检出矛盾，保留模型原判及有效依据，做有限修复或标明相应未知，不暗换成关键词答案 |

模型的语义判断权较高，但不能越过原文事实边界。程序校验通过也只证明“这句确实出自允许材料”，不证明该句的临床语义必然支持连接。

错误的一条次要引文不能删除独立有效的主动作。重复原文导致跨度不唯一时，保留所有出现位置；只有全部出现位置都在允许范围内，才可作来源层面的支持。不能任取第一处当作精确选择边界。

## 3. 原句索引、完整文书与语义输入

此前按句切分的合理用途是建立检索指针、减少关键词匹配范围和便于定位引用；它不应定义临床事件粒度，也不应截断 LLM 理解病程的上下文。

v0.4 发现阶段以完整当前临床文书或同次检查的原始报告版本为单位，提供最近完整临床文书及入院、手术、转入转出背景。小结先整篇阅读，再判断内部指征、风险、安排、术式字段是否表示同一次管理判断；查房也先读完整状态与计划，不因句号多而增加事件。

文书类型提供先验：术前小结/讨论常汇总既定安排；手术记录优先寻找“探查所见→继续/调整/终止”；术后首程常回述术中选择，也可能包含当前新的恢复管理。标题不能自动决定阳性或阴性。护理、同意、评估等支持类型可以降低主入口优先级，但若其中存在明确的新医学判断，需有补充召回路径，或将漏读范围明确记录。未检查这类材料时不得声称完整 EHR 决策召回。

证据复核阶段按每个目标建立自己的状态：此前原始来源、当前文书中选择前观察、实际当前动作、选择后执行/反应分别标记。原始来源不会被改写成新的病历事实。后写内容可以帮助识别回述身份，不能填回更早的选择前状态。

当前完整文书和当前动作可以在明确标记的“重建上下文”中展示，以便判断身份和边界；它们不是盲评材料，不应混入 `observation_quotes`。未来若构造医生/Agent 盲评包，须在所有相关文书中遮蔽目标动作的复述、选择后的执行与结果，不能只删一句“决定”。目前未形成并验证盲评包时，保持 `blind_replay_ready=false`。

所有预算省略都须登记来源、字符数、原因与模型实际收到的范围。目录中有报告、编译窗口有报告、给模型传了目录元数据，都不等于模型看到报告正文。指标核对实际请求回执和对应跨度。

## 4. 时间与可见性的最低要求

- 原文明示选择时刻才可称显式选择时间；记录钟、报告钟、检查钟分别保留代理或上界身份。模型填了可解析日期不等于原文验证通过。
- 术中一般只能定位到探查后、切除前。手术开始时间用于保守检索边界，不作为精确选择时分；同文探查所见可由阶段顺序纳入。
- 入 ICU 的后写解释不能使用已经入室后的检验，证明此前为什么选择入 ICU。术后复述中的“遂决定”不另建一次当时才发生的决定。
- 检查报告支持此前有检查行为/选择痕迹，但检查时间只是选择时间上界；早于检查的临床记录也可能晚于实际选择，不能自动认证为该检查的选择前状态。同次检查自己的所有报告版本均不用于证明当初为什么选择它。
- 相同患者信息先在病程被引用，较晚又出现原检验报告时，应核对对象、值、单位、检查日期和版本。不能只按报告行时间把已知值再算一次新信息；也不能只因措辞相同折叠不同对象或不同次检查。
- 时间或发布可用性无法确定时保留具体维度未知；它可以作为待核材料被检索，不能作为已认证的 prior/new fact。

## 5. 冻结开发集与预注册目标

A/B 源文审查合计覆盖 SCALE-01、02、03、04、06、08、10 七例，共83项：40项明确决策、29项非独立当次决策、14项原文不确定。40项明确决策中，30项支持确定的新证据轮，6项初始过程锚点，3项明确拟术但是否新增一轮仍未知，1项诊断检查选择属于初始或新轮尚不能确定。后四项不能混入30项确定新轮分母。证据控制中有53个 `needed` 目标跨度。

| 指标 | 开发目标 | 当前冻结分母的整数门槛 |
|---|---:|---:|
| 源文挑战集决策发现覆盖 | ≥90% | ≥36/40 |
| 确定新证据 CP 覆盖 | ≥80% | ≥24/30 |
| 标负项被另选为独立决策/CP | ≤10% | ≤2/29 |
| 必需证据在实际模型输入中的覆盖 | ≥95% | ≥51/53 |
| 未来/当前动作/选择后内容充当 prior 或 new fact | 0 | 逐类别报告绝对数量及适用分母 |
| 不确定按维度保留且有可解释原因 | 100% | 14项不确定及3项新轮未知的明确拟术，逐维度核查 |

决策发现与最终独立决策覆盖分别报告，不能只展示发现阶段高分。初始锚点单独报，不能靠将复杂新轮改叫“首个”绕过证据演化。负例允许作为既有事件支持、历史提及或执行材料被保留，只有被另选成独立当次决策/CP才算误选。

按 source ID、source hash、动作引文跨度及动作语义对齐，正例采用一对一匹配；ID 名称变化不影响命中。跨度重叠只是机械候选匹配，宽泛引文覆盖到错误动作仍须判不匹配。多次选中同一正例不得增加分子，额外重复单报。

证据分母以“目标决策+来源+跨度+角色”为单位。`needed` 要求完整跨度实际送入相应语义复核的允许证据范围；没找到事件也要算端到端缺失，不能只报“已找到事件中的覆盖率”。`availability_uncertain` 单报召回和未认证身份，不硬算已知可用证据。未来/选择后/当前动作任何违规重叠计入泄漏控制；既往基线允许作为基线，不允许重新宣称为新增。重建上下文中的答案披露与被错误当成 prior fact 分开报告。

不确定至少分开 scope、事件身份/粒度、选择时间、来源可用性、证据演化、信息-判断连接、管理过程连接；每个未知项有原因及原文依据，区分真实资料不足、标注规则歧义、来源时间冲突、处理/引文失败和模型语义不确定。仅输出一个总体 `uncertain` 不满足“维度+原因100%”。漏掉未知事件也不算保留未知。

因挑战集非穷尽，不报告整体 precision、F1 或全病例召回率。未标注的模型输出不能直接算假阳性。没有实际请求回执、没有适用分母或指标尚未实现时，返回 `not_measured`，不能当作0错误或通过。部分运行必须保留冻结总分母并报告缺失病例，不能缩小分母提高分数。

同一固定十例用于 v0.3→v0.4 开发比较，继承种子20261023；七例有本次源文挑战标签，其他三例只作未标注探索。冻结旧输出、代码和输入来源，新结果写新目录。不得把开发集进步称为独立验证或临床验证。

## 6. 必要回归反例

机器 contract 内给出14类合成测试规范：重复引文保留有效事件；小结多字段不强拆；小结新取消/延期可推翻先验；术中阴性/阳性探查与执行隔离；术后回述挂回；拔管前后与次日转出的时点差异；cTnI→CTA的跨专科召回；同值报告不伪造演化；拒绝无关营养前轮；历史 MR 检查选择未知；预算省略不冒充模型已见；重建全文不冒充盲评包；支持型文书的医学判断补召回；同事件/选中状态/episode 结构不一致不静默放行。

实现时将这些规范关联到实际稳定问题编号、失败样例及阳性/阴性对照。此文仅列测试规范，不冒称全部测试已实现或已通过。

## 7. 冻结时静态审查的风险

已阅读 prompts、context、validation、evaluate、配置，以及随后出现的 engine 草稿，未读新版模型结果。

提示词已明确完整文书、LLM 可改粒度/前轮、区分当前选择与前观察、区分同事件与同管理过程。逐引用校验也已避免一条坏次要引文使全部有效依据丢失。

需要运行前核对的风险包括：支持标题硬过滤可能隐藏新判断；最近四份文书与预算可能漏背景；目录元数据不是正文；未知检查选择的检查上界不认证前状态；显式选择时间需原文证明；LLM 初次分离选择前跨度仍可能语义错，逐字匹配不能替代时态判断；同事件连接需要影响最终去重，不能只写一条边后保留两个选中 CP；不通过先后/ID验证的边不能在 episode 组装时重新变成 supported；重复 review ID 不应静默覆盖；线程完成顺序不应改变相同输入的前轮 ledger 排序；`context_only` 不能被当成已证明的信息-选择连接。

这些是冻结前设计审查风险，不宣称所有风险已修复。实现回执、反例测试、数据观察及目标达成情况须分别报告。
