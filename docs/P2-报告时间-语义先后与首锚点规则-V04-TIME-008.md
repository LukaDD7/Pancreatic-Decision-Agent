## 1. 已确认的问题

1. 冻结十例的 102 个标准化影像源均没有有效报告发布/签发时间，旧 `p2_pathway_replay/core.py` 将 `report_time` 固定投影为空，只保留检查时间 proxy。

3. **2026-11-07 已向上回源修正**：在两个原始队列交付包的 `patient_source_bundle.json` 中找回 `imaging_all[].fragments[].raw_fragment/raw_token_array`，而不是只读标准化缓存。21,528 条保存的 CSV 原始影像行均在首个物理行包含日期，且独立日期/时刻分别位于零基 token 5、7；它们与 `exam_datetime` 对应，是**检查日期/检查时刻**，不是另一个报告发布时间。所有 21,528 条的 `archive_event_time` 非空，`archive_available_time` 非空数为 0。标准化缓存的 JSONL 来源记录有 2,895 条；其中 1,660 条已与保存的原始 fragment 精确匹配检查时间、检查号、所见和结论，证实完整 CSV 首行/身份列没有进入 `original_report_text` 或标准化缓存。1,235 条尚未在当前两个队列包中匹配，197 个重复坐标均为相同身份的跨队列重复，不能当作额外病例或遗漏。此结果只覆盖保存的 CSV 来源，不覆盖 Excel、其他医院系统或可能另存的 PDF/签发元数据。

5. 报告原文进入后续上下文不等于报告证据已被采用。历史中报告事件作为前轮提供 345 次、被选择为 previous/process predecessor 均为 0 次；这显示显式证据组织断点，不证明临床团队没有阅读或使用报告。

## 2. 首锚点与前置事件的实际规则

历史 `first_anchor` 是“研究范围内首个可见管理安排/判断”，**不要求前置临床决策事件**。冻结 451 个事件中：

- 最终 `CANDIDATE_FIRST_ANCHOR` 为 87 个，均无 `previous_event_id`；
- 31 个 first-anchor 提案因其他契约/图问题降级，0 个因 `PRIOR_ROUND_UNRESOLVED`；
- 167 个 new-evidence 提案均提供了 `previous_event_id`；
- 20 个独立报告事件中 2 个为 first-anchor 提案，报告自身的选择时刻可保留未知。

`PRIOR_ROUND_UNRESOLVED` 只适用于证据驱动的 `new_evidence`，不是每个 Episode 或首锚点的通用门槛。前置常规 CT 可以是背景检查，不必被虚构成一个前置决策节点。

但不得利用“首锚点不需要前轮”绕过以下情形：已有相关前轮、声明发生证据演化、或当前文书以既有检查结果支持新的管理判断。这些情形仍须保存其证据连接及不确定性。

## 3. 无发布时间时的语义判断边界

历史复核输出已有 469 条 `explicitly_known_before` observation 提案；其中 395 条的选择前依据引文位于当前管理文书，330 条观察引文也位于当前文书。它们说明“当前文书复述既有结果并据此判断”是已有语义通道，但不是独立认证的发布时间或医生已读事实。

后续 LLM 可以逐条提议：

- 原文引用的具体报告/检查对象；
- 报告所见与病程复述的引文；
- 该结果是否被表述为目标管理选择前已经取得；
- 相对目标选择是 before / after / same-time-unresolved / unknown；
- 时间先后是否对该 Checkpoint 证明必要；
- 证据用途是直接引用、复述、背景、未决或无连接。

程序必须核验引文来自实际提供的原文、对象与 EvidenceObject 一致，并保留原始 LLM 理由、请求/响应 receipt 和 hash。

**不得**由“根据 CT 结果……”生成一个虚构的发布时间；不得把语义上的先于选择扩大为精确时间、医生实际阅读或因果采用；不得用一个额外 LLM 的判断替代来源核验和医生 Reference。

## 4. 哪些事件需要证明先后

| 事件/证明类型 | 是否需要前置决策事件 | 时间/证据要求 |
|---|---|---|
| 首个可见管理安排或判断 | 否 | 保留当前动作原文、范围和身份；不虚构前轮 |
| 新增补充检查、EUS、增强 CT、肝 MRI、暂缓/改变路径 | 否 | 当前管理动作自身不须先于自身存在；其适应证可另作背景/证据关系 |
| 历史检查执行锚点 | 否 | 执行时间可与报告发布时间和选择时间分离，选择时间可 unknown |
| 证据驱动的后续管理选择 | 是，作为临床管理比较对象 | 需要相关前轮、选择前可见信息及证据到当前判断的连接 |
| 报告结果支持后续选择 | 不要求报告成为前置决策节点 | 报告作为 EvidenceObject；引用/复述可支持选择前已知，阅读/因果分别保存 |
| 重复表述或执行 | 不强行制造新演化 | 保留身份/过程连接，不能为了图完整伪造新事实 |

## 5. 反例与必须回归的控制

1. **首锚点反例**：研究资料中只有“常规 CT 提示可疑，现安排胰腺增强 CT”；增强 CT 可作为研究范围内首个管理安排，不能因无前置决策事件被否决。
2. **当前动作反例**：将“拟行 EUS-FNA”填为选择前新事实，应报字段错误；不能把当前安排要求为自身前轮。
3. **报告自身边界**：报告结果不能证明为什么选择该报告自身；报告执行锚点仍可保留。
4. **语义先后正例**：后续术前讨论原文复述某影像结果并据此推进管理，可形成有来源的选择前证据提案，即使报告发布时间为空。
5. **语义先后负例**：检查后执行记录或选择后复述不能反向成为该选择前证据。
6. **时间不可伪造**：不能根据语义先后生成精确 `issued`，不能根据检查时间或发布时间宣称医生已读。
7. **对象一致性**：报告 A 的结果不能用报告 B 或不同日期/对象的相似文字替代；重复词命中不等于复述采用。
8. **局部未决不抹除**：某一证据关系未决不删除事件、原文或其他已核实来源；只降低对应证明强度。

## 7. 用户提出的分层语义路线与数据可行性核查（2026-11-07）

数据整理核查反馈：很多源数据本身只有检查时间，没有独立报告发布时间。因此除继续保留原始字段核查外，需要评估**按事件类型分层语义证明**，而不是要求所有事件都取得精确 `issued`。

待数据检验的假设，不得先写成既定规则：

1. **非“安排/执行该检查自身”的后续管理动作**：如果当前文书明确复述或引用检查结果，并把它作为新管理动作的依据，语义关系可能比精确报告发布时间更有证明力。重点是相关证据更新是否支持该动作，而不是机械要求所有事件逐一通过报告发布时间 cutoff。
2. **检查自身成为事件**：需要单独判断其选择/执行时间、研究范围内定位，以及是否有必要呈现“可见时间前的全部事件”。可能只有一两个明确、关键的前置管理事件需要连接，其他检查只作为背景 EvidenceObject。
3. **经验先验的后续决策**：用户曾提出约 4 小时出报告的经验假设；经真实数据核查后，用户于 2026-11-07 明确决定将其从正式方案删除。它不得进入判定、候选排序、审计提示、字段填充或任何时间推断，也不得生成事实时间、替代原文证据、证明医生已读或自动升 Checkpoint。
4. **全量呈现与关键前轮分开**：完整来源仍应保存在 EvidenceObject/材料依赖中；临床 Episode 的前轮连接是否只保留关键管理事件，必须根据真实病例检查，不能借“关键前轮”丢弃其他原文或把证据更新强套到无关动作。

- 暂缓检查后重新安排，但原文未说明异常是否纠正：可以保存新安排，不能声称风险已解除；若作此因果声明，仍需要新结果及其选择前可见性。

## 9. 双通道实施方案与 Harness 完整度门（2026-11-07 用户确认方向）

### 9.1 两条长期并存的证明通道

1. **报告时间链**：保留检查执行、书写、审核/签名、发布、系统可见等字段角色及精度；报告时间早于选择只支持时间上可能可见，不证明实际阅读或采用。字段缺失不自动否决事件。
2. **语义证据链**：以报告原文、当前文书引用/复述、当前动作及连接引文证明来源绑定的选择前语义关系；不得生成精确时间、实际阅读或临床因果。
3. 两条通道分别保存支持、冲突、未决及来源。任一通道不足不等于事件不存在；时间冲突不能被语义标签覆盖。
4. 按事件类型决定证明义务：首锚点/新检查安排、后续证据驱动选择、检查执行锚点、报告 EvidenceObject、重复/执行、选择后记录分别处理。关键管理前轮与完整来源保存分开，不写死前轮数量。

### 9.2 Harness 必须作为完整链路交付，而非只改模型提示词

实现范围必须覆盖并逐段留存回执：

| Harness 环节 | 必要交付与阻断条件 |

| 输入与对象绑定 | 事件类型、当前动作、EvidenceObject 身份、候选关键前轮、完整来源及 omission 状态进入明确请求上下文；缺来源或对象不唯一时局部 HOLD，不猜测配对。 |
| Schema 定义 | 机器校验事件角色、报告/复述/动作/连接 span、来源 ID、语义顺序、证明通道、证据用途、关键前轮、uncertainty 和局部状态；禁止当前动作被声明为选择前患者事实，禁止语义判断生成时间字段。 |

### 10.1 已实现的程序边界

1. `evidence.py` 按 EvidenceObject 编译 report-time 与 semantic-prechoice 两通道，分别保存来源阻断、时间未决、真实时间冲突及字段级错误。narrative record time 与 publication 的先后不得冒充 publication 与精确 choice time 的先后。
