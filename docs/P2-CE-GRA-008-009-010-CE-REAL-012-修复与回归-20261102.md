## 3. CE-REAL-012：来源依赖闭包

- `inputs.resolve_episode_source_dependencies` 分别组织：
  1. 当前处理单位的完整原文；
  2. 每个事件 `source_ids ∪ actual_model_evidence[].source_id` 的历史证据来源依赖；
  3. 冻结交付包中 hash 可核验的来源；
  4. 交付中确实未找到的 source_id。
- 图审核和独立重建继续只使用当前处理单位原文，不借历史材料依赖扩大审核范围。
- 材料任务使用当前单位及可核验历史依赖的合并集合，不修改材料核心来源集合定义，也不删除冻结事件证据。
- 来源回执保存来源角色、来源 hash、来源时间元数据与 `clock_basis`、依赖缺口及来源清单 hash。来源恢复不认证目标时点可见性，不授予医生盲评许可，也不声称已阅读全患者病历。
- SCALE-01 无模型离线核对：当前单位 3 份；材料合并来源 257 份；两个 Checkpoint 材料装配均无 `ASSEMBLY_SELECTED_SOURCE_MISSING`；恢复历史依赖 254 份、未找到 0 份。该结果不等于新真实远程批次已运行。

## 4. CE-GRA-010：失败响应与业务 replay

- `candidate-graph-reconstruction-chain-0.2.0` 在响应校验失败时保存 response、脱敏 provider_receipt，以及 invocation_id、provider response hash、解析后 response 内容 hash 的绑定。
- provider 未返回响应时不伪造 response 或 provider_receipt；只保留失败类别和可用的 invocation_id。
- `validate_graph_reconstruction_chain` 支持成功新图、合法模型 HOLD、响应校验失败和 provider 失败的无模型重放。响应失败须重现同一业务拒绝理由；篡改、重算 hash 或成功图改名为失败 HOLD 均拒绝。
- 批次 replay 读取每条 `reconstruction-*.json`。成功重建链还须与同代 `graph-reconstruction-chain.json` 绑定；失败 HOLD 不伪造 generation。
- 旧 v0.1.0 冻结失败链没有被覆盖，也没有宣称其原先未保存的响应已被补齐。
