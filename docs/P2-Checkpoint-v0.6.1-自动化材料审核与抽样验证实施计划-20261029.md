# P2 Checkpoint v0.6.1：自动化材料审核、修订闭环与抽样验证实施计划

2026-10-29。登记时状态：**PLAN_REGISTERED／计划已登记，尚未实现**。

**2026-10-29 后续实现状态：A—C 工程实现与虚构整合回归已完成；D 的真实开发运行、独立人工抽样验收和 E 的真实医生试评／盲评尚未开展。**实现证据见 [自动化材料治理实施回执](P2-Checkpoint-v0.6.1-自动化材料治理实施回执-20261029.md)。此状态更新不表示真实患者资料已经运行、自动材料质量已达到统计门槛或临床发布已获许可。

本计划按研究负责人提出的自动化方向制定：不让几千例全部依赖人工逐段审核，而由 LLM 审核实际拟呈现给医生的完整原始资料，提出有原文依据的修订，程序执行并重编，形成可追溯的候选 Episode／Checkpoint 材料；实际人员通过分层抽样验证自动化质量。达到预先冻结的质量门槛后，未抽中人工材料审核的病例可沿同一冻结自动管线送专家临床盲评。专家始终可因信息泄漏、资料不足或任务不可评价而保留意见，不输出该次临床 Reference。

## 1. 版本定位与不改变的事项

### 1.1 与 v0.6.0 的关系

- v0.6.0 指 `config/p2_auto_checkpoint_v06_*.json` 中 `p2-auto-checkpoint-0.6.0` 的候选重建实现及其后续 FHIR／HTML、人工任务准备工具。
- v0.6.1 是**新增自动化材料治理层的计划版本**，不是把旧 v0.6.0 输出重命名，也不是声称候选重建的语义问题已经解决。
- v0.6.0 的 discovery、review、最终关系审计及冻结输出保持原样；v0.6.1 读取这些结果，另写新版本目录。需要修改候选事件、关系或 Episode 时，必须作为另一层可追踪的重建修订，不得在材料编译器中暗中改变图成员。
- v0.6.1 实施入口、schema 和配置只有在实现及测试完成后才能登记为可执行。本文件不授予真实患者远程模型运行或医生包发放许可。

### 1.2 研究边界

1. 不修改 P1 纳入门槛，不以 P1 PASS、手术执行或候选标签决定患者相关性。
2. 原始临床事实来自对应来源的原文；LLM 分类、审核意见和程序标签均不替换原文。
3. 不把资料缺失、无法判断或程序未识别自动改写成阴性；局部材料问题不自动排除患者。
4. 不将 LLM 材料审核称为独立人工审核，不将自动 `PASS` 称为临床正确、真实资料完整或专家已接受。
5. 临床 Mode/action、Q1—Q5、人员、盲法和 Reference 分歧规则继续等待 D01—D11 临床团队冻结。
6. 医生文件不包含被遮原文、未来 Checkpoint、研究者全量资源、模型提案或绕回原文的链接。

## 2. 当前缺口与 v0.6.1 目标

### 2.1 v0.6.0 尚未闭合的环节

当前流程主要让 discovery LLM 提议 `choice_boundary_quotes`、`prechoice_facts` 和 `postchoice_facts`，程序精确定位后组织证据池；材料桥接将已定位的决策／结果区间标为 MASK，其余大部分保留 REVIEW。引文机械通过不证明语义边界完整，也没有 LLM 阅读“实际拟呈现给医生的完整材料”后执行跨文书补遮、补资料和边界修订的闭环。

现有一次 discovery／review 反馈只处理相应阶段的特定错误，**不能替代材料审核循环**。人工工作台能够回收修订，但不会自动执行修订、重编和复审。

### 2.2 目标结果

```text
v0.6.0 候选事件／关系／Episode
        ↓
程序组织目标 Checkpoint 的候选完整来源范围
        ↓
初始 SourceManifest＋SplitProposal＋CompiledPartition
        ↓
材料审核 LLM 阅读研究者侧完整原文和医生视图预览
        ↓
结构化审核意见＋逐字引文支持的修订操作
        ↓
程序核验操作、生成新 manifest／分区及操作账本
        ↓
对新的内容 hash 复审；通过、保留未决或停止于预算
        ↓
版本化候选 Episode／Checkpoint 材料包
        ↓
独立人工分层抽样验证自动材料质量
        ↓
满足冻结门槛且临床表单／分配规则齐备后，送医生试评／盲评
```

交付对象不是单个模型分数，而是：

- 每个目标 Checkpoint 的来源范围、原文分区、医生视图和审核链；
- 候选 Episode 内各 Checkpoint 的引用、版本和相邻关系；
- 每次审核的发现、修订、重编和停止原因；
- 自动材料包状态与真实人工／专家状态的明确分离；
- 可重复的人工抽样、比较和统计验收接口。

## 3. 核心设计：审核完整呈现，而非只看模型引文

### 3.1 材料审核 LLM 的两份对齐视图

每次审核请求对同一 `compiled_sha256` 提供：

1. **研究者完整原文视图**：本任务纳入来源的完整原文、来源 ID、字符坐标、时间和版本信息，以及已加载的候选补充来源。审核者可以据此发现遗漏和跨文书回述。
2. **医生视图预览**：仅由当前 KEEP 原文按来源组成，MASK 以中性占位表示，REVIEW 不默认开放。预览必须使用与最终医生包相同的投影代码，防止审核一个视图、医生收到另一个视图。

还需提供中性任务说明、目标 Checkpoint ID、决策时间证据及不确定项、候选 Episode 内必要的顺序信息。模型原 `action`、`checkpoint` 等标签仅供研究者追溯，不能被写成医生任务提示或临床答案。

### 3.2 不把“两轮之间”简单理解为字符切片

两个临床决策事件之间的证据可能来自：

- 前一事件之后、当前事件之前形成或报告的新资料；
- 当前文书中对既往状态、检查结果或治疗反应的引用；
- 术中探查等同一文书内的阶段信息；
- 既往文书中已经记载、当前被重新解释的信息；
- 时间不明但可能相关的来源，必须保留待核而非强行排序。

v0.6.1 不以“当前时间减前次时间”的唯一规则自动决定临床可见性，也不只发送两个事件之间的模型摘录。程序先按 v0.6.0 的来源、时间和事件边界形成候选范围，再由材料审核 LLM 对完整来源提出必要补充、排除或保留未决。每次范围扩展必须显式记录依据；没有证据时不得用后续结局改写早期状态。

### 3.3 审核维度

材料审核 LLM 至少逐项回答：

- **范围**：是否缺少支持当前任务评价的必要已交付资料；排除来源是否含必要信息。
- **事件目标**：本包是否混入其他 Checkpoint 的目标答案；候选 Episode 顺序是否导致未来资料进入当前包。
- **决策遮蔽**：目标临床决策、同义回述、实际执行、反应和结局是否在标题、正文、字段或另一份文书中泄漏。
- **证据保留**：是否误删当前判断前可用的解剖、生物学、患者条件及其他任务相关资料。
- **边界语义**：KEEP／MASK 是否切断条件、对象、否定、时间或测量语境，是否错误拼接非连续文字。
- **时间与来源**：实际选择时间、代理时钟、报告版本、引用原报告缺口及可见性是否被过度声称。
- **可评价性**：资料不足、矛盾或不确定是否仍可送专家判断，还是本版本必须保留未决／修订。

## 4. 审核者与修订权限

### 4.1 与发现／复核 LLM 分开

材料审核使用独立请求、独立 schema 和独立审计记录。应支持配置与 discovery／review 不同的模型或独立上下文；“不同模型”不自动证明临床独立性，也不消除系统性遗漏。初版至少提供“不复用发现／复核对话状态”的材料审核请求。

发现／复核的一次反馈预算不因本计划自动增加。材料审核的迭代预算单独配置、单独记账，不反复改写原模型提案。

### 4.2 LLM 提议、程序执行

LLM 不自行编写患者原文、不直接覆盖 JSON 文件、不手工数字符。所有临床文字修订必须由逐字引文或程序已核验 anchor 定位。

建议新增 `MaterialReview` 与 `MaterialRevisionPlan` 对象，字段在实施时版本化，至少包含：

- `review_id`、`target`、`manifest_sha256`、`compiled_sha256`；
- 审核协议、模型／参数、实际请求／响应 hash、代码和来源绑定；
- 各来源覆盖结论、各审核维度结论、原文依据和未决问题；
- `operations[]`、总体状态、必需后续动作；
- 对原提案的保留，不以修订后状态覆盖初稿。

建议操作集合：

| 操作 | 作用 | 必要约束 |
|---|---|---|
| `SET_DISPOSITION` | 将明确原文字符区间设为 KEEP／MASK／REVIEW | 绑定原文 hash、anchor 和理由；未知默认不开放 |
| `SPLIT_SPAN` | 在已有区间中分离条件、观察、目标决策或结果 | 逐字边界定位；不得改变原文 |
| `INCLUDE_SOURCE` | 将明确来源纳入新候选材料范围 | 完整原文已提供；记录必要性和时点依据 |
| `EXCLUDE_SOURCE` | 从新候选范围排除具体来源 | 记录理由，不推断该来源临床无关 |
| `MARK_SOURCE_UNRESOLVED` | 保留具体来源缺口、多义或待核 | 不等于患者未做检查或医院没有报告 |
| `FLAG_EVENT_GRAPH_ISSUE` | 报告事件粒度、身份、前轮、过程或顺序问题 | 退回重建层，不在材料层直接改图 |
| `REQUEST_HUMAN_REVIEW` | 请求实际人员处理高风险或反复未决问题 | 记录具体原因，不自动形成人工任务完成 |
| `HOLD_PACKET` | 保留本 Checkpoint 不发放 | 局部保留，不自动否决患者其他 Checkpoint |

`INCLUDE_SOURCE`／`EXCLUDE_SOURCE` 必须生成新 manifest 和新分区；任何操作生成的新 `compiled_sha256` 都使旧审核不能许可新版本。

## 5. 重编、复审与停止规则

### 5.1 每轮确定性流程

```text
审核输入 hash 核验
→ LLM 输出 schema／引文／坐标／来源许可核验
→ 程序生成 MaterialRevisionPlan
→ 编译新 manifest／partition
→ 机械完整性核验和输入／输出 diff
→ 保存本轮审核与操作账本
→ 若修订被采用，则针对新 hash 开启下一轮审核
```

机械核验至少覆盖：完整互斥分区、Unicode code point、CRLF 保留、重复引文、多义 anchor、非法来源、REVIEW 默认不开放、医生视图无被遮原文、跨端投影一致、hash 漂移及新旧产物保留。

### 5.2 状态分离

建议区分：

- `AUTO_REVIEW_PASS`：自动材料审核在指定输入、协议和预算内未发现阻断项；
- `AUTO_REVIEW_REVISE`：存在可执行修订，尚未完成新版本复审；
- `AUTO_REVIEW_HOLD`：存在未决、缺来源、图问题或预算停止，不可自动发放；
- `HUMAN_SAMPLE_ACCEPT／REVISE／UNRESOLVED`：实际人员对抽样材料的独立评价；
- `CLINICAL_PACKET_ELIGIBLE`：满足冻结的自动门槛、所需人工／临床方案和分配条件，可创建医生包；
- `EXPERT_VALID／EXPERT_HOLD`：医生对实际收到包的独立评价。

自动审核状态不能冒充既有 `SemanticAudit.reviewer_type=human` 或 `independence_attested=true`。实施时决定扩展审核 schema 还是另建自动审核对象；不得改变旧 0.2.0 对象的历史含义。

### 5.3 迭代不是无限自我确认

材料审核迭代预算需通过开发实验确定，不沿用“一次一定最好”的假设。每轮必须有新的编译对象和具体修订依据。以下情形停止并 HOLD：

- 达到版本化预算仍有阻断问题；
- 新旧分区反复回摆或出现无实质变化的修订；
- LLM 提议无法定位、来源越权、操作冲突或预算不足；
- 材料问题实际要求修改事件图；
- 必要来源未提供，不能支持声称范围完整；
- 自动审核结果内部矛盾，不能可靠生成下一版。

收敛、最大轮数、模型调用预算和人工升级条件均写入运行回执。没有后续修订时不为“再确认一次”强制调用模型。

## 6. Episode／Checkpoint 版本化交付

### 6.1 包结构

以候选 Episode 为组织容器、以 Checkpoint 为独立资料许可单位：

```text
CandidateEpisodeMaterialSet
├─ episode_reference：只引用既有候选 Episode，不自动确认临床边界
├─ checkpoint_materials[]
│  ├─ checkpoint_id／event_reference
│  ├─ source_manifest／compiled_partition
│  ├─ auto_review_chain／revision_ledger
│  ├─ doctor_view_projection／content_hash
│  └─ state／open_issues／required_actions
├─ cross_checkpoint_checks
└─ set_version／code／protocol／input_hashes
```

同一来源可在不同 Checkpoint 中有不同 KEEP／MASK 资格，不能形成全患者永久遮蔽。当前 Checkpoint 的材料包不得因为属于同一 Episode 而自动包含后续 Checkpoint 内容。

### 6.2 事件图问题的回路

如果材料审核发现遗漏事件、同一事件误拆、跨事件误并或顺序错误：

1. 在当前包记录 `FLAG_EVENT_GRAPH_ISSUE` 并 HOLD；
2. 回到明确的重建修订接口，由相应 LLM／程序生成新候选事件或关系；
3. 重新运行必要的最终关系依赖审计；
4. 生成新的候选 Episode／Checkpoint 版本和材料范围；
5. 从头执行材料审核，不沿用旧图的材料 PASS。

这会单独登记为“候选重建修订”，不能与“同一事件的 KEEP／MASK 修订”混为一类。

## 7. 人工抽样验证与自动化放行门槛

### 7.1 人工不再逐段审核全队列

人工评价对象应是**冻结自动管线最终输出的完整 Checkpoint 材料包**，同时按抽样方案检查来源覆盖和跨文书泄漏。人工可查看研究者完整来源及模型操作链，但首轮语义评价不能被自动结论替代。评价维度至少包括必要资料遗漏、目标答案泄漏、合法证据误删、时点错误、错误拼接及可评价性。

现有 353 段／三份任务可作为开发与流程测试材料，但不自动构成有代表性的验收样本；现有八项 Phase A 任务继续用于独立原文重建，不转换成医生材料审核结果。

### 7.2 预注册抽样与指标

正式验收前冻结：

- 抽样总体、版本、随机种子、样本量和分层；
- 术前／术中、起始锚点／新证据、支持文书、零发现、被拒提案、缺来源、不同模型与复杂长文书等覆盖；
- 以来源、区间、Checkpoint、Episode 或患者为何种评价单位；
- 严重目标答案泄漏、关键资料遗漏与一般边界问题的定义和严重性；
- 自动通过与人工复核的一致性、各类缺陷率及相应置信区间；
- 关键缺陷的容许上限、未决如何处理、失败后的扩容或全量复核触发规则；
- 独立性、接触史、双人复核及裁定规则。

**本计划不擅自预填合格率数值。**关键泄漏通常需要比普通格式缺陷更严格的门槛，但最终界值和统计设计须由研究团队预先批准，不能看到结果后选择有利指标。

### 7.3 门槛后的适用范围

只有冻结的代码、模型、提示、来源范围、材料协议和抽样总体均一致时，验收结论才支持未抽中病例沿该自动管线进入后续医生评审。下列变化需要影响评估，必要时重新抽样：

- 材料审核模型、提示或操作语义变化；
- 来源路由、时间边界、Episode／Checkpoint 规则变化；
- 编译器、医生投影或遮蔽策略变化；
- 新人群、新文书类型或来源质量分布超出验收范围。

抽样验收不证明每份材料都正确。专家在实际评审中始终可以 `EXPERT_HOLD`，记录泄漏、资料不足或无法评价；该意见按临床方案进入修订和重新盲评流程，不强迫生成 Mode/action Reference。

## 8. 实施批次

### A：冻结 v0.6.1 接口与失败基线

- 固定 v0.6.0 输入及旧产物保护清单；另建 v0.6.1 输出命名空间。
- 写 `MaterialReview`、`MaterialRevisionPlan`、操作账本和 Episode 材料集 schema。
- 登记稳定问题编号，先保存当前缺口的虚构反例：边界过窄／过宽、跨文书答案回述、未来 Checkpoint 泄漏、误删否定／条件、相邻 Checkpoint 资料错配、来源范围改变后沿用旧审核等。
- 明确本版不改 P1，不自动启动真实远程模型。

**验收**：schema 独立校验；所有反例能定位到原对象和预期拒绝／修订行为；旧产物 hash 不变。

### B：实现材料审核与确定性修订执行器

- 建立研究者全文＋实际医生视图预览的请求适配器。
- 实现 LLM 审核输出核验、操作计划、来源重编、区间重编、diff 和追加式账本。
- 实现 `AUTO_REVIEW_*` 状态、HOLD、预算和人工升级；不生成临床 Reference。
- 用虚构资料验证多轮修订、无变化停止、回摆停止、越权拒绝及每版重新审核。

**验收**：旧实现上的失败反例被阻断；合法 KEEP、合法既往计划保留、无法判断保留等正对照通过；任何自动状态均不能伪装独立人工 PASS。

### C：接入候选 Episode／Checkpoint 和既有工作台

- 从真实候选事件构造材料审核任务，保存 Episode 内顺序及跨 Checkpoint 检查。
- 图问题退回重建层，重跑必要的关系审计后重新准备材料。
- 既有研究者 HTML 增加自动意见、操作历史和新旧版本对照；人工可以另存判断，不自动替人点击通过。
- 只有满足冻结许可条件时，才复用既有 FHIR／HTML 生成医生包；自动审核草稿不能直接进入医生 HTML。

**验收**：同一源文在不同 Checkpoint 中可分别许可；后续 Checkpoint 不进入当前医生文件；修订前后 hash 绑定正确；跨语言回收结果一致。

### D：开发运行与独立人工抽样验证

- 先在小批开发材料执行固定版本自动审核，记录模型调用、成功率、修订分布、HOLD 原因、人工升级和实际成本。
- 独立人员按预注册方案评价最终完整包，而不是只检查模型已标出的区间。
- 分别报告自动材料质量、候选重建语义和临床 Reference；不能用区间数或候选数下降代替准确性。

**验收**：有人工实际回收分母和置信区间；未回收仍为 `not_measured`；关键失败有逐例原文依据和版本定位。

### E：冻结适用版本并开展医生试评

- 只有材料验收、D01—D11 适用决定、问卷和分配／盲法规则均满足后，才开放真实医生包。
- 小规模试评检查任务理解、选项覆盖、泄漏／缺资料保留和意见回收。
- 按冻结方案开展正式独立盲评，保留专家 HOLD、修订后新版本和重新盲评。

**验收**：真实分配及响应绑定 Checkpoint、包版本／hash、表单版本／hash；专家原始意见与后续 Reference 分离。
