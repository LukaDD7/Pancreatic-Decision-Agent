2026-10-21｜基线 v0.3：`e689ebc`｜本版标签：`p1-relevance-usability-v0.3.1-20261021`

本版补齐已知问题的测试和提交流程保护，并修复补测发现的遗漏。P1 定义、P2 边界和医生盲评 Reference 不变；原始记录、旧实现和旧队列保持快照。

## 1. 上轮与本轮变更各是什么

| 版本 | 变更 | 原因 |
|---|---|---|
| v0.2 → v0.3，已提交 e689ebc | 从完整影像模板门槛改为研究相关性＋记录可用性；局部 QC 不否决患者，不默认限制 P2；新增来源与引用索引 | 落实已确认研究原则，避免字段不全和临床不确定性成为患者排除理由 |
| v0.3 → v0.3.1，本轮 | 补充测试、已知问题清单、提交保护；修复下表3处解析/覆盖遗漏 | 不能仅凭少数测试通过就声称所有已知问题已受保护 |

v0.3.1 的功能性修改：

| 问题 | 原行为 | 新行为及原因 |
|---|---|---|
| 模板省略重复病灶名 | “肿块评估：低密度…位于胰头”可能未命中目标语境 | 在有边界的肿块评估段内识别部位＋实质描述；不能借用下一节的胰腺词。对应 R08 |
| 分支描述误填主干 | 汇总栏的“SMV无累及空肠支”在遮罩分支后变空，空汇总又误生成主干接触 | 区分真正空列表项与被分支遮罩后的空值；后者不能填主干。对应 R02 |
| 叙述性转移信息未进入B覆盖 | 原文已保存“肝脏及腹膜未见转移”，但B检出仍可为否 | 明确目标器官＋转移/种植/播散的叙述也计入B覆盖；含阴性和不确定性，不生成阳性GT。对应 W10 |

配置正则经过实际加载、JSON往返和 CA19-9/ECOG 匹配验证，未发现多转义问题，因此没有修改其匹配逻辑。新增的是防回归测试 R11。

## 5. 如何防止以后再次漏测

统一入口：

```bash
/opt/anaconda3/bin/python3.12 scripts/cohort_construction/p1_source_quality/regression_guard/run_checks.py
```

入口先检查稳定编号和必需测试是否存在，再跑当前与历史测试；删掉、改名却未迁移、跳过必需测试都会失败。真实CLI测试使用临时纯合成数据，覆盖来源顺序变化、版本差异与局部质量标记、局部解码失败、原文不写回、输入哈希及全量行数异常时停止发布；不读真实病历。

已在实际使用的独立本地版本库启用 `.githooks/pre-commit`。涉及 P1、保护代码或 AGENTS 的普通提交会自动执行上述检查，失败则阻止提交；相关工作区与暂存内容不一致时也拒绝，防止测试的是未提交代码。新版本还必须切换 active release，不能用旧版本通过的测试替代。原项目旧 `.git` 没有覆盖或重设。

还在临时副本中分别恢复前置否定、模板省略、分支/主干、叙述性B覆盖这4个错误，4次都被对应测试以断言失败拦住；实际生产文件未被改动。这证明关键测试能够捕获这些错误的再引入，不代表可以消除所有未来歧义。

测试与核验回执：

- `receipts/p1_regression_guard_v0.3.1-tests.txt`：105项测试原始日志。
- `receipts/p1_regression_guard_v0.3.1_20261021.json`：问题覆盖与测试汇总。
- `receipts/p1_regression_mutations_v0.3.1_20261021.json`：4次错误再引入验证。
- `receipts/p1_relevance_usability_v0.3.1_20261021.json`：实际全量运行的坐标、覆盖与输出哈希。

新增已知错误时，先给稳定编号并写失败反例及必要对照，再修复、补清单、运行统一检查；行为变化须保存旧快照并重跑对比。单纯增加测试数量不算完成回归保护。
