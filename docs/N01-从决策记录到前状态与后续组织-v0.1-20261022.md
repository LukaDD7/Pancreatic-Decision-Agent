# N01：从一条决策记录，落实前状态与“然后呢”

2026-10-22，单病例组织草稿 v0.1。只处理已找到的节点，不增加全队列检索规则，不认证临床Reference，也不预先确定完整episode边界。

## 1. 先纠正上一轮解释中的缺口

上一轮核对到了“引流—条件改善—后续手术安排”，但未把首次操作及管道脱出纳入N01解释。完整源文书现在支持：较早已有一次PTCD；次日管脱出，安排择期再次PTCD；目标查房记录对应再次处理前的安排。两份操作记录明确写了不同操作日期，原始报告入口也有相应两次置管来源，不能只按相似句子把它们视为同一次计划复现。

因此，目标记录可以作为候选checkpoint，但其问题是**此前引流失效后，当前怎样处理梗阻、是否以及何时继续根治切除路径**，不是首次决定是否引流。

## 2. 前一份和后一份究竟是什么

下表日期均指正文所写事件/记录头；原文、系统时间和来源键在私有审计材料中。没有把所有时间统一成已验证的临床可见时刻。

| 位置 | 文书或资料 | 本例中的作用 |
|---|---|---|
| 较早背景 | 首次置管的有创操作记录 | 证明病历曾记录一次引流实施；不是把计划当执行 |
| **前一份临床文书** | **术后第一天病程记录** | 写明管道脱出、无引流，移除管道并计划择期再次处理；是理解目标节点的关键历史 |
| 中间新增证据 | 之后报告的肝功能原始检验 | 胆红素进一步升高，构成当次重新确认管理安排前的新信息；不能只给前一份病程而遗漏检验 |
| **目标记录** | **刘文宇副主任医师查房记录** | 当次 observations 后，写出再次PTCD、等待条件达到后手术的安排 |
| **后一份临床文书** | **同日有创操作记录** | 记录再次置管实施，是执行，不是新的术前状态 |
| 下一份状态反馈 | 次日术后第一天病程记录 | 写管道在位和引流状况；同文存在引流量与“无引流液流出”的不一致，要保留待核 |
| 之后的新检验 | 后续肝功能原始结果 | 反映处理后胆红素变化，不能倒放进目标节点 |
| 下一次明确改变管理的记录 | 之后的术后病程记录 | 引流仍不足，虽有指标下降但尚未达到要求，改用ERCP并继续等待手术条件 |

所以“后一份文书”“下一份新状态”“下一次管理改变”是三个不同角色。它们可以帮助组织同一问题的后续，不能默认每份都是一个独立决策点。

## 3. Agent的前状态：不只是前一份文书

本例已生成一个**按正文时序重建的展示草稿**。对假设评价时点之前的资料按来源分块给出：

1. 入院记录、首次病程及较早查房：原先的病变、症状、患者情况和评估背景。
2. 较早MR、CT的完整原始报告：保留两个来源的血管和其他发现差异，不自动判定可切除性、不代替医生形成Reference。
3. 首次PTCD的实施记录和管道脱出的病程：历史操作及反馈属于当前状态的一部分。
4. 时点前已报告的全部原始检验字段：本次共138条，不只挑胆红素；原始结果、单位、参考值、报告时间按来源呈现，不把“已复”等原文改成程序猜测值。
5. 当前查房中**决策之前的观察内容**：保留体征、辅助检查、诊断和指标描述；从当次动作“今予PTCD”开始隔离其后选择，不把它作为Agent应接受的答案。

目前为七个临床文书块（六个既往、一个当前前缀）、两个影像报告块和138条时点前报告的检验结果。它们不是一篇由程序改写的病情摘要。源原文不改，身份信息仅在展示副本遮蔽，源坐标和哈希留在研究者材料中。

输入问题应围绕研究目标，例如：

> 截至这些资料，当前根治性切除路径应如何管理？下一步应处理或核实什么，什么变化会触发重新评估？

不能把“医生选择PTCD，所以正确答案是PTCD”写入提示词。医生真实选择只用于定位和来源审计，不是可接受动作集合。

## 4. 哪些内容此刻不能给

- 目标文书中的当次引流决定和附带的当前手术安排；
- 同日稍后再次置管的操作结果；
- 之后的引流量、指标变化、ERCP决定和后来的切除计划；
- 后来确诊的病理、术后大小、最终治疗结局，以及P0入队确认字段。

过去文书已写过“择期再次PTCD”的计划，则不能为了让模型重新猜答案而悄悄删掉：它在假设的较晚节点是合法历史。**若研究的是首次提出再次引流的选择，候选点应前移到管道脱出后的那份病程；若研究的是后续新状态下继续还是改变原计划，目标查房可以作为再评价/执行前的候选点。**两种任务不要混为“首次决策”。

## 5. 时间问题怎样落实，而不是泛泛警告

该病例若按正文重建，临床记录顺序与目标记录附近的系统创建顺序恰好给出相同的前后邻接文书。但正文日期与系统创建日期并不一致：两份既往操作/病程和目标查房本身都较晚创建。

因此，本轮草稿选择**公开声明按正文时序重建**，并逐来源记录以下信息：

- 正文描述何时的事件；
- 源系统记录何时创建；
- 检验何时报告；
- 影像只有检查时间，签发/阅片何时仍不明。

这已经能够检查“前状态需要哪些来源”“是否混入当次选择或未来反馈”。但在缺少文书版本、签名/补记及报告可见性证据时，不能宣称草稿完全复现了医生当时真实看到的界面。创建晚不证明此前临床不知道；创建早也不保证最终导出文本从未改过。私有审计逐项标记，不伪造单一真时间，也不因此排除患者。

## 6. 对“定位—组织”的思路修正

上一轮方法主要完成候选检索；它不足以单独形成可实施的episode组织。这个病例提示一种值得验证的组织方向：**在episode内跟踪持续未解决的临床问题，把每次可观察状态、当次安排、执行与后续反馈分别挂到来源记录上。**

N01的这条问题是“梗阻/黄疸尚未改善到可以推进切除的状态”。它可经历一次处理失效、再次处理和再评价。它并不替代肿瘤分期、解剖关系等其他并行问题，也不意味着整个episode只剩黄疸。

工作次序可简化为：

```text
已定位的判断/安排句
    → 在同一来源内隔离当次动作，保留其前观察
    → 回取此前病变背景、已执行处理、反馈和时点前结果
    → 形成带来源和时间依据的前状态草稿
    → 向后分别找执行、新观察、下一次安排
    → 判断哪些是计划复现、执行或真正需要再次评价的候选点
```

这是一种组织假设，不声称它是指南定义或已经证明的新方法。本例先把一条实际记录落实成可检查的资料分包，比继续扩展病因词表更接近当前“定位—组织”的问题。

## 7. 可查看的交付物与版本

私有输出：`private/n01_checkpoint_casebook_v0.1_20261022/`（项目镜像）。

- `N01-决策前资料草稿.md` / `agent_state_reconstruction.json`：按来源分块的前状态；
- `N01-当次选择与后续-研究者查看.md` / `reviewer_only_followup.json`：当次完整记录及之后执行、反馈、再安排；
- `reviewer_source_audit.json`：原文、切分坐标、全部临床文书目录、影像来源、检验逐行纳入/排除及时间审计；
- `build_receipt.json`：输入、代码、输出哈希，以及可见性尚未认证的状态。

程序：`scripts/cohort_construction/p2_checkpoint_casebook/`。八项合成测试与病例构建断言验证时间精度、未来检验排除、当次动作切分、原始结果保留、展示遮蔽和字段隔离。没有把任何患者资料发给模型，也没有生成临床Reference。

本轮不改P0/P1成员、不改旧检索统计、不改episode正式边界及研究方案。与上一轮的差异是：N01被明确为首次置管失效后的后续管理情境，并实际落实了一个前状态草稿及分开的后续材料。
