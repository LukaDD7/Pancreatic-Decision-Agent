## 4. 许可前依赖与实施顺序

1. 临床团队解决 D01–D11 中适用于本轮任务的条目。若某项不适用，记录明确理由和适用范围，不用留空代表通过。将最终方案、Mode／动作字典、问卷及分歧规则分别版本化并保存hash。
2. 依审定内容生成外部冻结 `Questionnaire` 与响应 schema，核对多选、逐动作不确定项、条件题、停止评分及原始意见保存。`FrozenQuestionnaire` 的 `canonical/version/sha256/frozen/resource` 只绑定内容；`frozen=true`本身不证明临床团队已批准，应另存实际批准回执。
3. 实际独立材料审核者另行完成目标 Checkpoint 的逐区间审核、来源覆盖、跨文书目标临床决策回述和时间证据。三份既有任务的353区间仍未决；材料审核完成与临床方案冻结互不替代。
4. 当前分区须真实独立语义 PASS、审核范围完整、无 REVIEW、无待执行 REVISE、来源纳入／排除结论与当前分区一致、无未决来源覆盖及阻断问题。区间修订须另存新版、重新编译、审核新hash；来源范围修订须明确建立新manifest／分区并重新审核，保留旧材料和旧审核。`REQUIRED_MISSING`／`DELIVERY_NOT_FOUND`记录具体来源缺口，不自动表示改变来源范围或排除患者。
5. 同时具备上述材料结论、适用的冻结问卷及分配／盲法规则后，才创建真实患者医生许可包。评审响应须绑定 Checkpoint、包版本／hash、表单版本／hash及分配ID，并按方案回收到台账。

工程校验不能认证人员身份、实际独立性或临床正确性。材料审核者可能接触实际临床管理措施及未来信息，其研究者 HTML 不能用作医生盲评文件；独立原文重建工具也不能提前显示模型候选来代替独立发现。

## 5. 与本轮工程准备的衔接

- 独立原文验证可以先准备同范围、同hash的双人空白材料及比较工具；应明确属于已用开发材料还是锁定独立验证。模型候选、抽样理由、另一人的结果和临床 Reference 均留在研究者侧。准备材料不计为完成独立验证。
