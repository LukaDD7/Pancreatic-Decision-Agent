# P2：先定位当前切除评估事件，再组织 Episode

2026-10-20｜规则草案 v0.1｜未改变 P1 队列，未认证正式 P2 决策点。

## 1. 这一步实际要识别什么

病历不能证明医生何时“开始思考”。本研究先识别**有原文依据的临床评估事件**：在一次当前诊疗情境中，临床团队针对当前目标胰腺病变，评估、选择或明确启动评估“是否推进根治性切除路径”。

必须分开记录两个问题：

1. **事件存在性**：原文是否记录了针对当前目标病变的评估/选择？
2. **事件时间**：该判断发生于何时，能否据此建立信息快照？

事件明确但时点不明时，保留候选并标记时间待核，不能简单归为“没有决策”。事后病程回述一项明确的旧判断，也只证明有历史评估；不能把回述文书日期当成旧判断日期，更不能把其邻近活检日期自动当成评估日期。

## 2. 本次重新探查到的数据规律

沿用上一轮已冻结的 30 人便利样本，重新检查 878 条相关文书，不是新增样本或全队列验证；此前原始临床文件 265 个中仅 10 个本地可读的限制仍适用。

| 原文模式 | 命中文书 / 患者 | 对规则的意义 |
|---|---:|---|
| “可切除、不可切除、切除性、局部进展”等预定义词 | 0 / 0 | 不能仅依赖标准分期术语；此结果不代表全队列不用这些词 |
| “有手术指征／存在手术指征／手术指征明确” | 4 / 2 | 是评估候选；仍要核对当前病变与所指手术 |
| 当前根治性胰腺手术计划的模式 | 53 / 18 | “拟行胰体癌根治术”等是重要补充信号；不是已经确认 53 个新决策 |
| “考虑当时无手术指征” | 12 / 2 | 同一历史判断可重复出现在多篇文书中 |
| “无／未见／排除……手术禁忌” | 226 / 30 | 不能误判为否定手术，也不等于已经评价肿瘤可切除性 |
| 标题含颈椎／颈后路的手术文书 | 4 / 1 | PDAC 患者也有非胰腺手术；患者身份不能代替本次对象识别 |

503 条文书有可解析的正文起始日期，其中 **177 条、27 名患者**与文书记录日不同，既有正文日期早于记录日，也有晚于记录日的情况。它们是时间核查候选，不直接证明某字段错误。不能统一用 `create_time` 排列真实决策先后。

实际原文包括“目前诊断考虑胰头颈癌，侵犯 SMV……有手术指征。建议：手术治疗。”以及治疗计划中的“排除手术禁忌症后拟限期行胰体癌根治术”。前者明确记录当前判断；后者记录当前有条件的根治手术计划，不能因为仍有待完成项目而丢弃。

## 3. 事件标签：不要全部强行叫“明确可切除”

| 标签 | 确认条件 | 不能推断的内容 |
|---|---|---|
| `RESECTABILITY_ASSESSED` | 当前目标病变被明确评价为可/不可/交界可切除，或有明确等价的肿瘤切除可行性判断 | 不能由研究程序仅看血管接触自行推导临床分级 |
| `SURGICAL_CANDIDACY_ASSESSED` | 针对当前目标病变明确判断有/无手术指征、能/不能推进根治手术，包括医学耐受性导致的否定判断 | 不自动等于解剖学可切除性分类 |
| `CURATIVE_PLAN_DOCUMENTED` | 当前治疗计划明确选择胰腺根治性切除路径，允许“排除禁忌后”等条件 | 能证实已记录路径选择，不能证实选择何时首次形成或评估已完成 |
| `RESECTABILITY_ASSESSMENT_REQUESTED` | 当前明确要求外科/MDT 评价能否根治切除，或明确为此追加取证 | 能证实评估任务被启动；不代表已有结论 |

以下仅作为背景或待核：单独增强 CT 结果、单独化疗疗效复查、单独“无手术禁忌”、泛称“拟手术”但对象不明、仅有外科科室/术前讨论标题。

“目前不宜根治切除，先 NAT”是当前评估；“化疗后再看能否手术”单独出现时只表达未来评估意图。若一句同时包含当前否定和未来重评，应分成两个断言，不能整句统一标为未来。

## 4. 三个关键函数必须怎样判

### A. `bind_target()`：这句话针对什么

- 优先绑定同一当前诊断—评估—治疗计划块中的目标病变和拟施术式。
- 明确胰腺根治术、胰十二指肠切除等目标切除路径，可支持当前胰腺病变；仅有泛称术式时不推定。
- ERCP、支架、穿刺、脊柱手术等与“手术”同现，不能当作胰腺根治切除评估；但若同一会诊另外明确讨论能否根治切除，应另抽取该断言。
- “胰腺癌”只在既往史中出现，不能将当前别的手术绑定为胰腺评估。
- 术后局部复发或肝转移灶单独标记对象；是否属于研究目标另核，不混入原发胰腺病变评估，也不据此排除整个患者。
- 无法唯一绑定时返回 `UNKNOWN`，进入待核。

### B. `resolve_role()`：当前、历史还是未来

- “当时、此前、曾经、既往”或明确旧诊疗过程中的判断，标记 `HISTORICAL`。
- 未来条件下才启动的再评估，标记 `FUTURE_ONLY`；当前已选择的有条件根治计划仍是当前路径选择。
- 当前会诊意见、治疗计划、讨论总结等段落中的判断，或明确“目前／此次／现阶段”的判断，且无相反历史证据，标记 `CURRENT`。
- 现病史、病史特点、诊断依据、出院小结可能混合不同时间的内容；标题及一个“目前”不能替代逐断言判别。无法解开混合语境时返回 `UNKNOWN`。

段落标题和引文坐标用于**识别事件**；不意味着可以把拆出的片段前置为模型输入。

### C. `resolve_time()`：给哪个时间

同时保留 `assessment_time`、`document_time`、`available_time` 和各自依据/精度：

1. 优先采用明确修饰本次评估的原生会诊、讨论、查房时间等；需核对字段语义和原文。邻近的 CT、活检、手术预约时间不代替评估时间。
2. 若仅有正文文书头日期/时间，须先确认其为本次文书头而非历史事件；与系统记录字段一致可作为文书层锚点候选，仍不自动等于精确评估时刻。
3. 正文头与系统字段冲突时保留两者，`time_status=CONFLICT_REVIEW`，不自动选较早或较晚者。
4. 仅剩 `create_time` 时，只记 `document_time_proxy`，`assessment_time` 保持未知；只有日期则保留日期精度，不补零点。
5. 报告/文书何时对医生可见另存；没有依据时保持未知。时间代理可帮助定位审阅范围，不能直接认证模型信息快照。

## 5. 伪代码

```python
for patient in frozen_P1:
    events = []

    for doc in patient.clinical_records:
        # 本院来源、患者关联、全文 hash、来源键先核对。
        # 标题只用于召回和段落定位，不单凭“术前讨论”确认事件。
        for assertion in extract_candidate_assertions(doc):
            # 召回：切除性判断 / 手术指征 / 根治方案 / 为切除性而取证
            target = bind_target(assertion, current_diagnosis_and_plan(doc))
            role = resolve_role(assertion, section_and_surrounding_clauses(doc))
            kind = match_event_kind(assertion)  # 按上表四类，不推导临床分级

            if role == HISTORICAL:
                save_historical_assessment(assertion)  # 不用本篇日期前填旧事件
                continue
            if role == FUTURE_ONLY:
                save_future_reassessment_intent(assertion)
                continue
            if target == DEFINITELY_OTHER_PROCEDURE:
                save_non_target_decision(assertion)
                continue

            # UNKNOWN 不等于没有评估；原文全部保留。
            if UNKNOWN in (target, role) or kind == GENERIC_SURGERY_UNRESOLVED:
                send_to_review(assertion, reason="对象或当前性未解决")
                continue

            if kind in (IMAGING_FACT_ONLY, FITNESS_ONLY, GENERAL_FOLLOWUP_ONLY):
                save_supporting_context(assertion)
                continue

            if target_matches_study_lesion(target) and role == CURRENT:
                time = resolve_time(assertion, doc)  # 可返回 UNKNOWN / CONFLICT
                events.append({
                    "kind": kind,
                    "target": target,
                    "source_id": doc.source_id,
                    "quote_and_offsets": assertion.evidence,
                    "assessment_time": time.assessment_time,
                    "document_time": time.document_time,
                    "available_time": time.available_time,
                    "time_status": time.status,
                    "event_status": "CANDIDATE_CURRENT_ASSESSMENT",
                })

    for event in events:
        if exact_duplicate_source_or_same_document_version(event):
            link_duplicate(event)  # 来源副本不制造新点
        elif earlier_same_plan_or_quoted_event_exists(event):
            # 相同结论不等于复制；明确再评估即使结论不变仍可成为新事件。
            if explicit_fresh_reassessment(event) or new_evidence_used_in_judgment(event):
                keep_as_reassessment_candidate(event)
            else:
                link_as_continuation_or_send_to_review(event)
        else:
            keep_as_first_observed_assessment_candidate(event)

    # 得到“哪份记录在评价什么、何时评价”的事件表后，再聚合 episode。
    # 对象/任务一致、未有终止、同一评估过程 → 同 episode；
    # 转向 NAT 后新的手术评估 → 新 episode；时间冲突者不能强排先后。
```

`match_event_kind()` 只按上述表中的“明确判断／明确计划／明确评估请求”分类；同一断言包含多种含义时可保留多个标签。不因存在手术记录、最终实际手术或 P1 合格影像而补出此前不存在的评估事件。

## 6. 输出与边界

第一张表应是 `patient × assessment_event`，而非立即生成 `patient × episode`。最低字段为：目标病变、事件类别、当前性、时间及依据、原文出处、重复/延续关联和待核原因。分别计数：明确当前事件候选、历史事件、未来意图、对象待核、时间待核；不能把这些状态混成一个纳入/排除标签。

定位到记录了医生建议的评估文书，不代表该文书可直接喂给模型做独立决策。用于 P3 时还要确定评价发生前的证据边界，隔离目标建议及未来资料；若只能观察到既有方案，则另标方案复核任务。没有发现当前评估原文，只能说“当前交付资料未定位到”，不能断言临床从未评估。

本规则仍是开发草案：正则/段落规则先生成可追溯候选，复杂对象或时间角色需要审阅；不声称已经由代码完整解决临床语义。探查脚本为 `scripts/cohort_construction/probe_decision_anchors_20261020.py`，聚合结果见 `docs/p2-decision-anchor-probe-20261020.json`，患者引文仅保存在忽略的 `local_artifacts/p2_decision_anchor_probe_20261020/`。
