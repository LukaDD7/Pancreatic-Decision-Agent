# P2 重建标注手册 v0.1（试用冻结版）

2026-10-23。适用于首批独立重建标注；不定义正式episode、临床可接受动作或自动通过规则。首次双人试标后如需修改，另开版本并保留迁移与分歧记录。

## 材料与工作顺序

每名标注者仅接收自己的sources.json、原文材料.md及空白annotation.json。读取规定范围内所有文书，不看程序提议、另一位标注者结果或研究者抽样分层。范围内可出现后续轨迹，任务是重建原文记载，不评价治疗是否合理。

先在全文中标节点，再组织事件，最后标边。未命中程序标签不影响标注；没有判断时也明确记录已完成全文检查。需要范围外文书时填写outside_scope_reference_requests，材料扩展后为两名标注者同步登记新范围，不能只向一方补充。

## 原文节点

| 角色 | 操作含义 |
|---|---|
| DecisionMention | 原文中可定位的临床判断、选择、推迟、拒绝、补证据或有条件安排；历史与当前分别标 |
| EvidenceMention | 原文描述的状态、检查结果、观察或所引用证据；不因其支持某结论就自动视为充分证据 |
| ActionMention | 原文支持已执行的行为；计划、建议和条件性操作不能当成已执行 |
| FeedbackMention | 原文记载的治疗/操作后反应、失败、耐受或效果；先标原文表达，再单独判断是否能连接到某项动作 |

同一连续片段可承担多种角色，允许分别建立节点并共享原文。原文引用须逐字连续，不拼接不同句段为新事实。每个节点使用标注者局部ID、kind、anchor.source_id和anchor.quote；无需手算Unicode坐标。程序只定位引用，不生成标签。引用重复则扩展连续原文以唯一定位，不能猜测。

原文明确阳性、明确阴性、无法判断与未提及分别记录。算法未识别属于后续对照结果，不记为患者原始资料差。计划取得、已取得但原报告交付中未找到、只见二手引用，也分别保留来源状态；不能把它们推成阴性。

signature记录management_question、clinical_target、assessment、intended_action、condition、goal、commitment及temporality。每个有值字段保留原文依据；允许不确定或未提及。规范化描述不能补入“为了根治”等原文没有的目标。多动作时另列action_components，记录各成分是选择、维持、取消还是条件性安排，保留各自引用。

## 事件原子性和共指

一次相对统一的临床判断/管理承诺可以包含多个互相依赖的动作成分。“取消旧计划并改用新方案”可能是同一次修订；两个动作不能机械生成两个checkpoint。反之，一句话可回顾上午取消、再叙述下午重新评估后的选择，可能涉及两个事件。

依次核对：管理问题与对象、所针对时点、评估、动作与条件、承诺表达，以及是否有独立再次判断的依据。不要以句号、同日、24/48小时、动作相同或文字复制直接决定event身份。

- same_event：有依据认为不同mention记录同一次判断，不等于“内容相似”。
- different_event：可区分的记载事件；尚不自动具有研究checkpoint资格。
- uncertain atomicity/coreference：原文不足以判定。填写atomicity_notes，列出可行划分与缺少的依据；不强迫合并或拆分。
- first-visible：交付资料内首次可见的判断。不得改称临床首次判断，也不得因没有前项而不标。

每个mention在当前标注方案中映射一个event ID。Decision事件可汇集多个成分或跨文书共指；不同类型节点的事件ID分别使用。无法确定的分组保留候选及说明，裁定前不强制变成完整gold。

## 关系

先确认端点和事件身份，再标关系，支持依据必须说明连接本身。

- reaffirm：不同判断事件、同一管理问题，存在重新评估/新证据后的维持判断；不是仅又写一次相同计划。
- revise：同一管理问题下评估、动作或条件发生修订；不要求原文解释所有新证据来源。
- supersede：另有明确旧计划失效或被替代依据；不因日期更新就选最新为真。
- informs：证据被用于判断。端点各自存在不足以证明此边。
- implemented_by：实际行为落实此前判断，需动作和对象兼容；“已执行某动作”不自动证明执行的是最近计划。
- evaluated_by：反馈针对某次已执行动作；不能仅凭先后顺序推断。
- triggers_reassessment：反馈促成后续判断/重新评估，需相应原文依据。
- unrelated：已核对、管理问题不相干；uncertain表示无法确定。二者与“未标注该pair”分开。

“胆红素从300降至120”首先是观察变化；是否与某次PTCD相关、是否促成下一判断，各自需要依据。共用主题、同患者、相邻时间都不能单独证明因果。

## 独立标注、分歧与裁定

两人先独立完成同一范围，分别保存原始文件hash与版本。分歧记录包含节点遗漏/边界、类型、字段、事件划分、关系、范围不足及原文无法确定，不把所有分歧归为某人错误。

在裁定前计算一致性，并同时列出漏标、增标、拆分和合并数量。实体边界对齐规则在比较前固定；不能为提高一致性而事后挑选匹配。裁定者记录规则和引用，必要时保留unresolved。

只有实际完成双人标注与裁定、明确检查范围完整、记录annotator_ids和adjudicator_id后，才将annotation_status改为ADJUDICATED及complete_within_declared_scope=true。空模板、程序输出、模型一致或研究者挑选的锚点不能充当人工gold。

## 机器接口

编译器将anchor.quote定位到source_id及全文hash，写入patient_uid和[start,end)。输入原文不被修改。事件和边来自人工文件；编译不替人类决定事件划分。

评估器对真实材料要求source_windows范围；标注用source ID和来源hash与给定材料保持一致。mention精确跨度/类型对齐后，事件按mention交集Jaccard做一对一最大匹配，关系标签不参与匹配。手工对齐另记责任人，且只能在同患者、同来源版本、相交原文范围中进行。

scope内完整标注后，缺少的正边按无关系处理；明确uncertain的pair单独待核，不当阴性。跨范围边记录引用请求，不静默删除。假定完整的scope错误会直接影响FP和召回，因此完整性声明必须有实际全文复核依据。
