# P2 v0.2：诊断检查选择与两轮证据演化

本版修订实现约定，不回改标注手册、A/B/C或v0.1.1冻结结果。对应代码为 `scripts/cohort_construction/p2_auto_checkpoint/`，默认配置 `config/p2_auto_checkpoint_v02.json`。输出仍为研究候选。

1. 研究关联：胰腺肿瘤诊断、分期、可切除性、治疗后再评估和相关患者条件管理。尚未决定手术、为判断是否能推进而补充证据、暂缓、最终不推进手术均可相关。实际接受手术、P1状态和结局不能成为门槛。
2. 证据演化：比较两个具体选择之间新增了什么临床证据，以及与本次问题的关系。相同动作可以有新一轮判断；不同动作不能单独证明有演化。首见候选另列，不能伪造前轮。

诊断报告有两种用途：完整报告结果留作检查后的证据；报告表明检查实施过，也提出此前选择做该检查的间接候选。当前适配器覆盖所有 `imaging_all` / FHIR `DiagnosticReport` 来源，不把每一个 `Observation` 检验数值自动扩成一个检查选择。报告没有医嘱时仍提出候选，但不捏造FHIR `ServiceRequest`。

选择时间、实施时间、记录时间和报告签发时间分别保留。选择时间未知时 `decision_clock=null`，检查实施时间只能提供选择时间上界，不能写成精确决策时刻。只按上界筛出的资料不能宣称全部早于真正的选择。

同检查号、时间和检查名称的来源版本共同指向一个报告检查候选，全部原文仍保留。缺检查号时不强制跨源合并。同一已记录检查安排与随后报告是否为同一次选择，仍需原文联系；不能凭同模态自动新增或合并。

本次检查自己的结果及同次报告版本不能进入“选择做本次检查之前”的证据窗口。上一次检查的结果则可以成为上一次选择之后、本次选择之前的新证据；不能因为该结果出现在证明“上一次检查做过”的引用里，就提前算成上次选择前已知的baseline。

历史已做检查不再因 `role=historical_performed_test`、缺明确开单原因或缺精确时刻自动跳过演化判断。同文病史的先前MR→后来PET顺序可提供比较，单独标记为后来回述及相对顺序，不能包装为当时精确计时记录。

第一次LLM：识别该记录如何支持候选、研究关联、管理问题、实际动作和具体缺口。`role`仅描述记录性质，不是CP资格；`selection_reason_known=false`也不是排除条件。

第二次LLM：显式输入 `previous_decision`、`current_decision` 和 `comparison_window`。每个事件包含ID、问题、动作、原句、选择时间、时间上界、检查实施时间及文书时间。直接询问“两次候选决策事件之间是否出现与本次管理问题有关的临床证据演化”。两者的管理任务是否相同、连接是否有原文支持、时间是否只有上界或叙事顺序分别记录。

历史回述先按同文原句先后提出比较对象；其他情况仍以程序最近保留的已定位候选作为比较对象。它可能不是临床真正前轮，提示词必须公开这个限制；`different_task`不能解读成患者没有相关决策。并行管理任务的最佳比较对象尚未验证。

通过schema和逐字引用检查，只证明格式与引用可回溯，不证明模型的医学语义判断正确。报告可见时间仍有代理假设，未完成医生/Agent正式盲评遮蔽，所有输出 `blind_replay_ready=false`。

验证范围：保留迁移44项原有检查并新增16项诊断决策反例，共60项通过。固定10例只重跑规则提取；真实模型核对限于01、06中的3个定向比较，不称完整10例语义重跑或临床验证。详见 `private/p2_auto_checkpoint_v0.2_20261024/`。
