# 决策点输入：当时可见的临床资料

当前输入版本：`clinical-records-v0.2`。研究对象是 LLM/Agent 阅读临床资料后如何判断下一步。输入采用该时点医生可以看到的病历、报告和结果列表；不先由研究者抽取病灶特征、判断是否转移、标注问题域或筛出关键检验。

## 一个 state 的内容

- 病历：保留可用原文，包括病史、用药、查体及已形成的临床记录。混合文书仅移除被评价的治疗决定、后续回填及识别信息；移除范围在本地 provenance 中留痕。
- 影像：一份检查报告作为一份记录，全文按原措辞和顺序保留。不拆成“肿块大小”“血管受侵”“腹膜转移”等特征，不重写影像印象。影像科原有描述和结论属于资料本身。
- 检验：纳入截止边界前全部可用结果，保留项目、原始值、单位、采样/报告时间及源数据异常标记。不能只选 CA199、胆红素等少数指标。没有原始报告号/面板号时，只按日期汇集列表，不能虚构“原始检验单”或正常范围。
- 其他检查与后续观察：若资料中存在且在当前边界内，按原来源呈现；本数据包未提供的资料不能补造。

模型看到的是来源别名、资料名称、来源时间及原文。执行侧另存可用时间判定、审阅标记、动作/观察匹配和去重信息；这些不是临床判断提示。`domain`、`epistemic_status`、研究者提取的 `value`、未覆盖域清单和预先标注的 gap 均不进入资料输入。已有临床记录中的矛盾保留给模型自行识别。

底层 JSON 是文件封装，不是临床特征表。`build_messages` 将资料原文直接排入模型的 user message；`clinical_chart.md` 与该 user message 一致，便于人工核对。原始 schema 仍约束模型输出的 gap 和动作；这些是模型读完资料后的判断，不能预填到 D0。

## 决策点定义

先指定待评价的临床选择，再确定当时可见的资料范围：

1. D0 是本次处置/根治路径选择之前的资料快照，问题保持中性：“此时下一步如何处理，是否可以进入根治性切除，是否还需检查或讨论？”
2. D1 是有临床意义的新资料可见、需要重新决定下一步的时刻。一次检查可以带来整份新报告或多项检验结果，不等于拆出的每个发现都要建立一个节点。
3. 后续节点按同一原则产生。当前原始输出 contract 只支持最多两次追加取证；这是初版实现的上限，不是所有患者必须经历的三阶段临床流程。

关键节点可以预先选定，比较模型面对同一资料包时如何决策。应区分两种实验：

- **固定节点决策测试**：研究者在预先定义的 D0/D1 分别给模型完整的当时资料，测试判断及更新。若 D1 是既定真实轨迹上的观察，只能证明该节点判断表现。
- **行动条件下回放**：只有模型选择的取证动作能匹配到真实有效的记录时，状态机才揭示该结果。不匹配即停止，不能用患者后来实际做过的检查替代模型所选检查。

## 时间与信息边界

“原文保留”不能等同于“整份出院后整合包直接输入”。同一份入院记录可能混入后续最后诊断；文书创建时间也不保证所有段落在该时点已可见。无法恢复历史版本时，必须标记为候选回顾性重建，并在正式评价前审阅。可用时间代理留在执行与审阅记录中，不向模型额外提示哪个临床问题应当可疑。

当前只呈现数据包实际提供的文本资料，尚未恢复完整 EHR 界面、原始影像或数据包外的检查。更接近真实资料呈现不等于已证明复原了医生全部所见。
