# P1 规则对抗审计：研究相关性与记录可用性

2026-10-21｜审计 v0.1｜对象：已冻结的 P1 source-quality v0.2

**结论：当前 P1 将“符合完整影像模板”设成了主要通过条件，与现在明确的“研究相关性＋记录可用性”存在偏差。需要调整筛选设计，也有必须修正的解析错误。** 本次完成代码审查、12 个合成反例复现和冻结结果的规则覆盖统计；未实现新版筛选器，未更改患者成员、原始文字或 P2 结果。

## 1. 审计依据和边界

当前目标是：在已交付 PDAC 人群中，识别具有本研究相关、可读取和回溯记录的患者；缺失、尚未完成检查、无法明确判断，都不自动等于资料不可用。P1 不能提前要求某个决策点证据完整。

ABC 指解剖学、生物学、患者条件三个临床维度。原方案已经采用这个框架，出处为 [IAP 国际共识原文](https://www.ahpba.org/wp-content/uploads/2021/05/International-Consensus-ABC-PDAC.pdf)，另见 [PubMed](https://pubmed.ncbi.nlm.nih.gov/29191513/)。**共识中的临床分层标准不是本研究的数据完整性纳入标准**；本报告提出的缺失处理、队列分流和来源核验办法，是研究设计建议。

本次核对的方案已移动到 `研究方案/v0.2/研究方案-v0.2-manuscript.md`。其中 P1 仍写“是否进入手术评估”，尚未与最近讨论同步。方案正文及 Confidence 本次均未修改。

原始文字继续保留。以下“识别、标记、关联”仅生成检索和审计索引，不替换原文，不把不同记录合成为供 Agent 使用的新临床事实。

## 2. 代码现在实际在做什么

```text
报告通过 = 来源核验成功 AND 检查日期明确 AND 腹部/胰腺增强CT或MR
           AND 胰腺病变语境 AND 部位有表征 AND 尺寸有表征
           AND 五血管逐项有表征 AND 转移域有表征
           AND 没有命中预设冲突 AND 没有命中术后字样

患者通过 = 身份索引通过 AND 至少一条规则命中的临床文书
           AND 至少一份上述通过报告 AND 没有影像读取错误
```

实现位置：`p1_quality_v0.2/quality_rules.json`；`report_parser.py:168–236`；`run_quality.py:16–24, 96–115, 167–179`。本报告行号以审计 JSON 记录的代码哈希为准。

这不是 ABC 的可得性画像：B、C 没有专门检查；影像 A 则设置了很高的完整性门槛。多个条件必须在同一报告满足，也压缩了证据逐步收集的真实过程。

## 3. 优先修改的设计问题

| 编号 | 现有代码/规则 | 会造成什么错误 | 应怎样改正 |
|---|---|---|---|
| D1 | 五血管、尺寸和转移域缺一即报告 REVIEW；`evaluate_report:223–233` | 部分但真实的可切除性信息被挡在自动通过之外；队列偏向模板齐全的检查。B、C 的缺失却完全未检查 | 将 ABC 各字段的覆盖状态独立输出；取消五血管全齐、尺寸必有、转移模板必有这一组合门槛。不要改成 ABC 全齐，也不要简单用任意一个关键词放行 |
| D2 | `parse_report:196–198` 主要认“远处转移：”“肝脏病变：”等冒号字段 | 叙述性“肝脏及腹膜未见转移”被判为没有表征；格式差异成为队列差异 | 模板和叙述两条识别路径都保留证据位置；程序未识别与原文确实未提及分开标记，不据未命中直接判断临床缺失 |
| D3 | `parse_report:202`：尺寸表达超过一组就加待核标记，继而阻断报告通过 | 正常的本次/既往比较、多病灶或不同测量对象，可能成为不必要的阻断 | 先定位测量对象、方法及时间指向；记录差异及解释候选。仅在需要使用且比较对象仍不明时送局部复核，不将多组数字本身作为患者否决条件 |
| D4 | `resolve_vessel:145–148` 将阴阳或不相交角度变成阻断 CONFLICT；`run_quality:150–158` 对同 UID 不同内容全转 REVIEW | 同报告的不同血管段、历史比较、复核版本可能被笼统称为冲突；同 UID 有正式修订也不能仅凭内容不同判断质量差 | 保留每条原始表述、版本和比较对象。先标“差异待解释”，区分更新/不同对象/跨模态差异/同对象未解决分歧/已证实导出错误。不得自动选择较新或数值较大的结果 |
| D5 | `evaluate_report:218` 术后字样直接 REVIEW | 阶段适用性被混入记录质量；真实、清晰的术后报告被整体降级，其他质量标记也被早返回遮住 | 改成阶段线索，不作为 P1 质量否决。是否涉及本研究的原发灶/再次手术、是否可用于某个 episode，在 P2/P3 判断；不能只凭一个术后词确认全患者阶段 |
| D6 | 临床文书只检查标题、胰腺关键词、日期、来源 ID；没有“引用检查→原报告”核对 | 有一份任意历史影像就可能掩盖当前文书所引用的 CT/MRI 缺失；反过来，引用文字即使有价值，也不能被冒充为原报告 | 新增引用核对台账。直接引用的原文保留，同时记录是否找到原报告、候选匹配或多义匹配；未找到时写“本次交付资料中未找到”，不推断医院没有做检查 |
| D7 | `evaluate_report` 中检查名称不符直接 NOT_APPLICABLE、术后直接返回；`classify_patient` 用任一影像读取错误阻断 PASS | 一种标签遮住其他独立问题；局部文件问题上升为整个患者否决，难以分辨数据覆盖问题与临床信息缺失 | 先独立收集相关性、可读取性、来源和内容标记，再分流。读取错误必须保留运行未完整的警示，但不能抹掉该患者其他已核实可用的记录 |
| D8 | `run_quality:132–145` 按患者/日期/模态/文字哈希合并，重复来源通常保留第一条评估；只有“原先未核验、后来核验成功”才更新 | 静态可达风险：相同正文和日期、不同检查名称或协议字段，可能因输入顺序而保留不同的增强核实结果；本次未估计实际发生率 | 内容去重与来源核验、检查身份和协议字段分开；每条来源的核验结论保留，再进行确定性的汇总。增加调换输入顺序仍得到相同结果的测试 |

注意：REVIEW 本身不是永久排除，但旧流程实际从 2,004 名 PASS 开始 P2，因此这些门槛仍会影响谁进入后续探查，不能仅用“以后可人工复核”消除选择偏差。

### ABC 应记录什么，而不是要求什么全部齐备

| 维度 | 可检索的研究相关表述例子 | 缺失时的处理 |
|---|---|---|
| A | 目标胰腺病变、局部范围、具体血管及其关系；明确阴性、阳性或无法判断都可保留 | 某条血管未述、角度未量化，分别标记；不等于无接触，也不意味着整个患者不可用 |
| B | CA19-9 原始结果和测量背景、疑似或明确转移相关表述等 | 未查、未找到、原文未提及、明确无法判定分开；不把没有记录当作正常。胆道梗阻等背景可另设索引，不自动校正数值 |
| C | ECOG/体能、明确影响耐受性的状况及医生判断 | 未写 ECOG 不等于 C 不可用；保留具体临床条件，不从普通病历存在推断体能正常 |

上述为索引方向，并非本次已实现的新词表；也不从这张表生成切除性或手术建议。某条信息可能涉及多个维度，无须强制互斥归类。

## 4. 已通过执行确认的解析错误

以下均为纯合成文字，完整输入和实际输出见同名审计 JSON。它们验证代码行为，不代表这些错误在真实队列中的发生率。

| 反例 | 原文表达 | 代码实际行为 | 错误根源及修正方向 |
|---|---|---|---|
| W02 | 未见肠系膜上动脉受侵 | SMA = 接触/受侵 | `vessel_evidence:114` 只看名称后方，丢失前置否定；定位完整“否定—对象—谓词”范围 |
| W03 | SMA近段无接触，远段局部包绕 | 整体 SMA = 无接触 | `relationship:85` 阴性先返回，覆盖局部阳性；保留分段描述，不能压成全血管阴性 |
| W04 | SMA无接触，肝内结节可疑转移 | SMA = 明确无法确定 | `relationship:84` 的不确定词扫描整个尾段；限定到当前对象的谓词范围 |
| W05 | SMA无接触，脾动脉包绕270° | SMA 证据带上270° | `vessel_evidence:103–117` 只以五血管分割，未识别脾动脉这一新对象；扩大用于分界的解剖词表，分界词表不等于必须齐备词表 |
| W06 | 既往SMA接触180°，本次SMA无接触 | SMA = 缺失 | `vessel_evidence:126–128` 看到前缀“既往”便跳过，连本次信息一起丢弃；分别定位既往与本次跨度 |
| W08 | 胰头肿块，胆总管直径12mm | 肿瘤尺寸 = 12mm，报告 PASS | `parse_report:177–193` 只裁去部分器官/淋巴结，不排胆管；尺寸必须绑定测量对象，不能只取第一个“直径” |
| W09 | 肝脏病变：转移灶未见明显变化 | 肝脏病变 = 阴性 | `field_value:161` 将任何“未见”当阴性；区分“未见病变”和“未见变化” |

另复现了部分血管阻断 W01、正常比较尺寸阻断 W07、非模板转移描述漏检 W10、术后早返回遮住来源问题 W11、读取错误全患者否决 W12，共 12 个反例。

这些错误虽然不改原文，仍会造成错误筛选、错误标签或错误审阅优先级；不能因为未来 Agent 读原文而忽略。反过来，程序的误识别不能被计为患者原始资料质量差。

## 5. 冲突应该如何处理

**两条数值或判断不同，首先是差异；是否属于错误，需要知道它们是否声称描述同一对象、同一次检查/测量、同一记录版本。** 不能让全患者共享一个简单的 `has_conflict` 否决值。

| 场景 | 合适的标记 | P1 的处理 |
|---|---|---|
| CT 3cm，后来病理标本2cm | 不同测量来源/对象；不能直接比较 | 两份原文保留；不得拿病理尺寸替换术前影像 |
| 旧影像3cm，新影像2cm | 纵向变化候选 | 保留各自时间及治疗背景；不能仅凭数值判定疗效 |
| 同次 CT 初稿3cm，复核稿2cm | 版本变化候选 | 保留版本关系；可否确认修订及当时可见性后续复核 |
| 同日 CT 与 MRI 描述不同 | 跨模态分歧 | 保留真实临床不确定性，不判定导出错误 |
| 同一版本、同一病灶，前后两处给相反结论且无解释 | 同对象未解决分歧 | 标记具体字段待核；其他可用记录仍保留 |
| 导出值与可核验原文不符 | 已证实的提取/导出错误 | 修复衍生索引并留差异；原文不改，重新判断受影响筛选结果 |

当前程序的内部角度比较没有上述完整对象/时间/版本约束，因此只能充当差异筛查，不能证明临床或源数据错误。原通过人群审计也没有真正核实每一次差异的原因。

## 6. 引用的原报告没找到：需要新增的规则

这是可程序化的核对任务，但“未匹配到”不能冒充“已证明缺失”。现有 `verify_source` 只核对已经进入影像索引的报告，没有覆盖临床文书中的引用。

```text
对每条临床文书，定位对 CT/MRI 的实际引用
    # “拟查CT”“建议完善MRI”是未来检查计划，不是原报告缺失。
    若只是计划、假设或一般建议：标 PLANNED，不启动缺报告判定
    若明确在引用既有检查：保存引用原文位置、检查号、日期、模态等线索

为引用查找本患者的已交付原报告
    # 检查号优先；日期、模态和部位组合用于候选匹配，不能仅取最近检查。
    唯一、可靠对应 → FOUND_EXACT，并保存核对依据
    只有日期/模态等弱线索 → FOUND_CANDIDATE，保留待核
    多个候选且不能区分 → AMBIGUOUS，不擅自选一个
    当前交付范围未找到 → NOT_FOUND_IN_DELIVERED
    引用信息本身太少 → UNRESOLVED_REFERENCE，不伪装成确定未找到

保存引用记录与报告之间的索引关系
    # 此处不是把报告内容拼回病程，更不是让未来检查补齐过去的输入。
    找不到原报告时：保留病程中的二手表述及来源等级，并 mark 待核
```

代码级建议：新建独立的 `reference_linker.py`，输出 `note_id / quote_span / reference_role / exam_no / referenced_date / modality / candidate_report_ids / match_status / match_basis`。输出仅作检索与审计，真实患者级台账保存在忽略目录。P1 汇总未找到/多义引用；P2/P3 再核对是否正是某个决策所依赖的关键证据。

## 7. 冻结数据中的潜在影响范围

全量只读统计原 v0.2 的 31,236 个报告内容版本、2,707 人。患者列表示“至少一份报告命中该规则”，**不是修订后新增纳入人数**；不同行可重叠。术后及检查范围的早返回还会隐藏其他原因，所以原因计数不是全部内容缺口的普查。

| 信号 | 报告内容版本 | 涉及患者 | 其中当前待核患者 |
|---|---:|---:|---:|
| 五血管中至少一项因未述触发门槛 | 4,659 | 1,156 | 497 |
| 解析得到1–4条血管有表征，未达五条（不限定模态/报告状态） | 950 | 379 | 80 |
| 尺寸未表征，触发门槛 | 2,935 | 880 | 367 |
| 转移域未表征，触发门槛 | 4,651 | 1,157 | 497 |
| 术后字样直接待核 | 8,346 | 1,621 | 422 |
| 多组尺寸触发待核 | 174 | 72 | 30 |
| 原始记录簇未核对成功，触发待核 | 1,798 | 558 | 146 |
| 同报告 UID 不同内容规则 | 0 | 0 | 0 |

报告级 PASS 共 7,870 个，其中 7,856 个（99.8%）检测到三段模板标题；患者级 PASS 仍为 2,004、待核620、当前不满足83。这个分布提示明显的模板依赖，不能单独证明所有叙述报告都被误排。

原先“73名患者有两处尺寸差异”来自另一项通过人群对照审计；本表“72名患者命中多尺寸规则”是筛选器的不同口径，两者不能互换。

## 8. 建议的规则改写及实施顺序

```text
对 P0 患者逐份检查原始记录
    # P1 看研究相关性和记录能否使用；不要求拼出某个完整决策状态。
    标记能否读取、来源能否回溯；保留实际时间字段及来源
    标记是否有针对本患者PDAC的实质 ABC 信息
        明确阳性 / 明确阴性 / 明确无法判断，均属于实质表述
        未提及 / 未识别 / 尚计划取证 / 原始来源未找到，分别标记
    标记引用缺口、不同来源/时间/对象的差异，以及需要复核的具体记录

汇总到患者
    若至少有真实可读取、可回溯的研究相关记录：保留候选，并携带局部标记
    若相关性或记录可用性仍无法确认：进入针对性的患者复核
    仅在交付范围核实后仍无可用研究相关记录时，才考虑“当前资料不满足”
```

这里仍有一个需要通过样本校准的研究边界：**是否把“至少一份原始影像及实质血管关系”保留为 P1 最低门槛？** 若保留，它必须被明确写为研究对记录的最低要求，不能称为“信息应完整”的自然推论；若患者仅有“待查CT后评估”且始终找不到原报告，应作为明确的来源缺口组复核，不能因缺影像就断言没有发生相关评估。本次不擅自确定这条新门槛，也不把 ABC 任意一个弱关键词设为新的自动通过条件。

建议先做三项代码变更：

1. 将相关性、各项覆盖和来源标记从 `evaluate_report` 的单一 PASS/REVIEW 中拆开，取消同报告全齐的默认推论；研究期和阶段线索单列。
2. 修复前置否定、对象跨度、历史/当前跨度、尺寸归属与“未见变化”等已证实错误；保留逐条原文证据，不自动裁决真假。
3. 新增临床引用与原报告核对，再用固定开发样本检查“哪些缺失可接受、哪些需要来源复核”；同时覆盖旧 PASS、待核和当前不满足患者。之后才冻结新版规则、重跑 P0 全体并报告患者级迁移和具体原因。

新版完成前，旧 2,004 人只能称“v0.2 自动通过的开发患者池”，不能称已满足新定义的最终 P1。仅审计通过者也无法评估漏纳，因此下一轮必须包含旧待核和当前不满足组。
