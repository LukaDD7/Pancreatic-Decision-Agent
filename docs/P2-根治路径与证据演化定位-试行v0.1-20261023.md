# 根治路径与证据演化定位：最小试行 v0.1

2026-10-23。开发试行，仅回答“在哪里找候选checkpoint及其所在的候选episode”。采用两条核心原则，不先做全量事件标注或两两关系分类。既有Manual v0.1/v0.2及LOCAL-01 A/B/C保持原样。

## 两步定位

**第一步：找根治路径关联。** 从当时可见原文及必要上下文，找是否、何时、以何种条件推进、暂缓、补证据或不推进根治性切除的管理任务。分期/诊断取证、减黄、营养及并发症处理等，若上下文说明其服务于该任务，均可进入；不要求每条都重复写“为了手术”。不得仅凭患者有胰腺癌、诊断栏有“术前化疗”或后来接受手术，就把所有处理都视为相关。

关联明确时继续追踪；只有提示而缺连接依据时保留待核。范围内未找到关联，只说明本窗口未定位到，不排除患者，也不声称完整病程没有相关决策。

**第二步：沿决策相关证据演化，找重新判断。** 在上述管理任务内，将前后证据、已发生干预、反馈和管理安排顺序排开。出现相关检查结果、症状/患者条件变化、操作失败或其他已记载的新情况，并据此作出选择、维持、调整、暂缓、取证或不推进判断时，标一个候选checkpoint。连续上下文足以支持即可，不强求“重新评估”四个字。

行动相同也可以是新点；仅执行/复制已安排的连续计划不新增点；只有新证据而未见管理判断，先作为过程中的证据保存。不能由“附近多了检查”自动推定它触发判断。交付范围内首次可见的明确路径判断可作起始候选点，注明first-visible、此前状态未知，不强求补出范围外证据差异。

## 同时组织episode

为处理**同一个尚未解决的根治路径管理任务**而相互承接的证据、干预、反馈及判断，先组织为一个候选episode；链内可以有多个checkpoint。两次PTCD之间出现管道脱落和重新选择，可以形成同一任务链内的新点，不按操作次数切episode。

episode起点记交付中首次可见的相关任务/判断；终点有明确任务结束或转向时据实记录，否则记范围截断、开放结尾。一次住院、一次检查、同日或固定天数均不自动定义边界。不能证明任务承接时保留连接待核，不强串整条病程。

## 最小记录与本轮判断

每条候选链只保存：①管理任务；②根治路径关联原文；③按时点排列的证据演化及原文；④相应判断及原文；⑤候选checkpoint和episode边界；⑥待核信息。引用保留source ID/hash、逐字quote及范围；判断时间与文书时间分开，不用后续记录回写较早时点。

本轮试读LOCAL-01、LOCAL-02已交付原文；不读其算法图、relation proposal、独立标注结果或Clinical Reference。观察能否找出可解释的任务链和决策点，以及哪些链只能待核；不追求完整图、固定数量或所有不确定性消失。结果是开发候选定位，不是独立临床验证、医生Reference或最终episode规则。
